# 2026-08-17 PLM 宝塔下载项目目录清理与编码显示修复方案

## 修复目标

解决从宝塔下载项目后，本地与部署环境容易出现的两个问题：

1. 项目被重复解压出 `Yuewei/...` 残留目录，IDE 可能打开错误路径，导致改动不生效。
2. PowerShell 直接输出中文时显示乱码，容易误判为源码损坏。

本次修复只处理目录、部署配置和排查口径，不改业务逻辑。

已在后端容器环境变量中补充：

```text

```

作用是让数据库连接异常更快暴露，避免宝塔部署时后端启动长时间卡住。

### 4. 修正 Nginx 配置

已确认前端容器内的访问链路为：

```text
浏览器 -> plm-web nginx -> /api/ -> plm-server:8080 -> 后端 /api/v1
```

关键配置：

```text
plm-web/.env.production    VITE_API_BASE_URL=
plm-web/src/api/request.ts baseURL=/api/v1
plm-web/nginx.conf         /api/ proxy_pass http://plm-server:8080
```

同时保留：

```text
client_max_body_size 50m
```

用于支持附件上传。

### 5. 示例环境变量脱敏

`.env.baota.example` 只保留字段名和占位符，不记录真实数据库密码、钉钉密钥、公网地址等敏感信息。

真实部署值只放在服务器 `.env` 文件中，不提交到公共仓库。

## 宝塔部署操作

在服务器项目根目录执行：

```bash
cp .env.baota.example .env
```

编辑 `.env`，至少确认这些字段：

```text
WEB_PORT=8111
DB_URL=jdbc:postgresql://<db-host>:5432/<db-name>?currentSchema=plm
DB_USERNAME=<db-username>
DB_PASSWORD=<db-password>
SPRING_DATASOURCE_HIKARI_CONNECTIONTIMEOUT=10000
```

构建并启动：

```bash
docker compose -f docker-compose.baota.yml up -d --build
```

查看容器状态：

```bash
docker compose -f docker-compose.baota.yml ps
```

查看后端日志：

```bash
docker compose -f docker-compose.baota.yml logs -f server
```

查看前端日志：

```bash
docker compose -f docker-compose.baota.yml logs -f web
```

## 常见问题

### 访问前端正常，接口 502

优先检查：

```bash
docker compose -f docker-compose.baota.yml ps
docker compose -f docker-compose.baota.yml logs -f server
```

常见原因：

- 后端容器未启动成功。
- `.env` 中 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 配置错误。
- 数据库服务器或安全组未允许宝塔服务器访问。

### 浏览器刷新页面 404

检查 `plm-web/nginx.conf` 是否包含：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

当前项目已配置该 SPA fallback。

### 中文显示乱码

如果 IDE 正常、网页正常，但 PowerShell `Get-Content` 输出乱码，通常是终端显示编码问题，不代表源码损坏。

建议使用 VS Code / JetBrains 直接打开文件，或使用 UTF-8 方式读取：

```powershell
[System.IO.File]::ReadAllText((Resolve-Path 'plm-web\src\api\request.ts'), [System.Text.Encoding]::UTF8)
```

### 又出现 `Yuewei/` 子目录

不要直接在当前项目根目录解压宝塔下载包。先解压到临时目录：

```text
D:\work\_tmp\Yuewei-plm-baota-check
```

对比确认后，只迁移需要的文件。
