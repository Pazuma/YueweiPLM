# PLM 第一阶段恢复、存储迁移与回滚运行手册

适用范围：宝塔服务器上的 Docker Compose 部署，以及其私网 PostgreSQL。本文只定义恢复操作顺序；不要把命令直接用于未确认的生产主机。

## 0. 不可违反的边界

- `DB_URL` 必须是带 `currentSchema=plm` 的 PostgreSQL JDBC URL；`DB_SCHEMA=plm`。
- Flyway 的 `default-schema` 和 `schemas` 都是 `plm`，并且 `create-schemas=false`。数据库账户必须预先拥有既有 `plm` schema 的使用和建表权限。
- **禁止手工创建空业务表来“修复”启动。** 表结构只能来自已验证的初始化/迁移链。
- **禁止删除、清空或改名 `public` 中的既有表。** 即使它们不是正确的 PLM 历史，也只能先备份、核验和隔离；不得以删除 public 表作为恢复步骤。
- `.env` 只保留在服务器受限目录，权限设为 `chmod 600 .env`；仓库中的 `.env.baota.example` 仅是占位符。

## 1. 第一阶段恢复

1. 在维护窗口先记录状态：

   ```bash
   cd /www/wwwroot/YUEWEI/Yuewei-plm
   docker compose --env-file .env -f docker-compose.baota.yml ps
   docker compose --env-file .env -f docker-compose.baota.yml logs --tail=200 server
   ```

2. 备份私网 PostgreSQL（从可访问数据库的受控运维机执行；`PG_URL` 是 PostgreSQL 原生连接串，不是应用的 JDBC `DB_URL`；文件名使用实际日期）：

   ```bash
   export PG_URL='postgresql://plm_runtime:<password>@172.19.49.226:5432/plm_data_management'
   pg_dump --schema=plm --format=custom --no-owner --file=/srv/backup/plm-before-recovery.dump "$PG_URL"
   pg_dump --schema=public --format=custom --no-owner --file=/srv/backup/public-before-recovery.dump "$PG_URL"
   ```

3. 从示例重新建立 `.env`，只填私网地址和真实凭据。最小配置必须类似：

   ```dotenv
   DB_URL=jdbc:postgresql://172.19.49.226:5432/plm_data_management?currentSchema=plm
   DB_SCHEMA=plm
   DB_USERNAME=plm_runtime
   DB_PASSWORD=<仅服务器保存的强密码>
   ```

4. 在启动前做静态展开检查，再启动：

   ```bash
   docker compose --env-file .env -f docker-compose.baota.yml config -q
   docker compose --env-file .env -f docker-compose.baota.yml up -d
   docker compose --env-file .env -f docker-compose.baota.yml ps
   docker compose --env-file .env -f docker-compose.baota.yml logs --tail=200 server
   ```

`plm-server` 最多执行五次失败重启（`on-failure:5`）；修复配置或依赖后由运维人员显式执行 `up -d`，不依赖无限重启掩盖故障。

## 2. 1 TB 数据盘迁移边界

数据库服务器 `/dev/vdb2` 的快照、NTFS 清单、ext4 重建、`/data` 完整布局、Docker/containerd 根目录切换、PostgreSQL bind mount 和回滚步骤，统一以 `docs/运维/2026-08-17-数据库服务器1TB数据盘迁移与回滚.md` 为准。本手册不再提供另一个设备名或应用服务器存储覆盖流程，避免把两台主机的挂载和卷混用。

## 3. 回滚

1. 停止当前栈：

   ```bash
   cd /www/wwwroot/YUEWEI/Yuewei-plm
   docker compose --env-file .env -f docker-compose.baota.yml down
   ```

2. 还原上一个已验证的 Git 提交和 `.env` 备份；不要手改历史 Flyway 表或手工补空表。
3. 如数据库迁移已经改变数据，先在隔离库演练恢复，再由数据库负责人执行：

   ```bash
   pg_restore --clean --if-exists --no-owner --dbname="$PG_URL" /srv/backup/plm-before-recovery.dump
   ```

4. 用原 Compose 卷或已保留的数据副本启动，再运行下列验证。只有验证通过才结束维护窗口。

## 4. 验证命令

```bash
cd /www/wwwroot/YUEWEI/Yuewei-plm
docker compose --env-file .env -f docker-compose.baota.yml config -q
docker compose --env-file .env -f docker-compose.baota.yml ps
docker inspect --format '{{.State.Health.Status}}' plm-server
curl --fail --silent --show-error http://127.0.0.1:8110/api/v1/health/db
docker compose --env-file .env -f docker-compose.baota.yml logs --tail=200 server
psql "$PG_URL" -Atc "show search_path; select to_regclass('plm.plm_product'); select to_regclass('plm.flyway_schema_history');"
psql "$PG_URL" -Atc "select count(*) from pg_constraint where contype='f' and conrelid='plm.plm_product'::regclass and confrelid='plm.plm_product'::regclass;"
```

预期：健康接口成功、容器为 `healthy`、`plm.plm_product` 与 `plm.flyway_schema_history` 存在、`plm_product` 自关联外键计数大于 0。若 `public.flyway_schema_history` 存在，记录它并走审计/恢复流程；它不能替代 `plm.flyway_schema_history`。

### 非默认端口登录 403

Web 服务通过 `8111` 等非默认端口发布时，`plm-web/nginx.conf` 必须使用
`proxy_set_header Host $http_host;`，以保留浏览器 Origin 中的端口。使用 `$host`
会丢失端口，使 Spring CORS 将同源登录请求误判为跨域请求并返回 HTTP 403。

验证当前容器配置：

```bash
docker exec plm-web nginx -T 2>&1 | grep -F 'proxy_set_header Host $http_host;'
curl --request OPTIONS --include \
  --header 'Host: plm.example.invalid:8111' \
  --header 'Origin: http://plm.example.invalid:8111' \
  --header 'Access-Control-Request-Method: POST' \
  http://127.0.0.1:8111/api/v1/auth/login
```

预期预检请求返回 HTTP 200。直接修改运行容器只会改变该容器的可写层；重新创建
旧镜像会丢失热修复。仓库修复合入后必须重新构建 Web 镜像，再执行重新创建。

## 5. 开机启动

模板位于 `deploy/systemd/yuewei-plm-compose.service`。检查其中 `WorkingDirectory` 与实际部署目录一致后安装：

```bash
sudo install -m 0644 deploy/systemd/yuewei-plm-compose.service /etc/systemd/system/yuewei-plm-compose.service
sudo systemctl daemon-reload
sudo systemctl enable --now yuewei-plm-compose.service
sudo systemctl status yuewei-plm-compose.service
```

该单元是 `Type=oneshot`，只在开机时显式拉起 Compose，不以 systemd 无限重启替代应用故障处理。
