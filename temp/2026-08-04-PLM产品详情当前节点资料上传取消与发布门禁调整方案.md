## 3. 任务理解

截图红框圈中的区块是产品详情弹窗“当前节点”页里的“当前节点资料上传”。现在期望取消这个区块，不再把每个当前节点的资料上传放在节点卡片下面。

资料上传口径改为：

```text
产品线资料上传 = 新型号资料上传
```

也就是产品线和新型号线都走统一入口：

- 工作台上传；
- 产品详情的资料区上传；
- 如后续确认，也可以在基础资料/文件中心增加上传入口。

同时取消“产品发布门禁”的硬阻断。流程走完后即可发布，缺少 BOM、工艺路线、图纸、SOP/SIP、测试资料或部分节点资料时，不再阻断 Product 发布，只在发布前弹窗提示风险，让用户确认后继续发布。

本方案不新增 SKU、BOM、文件版本等根对象，所有资料仍作为 `Product` 附件或时间轴附件记录。

## 4. 当前系统事实

### 4.1 当前节点资料上传

`ProjectCenterView.vue` 当前在至少两处调用 `TimelineAttachmentPanel`：

- “当前节点”页：`scope="node"`，标题为“当前节点资料上传”。
- “项目流程”页：`scope="node"`，标题为“当前步骤资料上传”。
- “资料区”页：不传 `nodeKey`，默认 `scope="project"`，上传项目/产品级资料。

`TimelineAttachmentPanel.vue` 会根据 `scope` 选择上传接口：

```text
scope=node    -> POST /api/v1/projects/{projectId}/timeline/{nodeKey}/attachments
scope=project -> POST /api/v1/projects/{projectId}/attachments
```

因此系统已经有“资料区上传”的基础能力，红框区块可以取消，不影响资料上传，只是入口收敛。

### 4.2 当前节点推进资料门禁

后端 `TimelineActionServiceImpl.confirm` 当前存在两类阻断：

1. `requireCurrentNodeAttachment`
   当前节点如果配置了 `requiredFileCategory`，确认节点前必须上传对应分类附件。

2. `requireStageDocuments`
   跨阶段时，会检查本阶段要求的节点资料是否完整。

这意味着即使前端移除了红框上传区，后端仍可能因为节点资料缺失而阻断节点确认。因此后续落地必须同步调整后端节点资料门禁，否则页面入口取消后用户会被隐藏规则卡住。

### 4.3 当前产品发布门禁

后端发布接口：

```text
GET  /api/v1/projects/{projectId}/release-gate
POST /api/v1/projects/{projectId}/publish
```

`ProductServiceImpl.publish` 当前会调用 `ProductReleaseGateValidatorImpl.check`，门禁失败则抛 `RELEASE_GATE_NOT_PASSED`，阻断发布。

当前门禁检查包括：

- 产品状态必须是 `reviewing`；
- 产品不能已归档或废弃；
- 时间轴必须处于允许发布的最终节点；
- 当前时间轴节点必须已确认；
- 至少一个已冻结或已发布 BOM；
- 至少一条已锁定或已冻结工艺路线；
- 至少一个图纸附件；
- 至少一个 SOP 或 SIP 附件；
- 至少一个测试资料附件。

本次新口径要求取消其中“资料完整性 / BOM / 工艺路线”的硬阻断，保留为发布前风险提示。

## 5. 推荐业务口径

### 5.1 页面口径

产品详情弹窗中取消红框区块：

```text
当前节点页不再展示“当前节点资料上传”
```

资料上传保留在：

```text
工作台上传
产品详情 -> 资料区
```

产品线和新型号线使用同一个资料区能力，不再因为产品线/新型号线不同而出现不同上传入口。

### 5.2 节点推进口径

推荐调整为：

```text
节点资料缺失不再阻断节点确认或阶段推进。
```

后端仍可计算当前节点 `documentCount` 和缺失分类，用于页面提示和报表统计，但不能抛异常阻断流程。

实际效果：

- 当前节点可以确认；
- 可以推进下一节点；
- 缺少资料只显示提示；
- 操作日志继续记录确认、推进、退回动作；
- 资料完整率仍可用于项目看板和后续补录。

### 5.3 产品发布口径

推荐调整为：

```text
流程走到发布状态后即可发布；资料缺失只作为风险提示，不作为硬门禁。
```

后端保留基础状态校验：

- 产品存在且未删除；
- 产品不是 `archived`；
- 产品不是 `abandoned`；
- 当前状态允许进入 `released`，推荐仍要求 `reviewing`，即流程已走到最后发布阶段；
- 当前用户具备发布权限。

后端取消硬阻断：

- 不要求已冻结 BOM；
- 不要求已锁定工艺路线；
- 不要求图纸附件；
- 不要求 SOP/SIP 附件；
- 不要求测试资料附件；
- 不要求每个节点资料齐套。

前端在发布前调用风险检查，若存在缺失项，弹窗提示：

```text
当前产品存在资料缺口，发布后仍会进入已发布状态。

缺失项：
- BOM 未冻结或未发布
- 工艺路线未锁定
- 图纸资料缺失
- SOP/SIP 缺失
- 测试资料缺失

确认继续发布？
```

用户确认后，再调用发布接口。发布接口记录原因和风险确认结果。

## 6. 后端方案

### 6.1 发布门禁改为发布风险检查

保留 `GET /api/v1/projects/{projectId}/release-gate`，但语义建议从“门禁是否通过”改成“发布风险预检”。为了兼容前端和测试，接口名可以暂时不变，文案从“门禁”改为“风险提示”。

返回结构可沿用 `ProductReleaseGateCheckVO`：

```text
passed        表示没有风险项
missingItems  表示发布风险项
```

关键变化：

```text
missingItems 不再决定能否发布，只决定是否弹窗提示。
```

### 6.2 发布接口增加风险确认字段

建议在 `ProductLifecycleActionDTO` 增加字段：

```text
riskConfirmed: Boolean
```

推荐发布逻辑：

```text
1. 查询产品。
2. 校验产品未删除、未归档、未废弃。
3. 校验状态流转允许进入 released。
4. 执行发布风险检查。
5. 如果存在风险项且 riskConfirmed != true，返回确认必需错误和风险清单。
6. 如果 riskConfirmed=true，继续发布。
7. 更新 status=released、released_at、released_by。
8. 同步 Order 生命周期完成状态。
9. 写操作日志，detailJson 记录 riskConfirmed 和 missingItems。
```

这样既取消了硬门禁，又避免第三方或前端误调用导致用户没看见风险就发布。

### 6.3 节点资料门禁改为提醒

`TimelineActionServiceImpl` 中建议调整：

- `requireCurrentNodeAttachment` 改为 `collectCurrentNodeAttachmentWarnings`；
- `requireStageDocuments` 改为 `collectStageDocumentWarnings`；
- `confirm` 不因资料缺失抛异常；
- 操作日志 detailJson 中追加 `documentWarnings`；
- `TimelineActionResultVO` 可后续扩展 `warnings`，第一期也可以只记录日志，前端通过 timeline 的 `requiredAttachment + documentCount` 提示。

需要保留的业务门禁：

- `requireBusinessGate` 中 BOM 路线敲定、投产工序确认、投产颜色确认是否继续阻断，需业务确认。
- 本次用户主要强调“缺少资料或哪个步骤也可以”，推荐第一期只取消资料类门禁；BOM/工艺/颜色这类业务确认如果也要取消，需要单独确认，因为会影响投产决策数据生成。

### 6.4 附件接口保留并复用

不建议删除后端时间轴附件接口，因为工作台上传和历史文件仍可能需要节点归属：

```text
POST /api/v1/projects/{projectId}/timeline/{nodeKey}/attachments
GET  /api/v1/projects/{projectId}/timeline/{nodeKey}/attachments
```

资料区继续使用产品/项目级附件：

```text
POST /api/v1/projects/{projectId}/attachments
GET  /api/v1/file-center/attachments?projectId={projectId}
```

如业务明确“资料区”指基础资料下的文件中心，而不是产品详情资料区，则文件中心需要新增上传入口，并要求用户选择产品/项目和可选节点。

## 7. 前端方案

### 7.1 移除红框区块

在 `ProjectCenterView.vue` 中移除“当前节点”页的 `TimelineAttachmentPanel`：

```text
当前节点页只展示节点状态、确认/推进/退回、最近动作、风险提示和发布操作。
```

同时建议移除“项目流程”页中同类的“当前步骤资料上传”面板，避免红框区块换个页签继续出现。资料上传统一放到“资料区”。

### 7.2 资料区作为统一上传入口

`ProjectCenterView.vue` 已有：

```text
activeDetailSection === 'materials'
TimelineAttachmentPanel scope=project
```

后续落地建议：

- 将页签文案保持为“资料区”；
- 产品线、新型号线都展示同一个资料区；
- 上传分类沿用 `FILE_CATEGORY_OPTIONS`；
- 不强制选择当前节点；
- 如需要追溯节点，资料区可增加“归属节点”下拉，但该字段可选；
- 上传成功后刷新资料区列表、文件中心列表和当前节点资料数量。

### 7.3 工作台上传保持

工作台中的上传入口不取消。它适合项目推进过程中快速上传资料。

建议统一规则：

```text
工作台上传：可带当前节点归属。
资料区上传：默认产品/项目级资料，可选节点归属。
文件中心：第一期继续查询/预览/下载/删除；如确认需要上传，再新增上传弹窗。
```

### 7.4 发布弹窗调整

`ProjectReleaseGatePanel.vue` 当前文案是“项目发布门禁”，且 `gate.passed=false` 时阻止发布。后续改为：

```text
项目发布风险
```

交互建议：

1. 打开产品详情时加载风险预检。
2. 点击“发布 Product”。
3. 如果没有风险项，显示普通确认弹窗。
4. 如果有风险项，显示风险确认弹窗，列出缺失项。
5. 用户确认后，调用 `publishProject(projectId, { reason, riskConfirmed: true })`。
6. 发布成功后刷新详情、列表和时间轴状态。

`ProjectCenterView.vue` 顶部“发布 Product”按钮也要使用同一套风险确认逻辑，避免一个入口能发布、另一个入口仍按旧门禁报错。

完成后预计达到以下效果：

1. 产品详情“当前节点”页不再显示红框中的“当前节点资料上传”大区块，页面更聚焦节点状态、确认、推进和发布。
2. 产品线和新型号线的资料上传口径统一，均可在工作台或产品详情“资料区”上传。
3. 用户不再为了推进节点或发布 Product 被隐藏的资料必传规则阻断。
4. 缺少 BOM、工艺路线、图纸、SOP/SIP、测试资料时，系统只在发布前弹窗提示风险。
5. 用户确认风险后，Product 可以正常进入 `released`。
6. 资料缺口仍可在风险预检、资料完整率、文件中心、报表中继续追踪，不丢失管理视角。
7. 操作日志能追溯是谁在存在资料缺口的情况下确认发布。
8. 现有附件表、MinIO/S3 存储、预览、下载、删除能力继续复用，不新增文件根对象。

## 10. 验收标准

### 10.1 页面验收

1. 打开产品详情“当前节点”页，不再出现“当前节点资料上传”区块。
2. 产品详情“资料区”仍可上传、查看、预览、下载和删除资料。
3. 新产品线和新型号线的资料区表现一致。
4. 工作台上传入口仍可用。
5. 发布区域文案不再使用“门禁未通过，请先补齐”作为阻断提示。
6. 缺少资料时点击发布，会弹窗列出风险项并要求确认。

### 10.2 后端验收

1. 当前节点缺少 `requiredFileCategory` 对应附件时，仍可确认当前节点。
2. 跨阶段时缺少阶段资料，不再抛异常阻断。
3. Product 状态为 `reviewing` 且未归档/未废弃时，即使缺少 BOM、工艺、图纸、SOP/SIP 或测试资料，也可在风险确认后发布。
4. Product 非法状态仍不能发布，例如 `archived`、`abandoned` 或不允许流转的状态。
5. 发布成功后写入 `released_at`、`released_by`、`updated_at`、`updated_by`。
6. 发布操作日志包含风险确认标识和缺失项清单。

### 10.3 回归验收

1. 已发布 Product 仍不可直接编辑。
2. 已归档 Product 仍不可重复发布。
3. 附件上传、预览、下载、删除能力不受影响。
4. 文件中心仍能按项目、节点、分类查询附件。
5. BOM 管理、工艺路线管理的自身冻结/锁定规则不被本次发布口径误伤。

## 11. 风险点

1. 取消发布门禁后，`released` 不再等同资料齐套，只代表流程确认发布，需要在报表和详情中区分“已发布”和“资料完整”。
2. 如果后续 ERP/MES 只允许读取资料齐套的 Product，需要增加外发集成门禁，不能复用本次宽松发布口径。
3. 如果完全取消节点资料后端阻断，部分历史测试用例会失败，需要同步更新测试预期。
4. 如果文件中心也要支持上传，需要新增选择产品/项目的交互，否则文件无法正确归属。
5. `ProductReleaseGateValidatorImpl` 名称仍带 Gate，短期兼容可保留；长期建议重命名为 `ProductReleaseRiskChecker`，但这属于后续整理，不建议本次大改。

## 12. 待确认事项

1. 本次是否只取消产品详情“当前节点”页红框上传区块，还是同时取消“项目流程”页中的当前步骤上传区块；推荐同时取消，统一放到资料区。
2. “资料区上传”是否指产品详情页内的“资料区”，还是基础资料菜单下的“文件中心”；推荐第一期先使用产品详情“资料区”，文件中心保持查询台账。
3. 产品发布是否仍要求流程进入最终发布阶段 `reviewing`；推荐保留这个状态门槛，因为用户表述是“流程走完就可以发布”。
4. `requireBusinessGate` 中 BOM 路线敲定、投产工序确认、投产颜色确认是否也要取消硬阻断；推荐本次先不取消，避免破坏投产决策数据。
5. 风险确认是否必须后端强制校验 `riskConfirmed=true`；推荐强制校验，保证不是前端绕过弹窗直接发布。
