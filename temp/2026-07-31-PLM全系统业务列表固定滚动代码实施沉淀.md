# 2026-07-31 PLM 全系统业务列表固定滚动代码实施沉淀

## 实施目标

按《2026-07-31-PLM全系统业务列表固定滚动统一方案》完成前端业务主列表统一改造：主列表表头固定、表体在列表区域内纵向滚动、横向滚动条始终位于列表区域底部，不再因记录数量增加而拉长整页。

本次只调整 Vue 3 前端列表承载方式，不修改后端接口、数据库、Flyway、核心对象、状态机、权限或审批逻辑。

## 公共能力

| 文件 | 作用 |
| --- | --- |
| `plm-web/src/composables/useFixedTableHeight.ts` | 根据列表容器距视口底部的实际空间计算表格高度；默认最小 320px、最大 760px；监听窗口尺寸变化并提供渲染后刷新方法。 |
| `plm-web/src/components/FixedTableViewport/index.vue` | 固定主列表视口组件。通过插槽向 `el-table` 提供受控高度，使 Element Plus 接管固定表头、表体纵向滚动和底部横向滚动条。紧凑模式最大高度为 560px。 |
| `plm-web/src/composables/__tests__/useFixedTableHeight.spec.ts` | 验证可用高度、最小高度和最大高度三种边界。 |

主列表不再通过外层无边界 `overflow: auto` 处理滚动，而是将计算高度传给 `el-table`。横向滚动轨道、表体和固定列因此保持在同一组件边界。

## 保持原样的表格

- 详情抽屉和详情弹窗内的成本、供应商、质量、工序、SKU/BOM 明细表。
- BOM 编辑、候选 BOM、工艺路线编辑、附件面板等嵌入式编辑明细。
- 导入预览表。该类表格已有局部高度限制，不再套用页面主列表视口，避免双重滚动条和编辑空间被压缩。

## 目标效果

1. 数据超过一屏时，业务主列表表头保持可见，只有数据行在列表区域内纵向滚动。
2. 宽表横向滚动条持续位于对应列表底部，用户不必滚到整页底部才可左右查看字段。
3. 项目中心进行中列表的横向滚动范围限制在原红框对应的表格区域，右侧固定操作列持续可用。
4. 切换筛选、页签或窗口尺寸后，列表根据当前可视空间重新计算高度。
5. 原有查询、筛选、分页、详情、固定列、状态显示和权限控制不变。

## 验证结果

已通过以下验证：

- `npm run test:run -- src/composables/__tests__/useFixedTableHeight.spec.ts`：3 个测试通过，覆盖正常可用高度、最小高度兜底和最大高度限制。
- `npm run type-check`：通过。
- `git diff --check`：通过。

尚需在运行中的 Vite 页面手工确认：1920x1080、1440x900、1366x768、1024px 宽和浏览器 125% 缩放；并检查项目中心“进行中”切换全部/新产品线/新型号线及选择时间轴节点后的列表高度、横向滚动条和固定操作列。
