# 2026-07-31 PLM 项目中心进行中项目列表固定滚动方案（专项）

> 说明：本文件保留截图红框对应的项目中心专项设计。根据后续确认，统一规范已扩展至全系统业务主列表，见《2026-07-31-PLM全系统业务列表固定滚动统一方案》；后续实施应先建设公共列表能力，再由本专项作为项目中心接入依据。

## 1. 任务理解

项目管理页面的“进行中”视图中，红框标识的项目表格需要成为独立、固定高度的列表工作区。表头、项目记录和横向滚动条均限定在该工作区内；用户浏览更多项目时只滚动表格内容，不能让表格无限拉长页面，横向滚动条也必须始终出现在红框底部。

本次仅沉淀前端展示方案，不修改业务代码、后端接口、数据库、状态机或权限。

## 2. 所属业务链路

- 模块：项目管理 / 项目中心 / 进行中项目。
- 核心对象：`Product`。新产品线与新型号线均通过 Product 的类型、版本和流程节点展示。
- 使用场景：项目经理、工程、采购、品质、生产和管理层查看进行中项目当前节点、下一关口和完成度，并进入项目详情。
- 业务边界：仅调整列表承载与滚动体验，不改变项目筛选、节点查询、详情入口、字段含义或数据排序。

## 3. 现状与问题

当前“进行中项目”列表位于 `plm-web/src/views/project/ProjectCenterView.vue` 的 `project-list-shell` 中，`el-table` 未配置固定高度，外层也只设置了顶部间距。

因此：

1. 项目记录增多时，表格高度随数据持续增加，页面整体被拉长。
2. 表格的横向滚动条位于所有记录之后；需要先向下滚动很久才能看到，无法持续操作右侧字段或“详情”。
3. 页面纵向滚动、浏览器横向可视范围和表格横向滚动的责任边界不清晰，宽表在小屏或缩窄窗口下体验不稳定。

## 4. 目标效果

以截图红框为唯一滚动边界，达到以下效果：

1. 红框范围内的表格高度固定，随浏览器可视高度自适应，避免遮挡页面底部并保留最小可用高度。
2. 表头固定在该区域顶部；项目行在表头下方独立纵向滚动。
3. 横向滚动条始终固定在红框底部，用户无论浏览到第几条记录都可以立即左右移动查看全部列。
4. 横向滚动的宽度和轨道仅覆盖项目表格区域，不影响页面筛选栏、时间轴、项目模块头和浏览器页面本身。
5. 右侧“操作”列继续固定，左侧列按现有配置展示；点击“详情”的行为保持不变。
6. 无数据、加载中、切换“全部 / 新产品线 / 新型号线”时，列表区域仍保持稳定，不发生明显跳动。

## 5. 方案设计

### 5.1 独立列表视口

在进行中项目的 `project-list-shell` 上增加专用样式类，例如 `project-list-shell--in-progress`，仅作为红框对应的视觉边界。

- 该容器保持表格边框范围，不把 `overflow: auto` 下放到页面或模块总容器。
- 容器高度使用桌面端视口计算值：以页面可视高度减去顶部导航、项目筛选栏、模块标题、流程筛选栏、可选时间轴和提示条的已占高度为基准。
- 同时设置合理的 `min-height` 与 `max-height`，保证窗口较小时仍可阅读至少数行项目，窗口较大时不无限扩张。
- 当选择“全部”流程类型、未展示时间轴时，采用较大的可用高度；当选择新产品线或新型号线并展示时间轴时，扣除时间轴区域后得到较小但稳定的列表高度。

建议优先将计算后的高度直接传给 `el-table` 的 `height` 或 `max-height` 属性，而不是将表格套进普通 `overflow` 容器。Element Plus 在固定高度表格中会拆分表头、表体和滚动区域，可让纵向表体与底部横向滚动条保持在同一组件边界。

### 5.2 表头、表体与横向滚动条

- `el-table` 配置固定高度后，表头由组件固定在列表顶部。
- 表体承担纵向滚动；数据超过可视行数时只滚动行内容。
- Element Plus 表格的横向滚动容器位于表体底部，轨道宽度跟随表格实际可视宽度，因此天然限定在红框范围。
- 保持现有列 `min-width`、右侧固定“操作”列和 `border/stripe`，避免改变字段密度和详情入口。
- 需要通过局部 `:deep()` 样式确认 `.el-scrollbar__bar.is-horizontal` 不被外层 `overflow: hidden` 裁切，并给底部预留滚动条所需空间。

### 5.3 高度刷新

固定高度依赖可视区域，需在以下情况刷新表格布局：

- 页面首次加载和异步项目数据加载完成后。
- 用户切换“全部 / 新产品线 / 新型号线”筛选时。
- 用户选择或取消选择时间轴节点，导致上方内容高度变化时。
- 浏览器窗口尺寸变化时。
- 侧边栏展开/收起或页面主内容宽度变化时。

实现时通过 Vue 的 `nextTick` 后调用表格实例的 `doLayout()`；如采用动态高度计算，可在同一时机更新高度状态。窗口监听必须在组件卸载时移除，避免重复监听。

### 5.4 响应式规则

- 桌面端：使用固定的独立列表视口，确保横向滚动条持续可见。
- 窄屏：仍以列表区域作为横向滚动范围，不让页面出现由表格触发的横向滚动；高度可改用较小的最小值。
- 移动端：保持表格横向滚动和固定操作列的可用性；若固定列造成可视面积过窄，仅在后续单独评审后调整列冻结策略，本次不删除字段或改为卡片视图。

- 不改变详情、成本、流程推进等现有权限判断；本次只是让可见列表更易浏览。

## 8. 验收标准

1. 在进行中项目数据超过固定可视行数时，页面不被项目行无限撑长。
2. 向下滚动项目行时，列标题保持可见。
3. 在任意表体纵向位置，红框底部横向滚动条均可见并可拖动。
4. 横向滚动条左右端点与红框内表格宽度一致，不延伸到页面筛选栏或模块外部。
5. 左右滚动后，右侧固定“操作 / 详情”列仍可使用。
6. 在“全部”“新产品线”“新型号线”之间切换、选择时间轴节点、调整浏览器窗口大小后，表格列宽和滚动条位置正常，无横向页面溢出或滚动条丢失。
7. 无数据和加载状态不出现空白大面积跳动或双重滚动条。

## 9. 验证方式

- 前端静态检查：`npm run type-check`。
- 手工验证桌面宽度：1920x1080、1440x900、1366x768。
- 手工验证窄屏：1024px 宽度，以及浏览器缩放 125%。
- 使用至少 10 条进行中项目数据验证纵向滚动；使用完整列宽验证横向滚动和右侧固定操作列。
- 检查浏览器页面本身不出现由项目表格引起的横向滚动条。

## 10. 风险与待确认项

- 上方时间轴是否始终完整显示，会直接影响可分配给列表的视口高度；方案默认优先保证红框列表在同一视口内稳定可用，并使用最小高度兜底。
- 若页面框架存在固定顶部导航或不同高度的浏览器工具栏，纯 CSS `calc()` 可能需要与运行时测量配合；实施时应以实际页面容器为准，不硬编码单一屏幕高度。
- Element Plus 的固定列与横向滚动依赖组件内部结构，需在实际浏览器中验证滚动轨道未被外层面板的 `overflow: hidden` 裁切。
- 当前需求仅指定进行中项目红框列表；全部项目、归档项目、SKU 列表和已放弃项目保持现状，避免一次性改变所有表格的阅读节奏。
