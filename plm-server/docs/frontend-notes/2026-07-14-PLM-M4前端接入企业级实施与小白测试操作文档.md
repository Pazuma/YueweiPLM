## 3. 业务边界

### 3.1 核心业务主线

M4 前端接入必须围绕以下主线设计：

```text
Product 项目
  → 时间轴当前节点
  → BOM / Process / Attachment 成果
  → 文件中心归档查询
  → 后续 M5 发布门禁
```

时间轴是主线，BOM、工艺路线和文件不是三个互不相关的页面。

例如“样品与工艺”节点应能够看到：

```text
BOM
工艺路线
SOP
SIP
测试报告
图纸
```

### 3.2 核心对象

本次只复用现有核心对象：

| 能力 | 归属对象 |
| --- | --- |
| 项目、产品线、型号和版本 | Product |
| BOM 头和 BOM 明细 | Product 下的业务资料 |
| 工艺路线和工序 | Process |
| 图纸、SOP、SIP、测试报告 | Product 时间轴节点下的 Attachment |

不得新增以下前端根对象或自定义后端概念：

```text
独立 BOM 根对象
独立 Routing 根对象
独立 FileVersion 根对象
独立 QualityDocument 根对象
```

前端类型名称可以表达 DTO 或 ViewModel，但不能改变后端领域归属。

### 3.3 本次不做

- 不新增后端业务接口。
- 不新增数据库字段或 Flyway 迁移。
- 不接 ERP、MES、WMS、CRM。
- 不实现在线 CAD 预览。
- 不实现复杂文件版本审批。
- 不使用前端 mock 结果掩盖真实接口失败。
- 不为了接 M4 重写整个项目中心或整个前端架构。

### 4.2 仍是 mock 的 M4 部分

#### BOM

```text

```

当前问题：

- `getProjectBoms`、创建、修改、明细维护和冻结均使用 `mockResolve`。
- 前端使用 `bomId`，后端返回 `productBomId`。
- 前端 `getBomDetail` 预期 `{ bom, items }`，后端直接返回包含 `items` 的 BOM 对象。
- 前端创建参数只有 `bomType` 和 `items`，后端要求 `bomName`、`bomType`、`versionNo`、`remark`。
- 后端 BOM 明细通过独立接口逐条维护，不能把明细直接塞进创建 BOM 请求。

#### 工艺路线

```text
plm-web/src/api/modules/process.ts
```

当前问题：

- 项目工艺路线查询、详情、创建、更新和冻结均使用 `mockResolve`。
- 前端使用 `routeName`，后端字段是 `processName`。
- 前端详情预期 `{ route, operations }`，后端直接返回包含 `operations` 的路线对象。
- 前端使用 `operationId`，后端工序主键仍是 `processId`。
- 后端状态是 `draft` 和 `locked`，不能只依赖前端 `isFrozen` 布尔值。

#### 附件和文件中心

```text
plm-web/src/api/modules/attachment.ts
plm-web/src/components/FileUpload/index.vue
plm-web/src/views/file/FileCenterView.vue
```

当前问题：

- 上传、节点附件查询、文件中心、下载和删除均为模拟实现。
- `FileUpload` 只把文件名传给 mock API，没有上传真实文件内容。
- 文件中心的“上传”和“删除”只修改浏览器内存数组。
- 前端使用 `projectId`，附件后端返回 `ownerObjectId`。
- 前端使用 `mimeType`、`uploadedBy`、`uploadedAt`，后端返回 `contentType`、`createdBy`、`createdAt`。
- 文件中心前端预期分组数组，后端返回分页 `PageVO<AttachmentVO>`。

## 5. 推荐接入方案

采用“项目时间轴主线接入，文件中心辅助归档”的方案。

### 5.1 第一入口：项目详情

在项目详情中提供三个真实业务区：

1. BOM 管理。
2. 工艺路线。
3. 当前时间轴节点附件。

项目详情只负责选择项目、提供 `projectId` 和当前 `nodeKey`，具体 M4 行为由私有组件负责。

### 5.2 第二入口：文件中心

文件中心接入真实：

```text
GET /api/v1/file-center/attachments
GET /api/v1/attachments/{attachmentId}
GET /api/v1/attachments/{attachmentId}/download
DELETE /api/v1/attachments/{attachmentId}
```

文件中心用于跨项目归档查询和下载，不承担 BOM、工艺路线编辑。

### 5.3 暂缓独立 BOM/工艺中心全量接入

当前后端只提供项目级 BOM 和项目级工艺路线列表，没有全局 BOM/工艺聚合接口。

如果独立中心页直接遍历所有项目再逐个查询，会产生 N+1 请求：

```text
查询 1 次项目列表
再按每个项目查询 1 次 BOM
再按每个项目查询 1 次工艺路线
```

这不符合企业级性能和可维护性要求。

第一阶段建议：

- 项目详情中完成全部 M4 增删改查和冻结闭环。
- 文件中心完成真实归档查询。
- BOM 和工艺中心保留只读入口或跳转项目详情。
- 后续如需要全局中心，再设计后端分页聚合接口。

## 6. 企业级前端架构

### 6.1 分层结构

```text
页面 View
  ↓ 只负责页面编排
项目私有组件
  ↓ 负责用户交互和局部状态
Composable
  ↓ 负责请求编排、刷新、错误状态
API 模块
  ↓ 负责 HTTP 和后端 DTO
Mapper
  ↓ 负责 Backend DTO → ViewModel
Axios request
  ↓ Token、X-Request-Id、错误传播
M4 后端
```

### 6.3 为什么这样拆分

- API 模块不包含页面文案和 Element Plus 逻辑。
- Mapper 隔离后端字段和前端展示字段，后端字段变化不会扩散到所有页面。
- Composable 统一请求、刷新和异常状态，避免每个组件重复实现。
- 项目私有组件不放到全局 `components`，因为它们只服务项目模块。
- 大表单使用 Dialog 组件，主页面保持可扫描。
- 不把项目局部状态放进 Pinia，防止不必要的全局状态污染。

```ts
  projectId: number,

export async function getFileCenterAttachments(params: FileCenterQuery) {
  const response = await request.get('/file-center/attachments', { params })
  return unwrapPage<AttachmentDTO>(response)
}

export async function downloadAttachment(attachmentId: number) {
  const response = await request.get<Blob>(`/attachments/${attachmentId}/download`, {
    responseType: 'blob'
  })
  return response.data
}
```

### 11.4 FormData 请求头

当前 Axios 实例默认设置：

```text
Content-Type: application/json
```

上传 FormData 时必须让浏览器自动生成 multipart boundary。

建议在请求拦截器中识别 FormData，并移除固定 JSON Content-Type。不要手工拼 multipart boundary。

### 11.5 下载工具

```ts
export function saveBlob(blob: Blob, fileName: string) {
  const url = URL.createObjectURL(blob)
  const anchor = document.createElement('a')
  anchor.href = url
  anchor.download = fileName
  document.body.appendChild(anchor)
  anchor.click()
  anchor.remove()
  URL.revokeObjectURL(url)
}
```

必须调用 `URL.revokeObjectURL`，否则反复下载会积累浏览器内存。

## 14. 状态、权限和错误处理

### 14.1 状态驱动

| 对象 | 可编辑状态 | 只读状态 |
| --- | --- | --- |
| BOM | `draft` | `frozen` |
| 工艺路线 | `draft` | `locked` |
| 附件 | 未删除 | 软删除后不可见 |

前端禁用按钮是用户体验，后端 `40301` 才是最终安全边界。

### 14.2 权限驱动

企业级前端需要同时判断：

```text
用户是否有操作权限
对象状态是否允许操作
页面是否处于只读上下文
```

无权限或状态不允许时：

- 按钮保持可见但禁用。
- Tooltip 明确说明原因。
- 不只依赖 `v-if` 隐藏按钮。
- 即使前端禁用，后端错误仍需正确展示。

### 14.3 错误语义

| 错误码 | 前端处理 |
| --- | --- |
| `40001` | 保留表单，定位校验问题 |
| `40301` | 提示已冻结/已锁定，刷新详情进入只读 |
| `40401` | 提示项目或业务资料不存在，刷新列表 |
| `40402` | 提示附件不存在，刷新附件列表 |
| `40901` | 提示行号或工序顺序冲突 |
| `50002` | 提示文件超过大小限制 |
| `50003` | 提示元数据存在但物理文件丢失 |
| `50004` | 提示文件类型不支持 |

不得将接口错误转换为空数组。只有后端成功返回空列表时，前端才展示空状态。

### 14.4 请求竞态

用户快速切换项目时，旧项目请求可能晚于新项目返回。

企业级实现至少采用一种方式：

- Axios AbortController 取消旧请求。
- 使用递增 requestKey，只接收最后一次请求结果。

否则可能把项目 A 的 BOM 显示在项目 B 中。

### 14.5 后端为准

新增、修改、冻结、上传和删除成功后，不做长期乐观假数据。

推荐流程：

```text
提交请求
→ 后端成功
→ 重新查询资源
→ 使用后端最新状态刷新页面
```

## 15. 使用技术及理由

| 技术 | 用途 | 采用理由 |
| --- | --- | --- |
| Vue 3 Composition API | 页面和组件 | 与现有工程一致，逻辑可组合 |
| TypeScript | DTO、ViewModel、表单 | 提前发现字段不一致和空值问题 |
| Axios | REST、FormData、Blob | 现有请求层已使用，支持拦截器和上传进度 |
| Element Plus | 表格、表单、Dialog、上传 | 与现有 UI 体系一致 |
| Vue Router | 项目、中心页跳转 | 保持现有 Hash 路由 |
| Pinia | 用户、Token、权限 | 只保存全局状态，不保存项目局部 BOM 表单 |
| Mapper 纯函数 | 后端 DTO 转展示模型 | 隔离后端合同与 UI 展示需求 |
| AbortController | 取消旧请求 | 防止项目切换数据串线 |
| Blob/Object URL | 文件下载 | 浏览器标准文件流处理方式 |
| Vitest | API Mapper 和 Composable 单测 | 与 Vite/Vue 生态匹配、执行快 |
| Vue Test Utils | 组件交互测试 | 验证冻结只读、表单和错误状态 |
| `vue-tsc` | 类型检查 | 发现模板和 TypeScript 类型错误 |
| Vite build | 生产构建验证 | 验证打包、动态导入和资源引用 |

当前仓库使用 `package-lock.json`，后续统一使用 `npm`。不要同时使用 pnpm 改写锁文件。

## 17. 开发注意事项

1. 不要直接删除整个 mock 基础设施，其他未接模块仍可能依赖它。
2. 只替换 BOM、工艺和附件的项目级函数，避免一次改动全站。
3. 后端字段和值必须以实际接口为准，不以旧前端类型为准。
4. `processParamJson` 是 JSON 字符串，提交前必须校验，但不能改成嵌套对象发送。
5. 更新工艺路线需要提交完整 operations，不是局部一行。
6. 上传 FormData 不能继续使用固定 `application/json` 请求头。
7. 下载接口返回 Blob，不经过普通 `unwrapResponse`。
8. 下载文件名优先使用已查询的 `originalFileName`。
9. 文件中心后端是分页列表，不要强制映射成旧 mock 分组结构。
10. 冻结或锁定后必须重新拉取状态，不能只在前端改布尔值。
11. 删除附件是软删除，页面删除后刷新列表即可。
12. 上传和删除附件后刷新时间轴，否则 `documentCount` 会滞后。
13. 所有请求保留 `X-Request-Id`，方便后端日志定位。
14. 不记录 Token、密码、文件内容等敏感信息到浏览器日志。
15. 不在生产代码中保留 `console.log(response)`。

## 18. 后期维护注意事项

### 18.1 API 合同维护

- 后端 DTO 变化先修改 API 类型和 Mapper，再修改页面。
- 不允许同一后端字段在多个页面各自随意映射。
- 新增错误码时同步补充统一错误处理和文档。

### 18.2 状态维护

- BOM 状态文本统一维护，不在多个组件硬编码。
- Process 状态文本统一维护。
- 权限与状态必须同时判断。
- M5 发布门禁接入后复用同一附件查询结果。

### 18.3 文件维护

- 文件大小显示统一使用格式化工具。
- Object URL 使用后立即释放。
- 不在前端缓存 Blob 到 Pinia 或 localStorage。
- 下载失败必须显示服务端错误，不生成空文件。
- 后续切换 MinIO/S3 时前端接口合同应尽量不变。

### 18.4 性能维护

- 项目切换取消旧请求。
- 同一项目详情避免重复查询同一资源。
- 文件中心使用后端分页，不一次加载全部文件。
- 不在前端遍历全部项目制造 N+1 请求。

### 18.5 测试维护

- 每次修复线上或联调问题先补回归测试。
- Mapper 测试使用真实后端响应形状。
- 不用 mock 成功响应掩盖 API 失败。
- 版本升级后重新运行类型检查和生产构建。
