含义：

- 打开项目进度弹窗后，继续读取后端项目时间轴。

### 3.2 弹窗加载真实时间轴

```ts
async function loadActiveProgressTimeline(projectId: number) {
  try {
    const timeline = await getProjectTimeline(projectId)
    activeProgressTimeline.value = timeline
    activeProgressNodeKey.value = timeline.nodes.find((node) => node.status === 'current')?.nodeKey || timeline.nodes[0]?.nodeKey || null
    if (activeProgressProject.value) {
      activeProgressProject.value = {
        ...activeProgressProject.value,
        currentStage: timeline.currentNode,
        currentStepNo: timeline.currentStepNo
      }
    }
  } catch (error) {
    ElMessage.error(getErrorMessage(error))
  }
}
```

业务逻辑：

1. 用户从工作台点击项目。
2. 前端打开项目进度弹窗。
3. 弹窗调用 `GET /api/v1/projects/{projectId}/timeline`。
4. 当前节点由后端 `status === 'current'` 决定。
5. 弹窗标题、当前阶段、步骤号以后端返回为准。

### 3.3 确认当前节点

```ts
async function confirmCurrentProgressNode() {
  const context = requireProgressActionContext()
  if (!context || progressActionLoading.value) return
  try {
    const { value } = await ElMessageBox.prompt('可填写当前节点确认备注，留空则只确认节点。', '确认当前节点', {
      confirmButtonText: '确认',
      cancelButtonText: '取消',
      inputPlaceholder: '例如：资料已确认，可以进入下一环节'
    })
    progressActionLoading.value = 'confirm'
    await confirmTimelineNode(context.project.productId, context.node.nodeKey, String(value || ''))
    await refreshActiveProgressProject()
    ElMessage.success('当前节点已确认')
  } catch (error) {
    if (error !== 'cancel' && error !== 'close') ElMessage.error(getErrorMessage(error))
  } finally {
    progressActionLoading.value = false
  }
}
```

业务逻辑：

- 当前节点未确认时，用户可以先在工作台完成确认。
- 确认备注传给后端，后端负责写入节点确认状态和操作日志。
- 成功后刷新项目时间轴和工作台进行中项目列表。

### 3.4 推动项目进程

```ts
async function advanceCurrentProgressNode() {
  const context = requireProgressActionContext()
  if (!context || progressActionLoading.value) return
  if (!context.node.confirmed) {
    ElMessage.warning('请先确认当前节点，再推进到下一节点')
    return
  }
  try {
    await ElMessageBox.confirm('推进后项目会进入下一节点，新节点会回到未确认状态。', '推进下一节点', {
      confirmButtonText: '推进',
      cancelButtonText: '取消',
      type: 'warning'
    })
    progressActionLoading.value = 'advance'
    await advanceTimelineNode(context.project.productId, context.node.nodeKey)
    await refreshActiveProgressProject()
    ElMessage.success('已推进到下一节点')
  } catch (error) {
    if (error !== 'cancel' && error !== 'close') ElMessage.error(getErrorMessage(error))
  } finally {
    progressActionLoading.value = false
  }
}
```

业务逻辑：

- 工作台“推动项目进程”不再是占位提示。
- 前端先判断当前节点是否已经确认。
- 已确认才调用 `POST /api/v1/projects/{projectId}/timeline/{nodeKey}/advance`。
- 推进成功后刷新工作台列表和弹窗时间轴，保证用户看到后端真实状态。

### 3.5 退回当前节点

```ts
async function returnCurrentProgressNode() {
  const context = requireProgressActionContext()
  if (!context || progressActionLoading.value) return
  try {
    const { value } = await ElMessageBox.prompt('请输入退回原因，系统会写入项目时间轴操作记录。', '退回当前节点', {
      confirmButtonText: '退回',
      cancelButtonText: '取消',
      inputPlaceholder: '例如：资料缺失，需要补充后重新确认'
    })
    progressActionLoading.value = 'reject'
    await returnTimelineNode(context.project.productId, context.node.nodeKey, String(value || ''), true)
    await refreshActiveProgressProject()
    ElMessage.success('已退回上一节点')
  } catch (error) {
    if (error !== 'cancel' && error !== 'close') ElMessage.error(getErrorMessage(error))
  } finally {
    progressActionLoading.value = false
  }
}
```

业务逻辑：

- 工作台驳回按钮映射到后端时间轴退回接口。
- 退回原因传给后端，保持推进过程可追溯。
- `resetConfirmation = true`，退回后节点确认状态重新由后端控制。

### 3.6 上传当前节点资料

```ts
async function submitProgressUpload() {
  const context = requireProgressActionContext()
  if (!context || progressActionLoading.value) return
  if (!progressUploadFile.value) {
    ElMessage.warning('请先选择要上传的资料')
    return
  }
  try {
    progressActionLoading.value = 'upload'
    await uploadTimelineAttachment(context.project.productId, context.node.nodeKey, progressUploadFile.value, {
      fileCategory: progressUploadCategory.value,
      remark: '工作台当前节点资料'
    })
    progressUploadVisible.value = false
    await refreshActiveProgressProject()
    ElMessage.success('资料已上传')
  } catch (error) {
    ElMessage.error(getErrorMessage(error))
  } finally {
    progressActionLoading.value = false
  }
}
```

业务逻辑：

- 工作台上传资料围绕“当前项目 + 当前节点 + 资料类别”进行。
- 上传接口为 `POST /api/v1/projects/{projectId}/timeline/{nodeKey}/attachments`。
- 文件元数据和文件存储仍由后端校验。
- 上传完成后刷新时间轴，节点附件数由后端重新返回。

## 4. 工作台到模块的数据联动逻辑

本次实现后的数据方向：

```text
工作台项目进度弹窗
  -> 获取后端时间轴
  -> 确认 / 推进 / 退回 / 上传资料
  -> 后端保存项目节点、附件、日志
  -> 刷新工作台项目列表和当前项目时间轴
  -> 项目中心、文件中心、发布门禁等模块读取同一份后端数据
```

当前可跑通的最小 MVP：

1. 工作台读取进行中项目。
2. 点击项目后读取真实时间轴。
3. 在工作台确认当前节点。
4. 当前节点已确认后，在工作台推动到下一节点。
5. 在工作台上传当前节点资料。
6. 操作完成后刷新工作台列表和当前弹窗时间轴。

暂未完整闭环的部分：

- “暂不推进”仍只做前端提示，因为当前后端没有暂停/挂起接口和审计模型。
- “强制推进”仍只做前端提示，因为企业级场景必须先补后端权限、原因、审计和风险闭环。
- 文件中心、发布门禁的实际联动展示依赖既有模块接口和页面刷新，本次没有改模块页面。

## 6. 后期维护建议

1. 补齐暂停/挂起接口：为“暂不推进”新增后端状态、原因、恢复动作和操作日志。
2. 补齐强制推进闭环：强制推进必须包含 RBAC 权限、原因必填、风险说明、操作日志和审计查询。

4. 统一刷新策略：后续可建立项目级刷新事件，让工作台、项目中心、发布门禁、文件中心在关键动作后统一刷新。
5. 模块继续去静态化：BOM、工艺、文件中心、测试、质量、成本等模块的真实业务结论必须持续收敛到后端数据源。
6. 增加端到端验收：建议补一条 Playwright 路径，覆盖“工作台确认节点 -> 推进 -> 项目中心时间轴一致 -> 文件中心看到附件”。

## 8. 运行问题补充处理：时间轴动作错误提示

### 8.1 现象

前端点击项目中心“确认当前节点”时，浏览器控制台出现 Axios 请求栈：

```text

```

```text

```

这个提示不能告诉用户真实业务原因。

### 8.2 排查证据

后端当前项目时间轴查询结果显示，项目 `9` 当前节点为：

```text
PRODUCT_LINE_MOLD_TRIAL
currentConfirmed=false
```

直接调用确认接口时，后端有两类明确业务响应：

```text
无 token：
code=40101
message=未登录或登录已失效

带 token 但 nodeKey 不是当前节点：
code=40002
message=只能操作当前时间轴节点
```

### 8.3 根因

`ProjectCenterView.vue` 和 `DashboardView.vue` 的 `getErrorMessage(error)` 先读取 `Error.message`，导致 Axios 错误被显示为通用文案 `Request failed with status code 400`，没有优先展示后端 `response.data.message`。

### 8.4 修复代码

项目中心和工作台均调整为优先读取后端业务消息：

```ts
function getErrorMessage(error: unknown) {
  if (typeof error === 'object' && error && 'response' in error) {
    const response = (error as { response?: { data?: { message?: string } } }).response
    if (response?.data?.message) return response.data.message
  }
  if (error instanceof Error) return error.message
  return '操作失败，请稍后重试'
}
```

工作台兜底文案为：

```ts
return '操作失败'
```

## 9. 运行配置补充处理：dev 环境安全过滤器必须启用

### 9.1 现象

浏览器反复出现：

```text
GET /api/v1/auth/profile 400
POST /api/v1/projects/9/timeline/PRODUCT_LINE_MOLD_TRIAL/confirm 400
POST /api/v1/auth/login 500
```

命令行复现发现：

```text
不带 token 调 /api/v1/auth/profile：
HTTP 400
code=40101
message=未登录或登录已失效

登录 engineer01 / plm123456：
登录成功并返回 token

使用新 token 调 /api/v1/auth/profile：
仍然 HTTP 400
code=40101
message=未登录或登录已失效
```

### 9.2 根因

`application-dev.yml` 原配置为：

```yaml
app:
  security:
    enabled: ${APP_SECURITY_ENABLED:false}
```

在 `APP_SECURITY_ENABLED=false` 时，`SimpleTokenAuthenticationFilter` 会直接跳过 token 解析：

```java
if (!appProperties.getSecurity().isEnabled() || isPublicPath(request.getRequestURI())) {
    filterChain.doFilter(request, response);
    return;
}
```

结果是：

- 登录接口能返回 token。
- 但后续请求不会把 token 解析进 `CurrentUserContext`。
- `profile`、确认节点、推进节点、上传资料等依赖当前用户的接口会认为“未登录或登录已失效”。

### 9.3 修复配置

将 dev 默认安全开关改为启用：

```yaml
app:
  security:
    enabled: ${APP_SECURITY_ENABLED:true}
```

同时更新本地启动脚本：

```powershell
$env:APP_SECURITY_ENABLED = "true"
```
