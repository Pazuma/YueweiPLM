核心逻辑：

- `projectId = productId`，创建 BOM 前校验 Product 存在。
- BOM 默认 `status=draft`。
- BOM 明细校验 `quantity > 0`、`lineNo > 0`、名称和单位必填。
- 同一个 BOM 下 `lineNo` 不能重复。
- `freeze` 后 BOM 状态变为 `frozen`，后续 PUT、增删改明细全部返回 `40301 VERSION_FROZEN`。
- 创建、更新、明细新增/修改/删除、冻结都写 `plm_operation_log`。

### 2.3 工艺路线模块

新增目录：`src/main/java/com/yuewei/plm/module/process`

- Controller：`ProcessRouteController`
- Service：`ProcessRouteService`、`ProcessRouteServiceImpl`
- Repository：`ProcessRepository`
- TypeHandler：`PostgresJsonbStringTypeHandler`
- Entity：`ProcessEntity`
- DTO：`ProcessRouteSaveDTO`、`ProcessOperationDTO`
- VO：`ProcessRouteVO`、`ProcessOperationVO`
- Test：`src/test/java/com/yuewei/plm/module/process/service/impl/ProcessRouteServiceImplTest.java`

核心逻辑：

- 路线头：`plm_process.process_type = routing`。
- 工序行：`plm_process.process_type = operation`，`parent_process_id = 路线 process_id`。
- 创建/更新路线时校验 Product 存在。
- 每道工序必须有 `sequenceNo`、`processName`、`qualityRequirement`。
- `processParamJson` 填写时必须是合法 JSON。
- `process_param_json` 在现有 PostgreSQL 中为 `jsonb`；实体字段通过
  `PostgresJsonbStringTypeHandler` 使用 JDBC `Types.OTHER` 写入，避免普通
  VARCHAR 参数触发 jsonb 类型转换错误。
- 同一路线下 `sequenceNo` 不可重复。
- M4 更新策略：软删除旧工序，再按请求重建新工序。
- 冻结后路线和工序状态都变为 `locked`，后续 PUT 返回 `40301 VERSION_FROZEN`。

## 4. Apifox 测试步骤

### 4.1 启动前确认

1. 使用 dev 配置启动后端。
2. 首次启动观察日志，确认 Flyway 执行 M4 迁移。
3. 如果数据库已有历史表，`baseline-on-migrate=true` 会让 Flyway 接管后续迁移。

Flyway 的 `baseline-version` 必须在 YAML 中写成字符串：

```yaml
spring:
  flyway:
    baseline-version: "20260703.0000"
```

不能省略引号，否则 YAML 可能把版本解析为科学计数法，启动时出现：

```text
Version may only contain 0..9 and . (dot). Invalid version: 2.0260703E7
```

如果数据库已经存在旧版 `plm_attachment`，M4 迁移还会通过
`alter table ... add column if not exists` 补齐 `timeline_node_key`、
`file_category`、`storage_key` 等字段。仅使用
`create table if not exists` 无法升级已有表，后续索引会因字段不存在而失败。

如果启动日志出现 `Port 8080 was already in use`，先查询占用进程：

```powershell
cmd /c netstat -ano | Select-String ":8080"
```

确认该 PID 是旧的 PLM Java 进程后再停止：

```powershell
Stop-Process -Id <PID>
```

也可以临时使用其他端口启动：

```powershell
$env:SERVER_PORT = "8081"
& $mvn spring-boot:run
```

### 4.6 创建工艺路线

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/process-routes
```

```json
{
  "processName": "超队3.0 样品工艺路线",
  "versionNo": "A",
  "remark": "M4 工艺路线验收",
  "operations": [
    {
      "sequenceNo": 10,
      "processName": "注塑成型",
      "processParamJson": "{\"temperature\":80,\"pressure\":0.5}",
      "standardTimeMins": 15,
      "qualityRequirement": "外观无缩水、无明显披锋"
    },
    {
      "sequenceNo": 20,
      "processName": "磁铁装配",
      "processParamJson": "{\"magnetCount\":36}",
      "standardTimeMins": 8,
      "qualityRequirement": "磁铁方向一致，磁吸力满足规格"
    },
    {
      "sequenceNo": 30,
      "processName": "功能测试",
      "processParamJson": "{\"sampleSize\":5}",
      "standardTimeMins": 5,
      "qualityRequirement": "磁吸、按键、孔位全部通过"
    }
  ]
}
```

通过标准：

- `data.processId` 有值
- `data.processType=routing`
- `data.operations.length=3`
- 工序按 `sequenceNo` 升序返回

如果请求格式正确但返回 `50001`，并且工序填写了 `processParamJson`，需确认
后端已包含 `PostgresJsonbStringTypeHandler` 并完成重启。旧代码会把 JSON
作为 VARCHAR 写入 PostgreSQL `jsonb` 列，导致整条路线事务回滚。

## 6. 后续维护建议

1. M4 使用本地真实文件，后续接 MinIO/S3 时只替换 `StorageClient` 实现，Controller 和 Service 合同保持不变。
2. `plm_process` 已按最小 Process 模型承载 routing/operation；后续更复杂版本管理仍应作为 Process 扩展，不新增 Routing 根对象。
3. 文件中心无结果返回 `code=0` 且 `content=[]`，文件丢失和存储异常返回错误码，不要吞成空结果。
4. Flyway 引入后，后续数据库变更继续按 `VyyyyMMdd_HHmm__description.sql` 新增迁移，避免直接改已发布迁移。
5. 生产库首次启用 Flyway 前建议备份数据库，确认历史 SQL 与当前库结构一致。
