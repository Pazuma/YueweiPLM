本次只生成方案沉淀文档，不修改任何实际业务代码。

本次只涉及前端，不涉及后端 Controller、Service、数据库、接口、迁移脚本和业务状态机。文档中的代码均为后续实施草稿，用于评审和二次开发。

目标口径：运行态页面不再依赖前端假数据；测试态保留测试数据。

## 1. 任务理解

当前前端项目中仍存在多类假数据：

1. `src/mock/*` 中的大量页面演示数据。
2. API 模块中直接 `import '@/mock/...'` 并通过 `mockResolve` 返回数据。
3. 工作台 `DashboardView.vue` 中硬编码的待办、风险、冻结、新建项目选项。
4. 个别页面存在“仅前端假数据”“前端假数据演示”等展示文案。

用户要求“先清理项目的假数据，只留测试数据”，但本次只沉淀文档，不直接修改业务代码。

本方案定义后续清理边界：

- 保留：`__tests__` 目录内单元测试、组件测试、API 测试使用的 mock 数据。
- 保留：测试辅助工厂函数，例如 `createProject()`、`createTimeline()`、`mockResolvedValue()`。
- 清理：运行页面、正式路由、业务 API 模块中直接返回的前端假数据。
- 清理：页面上暴露给用户的“前端假数据演示 / 仅前端假数据”等标签。
- 过渡：后端未实现的页面不伪装成真实数据，改成空态、未接入提示或禁用入口。

## 7. 实施方案

### 7.1 清理原则

1. 运行态禁止从 `src/mock/*` 读取业务数据。
2. 运行态 API 模块必须使用 `request.get/post/put/delete`。
3. 后端未提供的模块，前端返回明确的未接入错误或展示空态，不返回假数据。
4. 测试数据移动或保留在测试上下文中，例如：
   - `src/views/**/__tests__`
   - `src/api/modules/__tests__`
   - `src/test-fixtures`
5. 页面文案不得出现“前端假数据演示”“仅前端假数据”等运行态标签。

### 7.3 API 模块改造模式

#### 7.3.1 已有后端接口的模块

把 mock 写法：

```ts
import { bomCenterData } from '@/mock/data'
import { mockResolve } from '../request'

export function getBomCenterSnapshot() {
  return mockResolve(() => structuredClone(bomCenterData))
}
```

改为真实接口：

```ts
import request, { unwrapResponse } from '../request'
import type { BomCenterSnapshot } from '@/types/bom'

export async function getBomCenterSnapshot(): Promise<BomCenterSnapshot> {
  const response = await request.get('/bom-center/snapshot')
  return unwrapResponse<BomCenterSnapshot>(response)
}
```

如果后端没有 `/bom-center/snapshot`，则不建议前端继续造假，应改为未接入：

```ts
export async function getBomCenterSnapshot(): Promise<BomCenterSnapshot> {
  throw new Error('BOM 中心快照接口未接入，请先在项目详情或项目级 BOM 页面查看真实数据')
}
```
