## 1. 任务理解

M4 的目标是让项目推进过程中能沉淀成果物。时间轴仍然是项目推进主线，BOM、工艺路线、SOP、SIP、测试报告等资料不是孤立页面，而是挂在 Product-as-project 的当前节点或历史节点上。

本次后端实施重点：

```text
1. 项目能创建和维护 BOM。
2. BOM 能添加多条明细。
3. BOM 冻结后不能修改。
4. 项目能创建和维护工艺路线。
5. 工艺路线能维护工序顺序和质量要求。
6. 工艺路线冻结后不能修改。
7. 当前时间轴节点能上传文件。
8. 本机目录里能看到真实文件。
9. plm_attachment 能看到元数据。
10. 文件中心能按项目、节点、分类查到文件。
11. 下载文件存在时返回文件流。
12. 本机文件丢失时返回明确错误。
13. 所有关键动作都有日志。
```

## 3. 所属 PLM 业务链路

M4 属于新产品线和新型号线的研发资料沉淀链路：

```text
Product 立项
  -> 时间轴推进到样品与工艺节点
  -> 维护 BOM
  -> 维护工艺路线
  -> 上传 SOP / SIP / 测试报告 / 客户确认资料
  -> 冻结 BOM 和工艺路线
  -> 文件中心归档查询和下载
```

当前后端仍保持：

```text
projectId = productId。
项目不是新的根对象，而是 Product 的项目视图。
BOM 不是根对象，而是 Product 下的版本化资料扩展。
工艺路线不是 Routing 根对象，而是 Process 对象中的 routing 记录和 operation 明细。
文件不是 FileVersion 根对象，而是 plm_attachment 元数据 + 本地/对象存储文件。
```

## 5. 涉及数据对象、状态和 API

### 5.1 核心对象映射

| 能力 | 归属对象 | 说明 |
| --- | --- | --- |
| BOM 头 | Product 扩展资料 | 表为 `plm_product_bom`，不作为根对象 |
| BOM 明细 | Product + Inventory 关系 | 表为 `plm_product_bom_item` |
| 工艺路线 | Process | `process_type=routing` 的 Process 记录作为路线头 |
| 工序明细 | Process | `parent_process_id=路线 process_id` 的 Process 记录作为工序 |
| 时间轴文件 | Product 附件 | `owner_object_type=PRODUCT`，`owner_object_id=projectId`，补充 `timeline_node_key` |
| 文件中心 | plm_attachment 查询视图 | 按 projectId、nodeKey、fileCategory 聚合 |

### 5.2 状态

```text
BOM：draft -> frozen -> archived
工艺路线 Process：draft -> locked -> changed -> archived
附件：draft -> released -> archived
```

M4 的冻结语义是最小闭环：

```text
BOM freeze 后 status=frozen，BOM 头和明细均不可修改。
工艺路线 freeze 后 route 与所有 operation 均 status=locked，不可修改。
附件上传后默认 draft，本阶段先保证能上传、查询、下载、删除；正式审批发布后续 M5/M6 再接。
```

## 6. 不确定点和建议口径

| 不确定点 | 建议口径 |
| --- | --- |
| BOM 冻结是否等同 released | M4 先用 `frozen` 表达不可修改，正式 `released` 等发布流程后续接审批 |
| BOM 明细是否必须 2-3 条才能冻结 | 测试时添加 3 条；业务门禁建议至少 1 条，不人为限制真实 BOM 数量 |
| 工艺路线是否单独建表 | 不单独创建 Routing 根对象；用 Process 自关联承载 |
| 文件上传是否直接 MinIO | M4 先实现本机真实文件，后续替换 MinIO/S3 实现 `StorageClient` |
| 文件下载返回流还是签名 URL | 用户要求文件流；M4 本机存储返回 `Resource` 文件流 |
| 文件丢失错误码 | 增加明确业务错误，例如 `50003 FILE_SERVICE_ERROR` 或 `40402 ATTACHMENT_NOT_FOUND` 搭配“文件实体丢失”消息 |

## 7. 实施步骤

### 7.1 第一步：BOM 查询和维护

新增 BOM 头和 BOM 明细表、实体、DTO、VO、Repository、Service、Controller。

关键规则：

```text
创建 BOM 时校验 projectId 对应 Product 存在。
BOM 状态默认为 draft。
BOM item 的 quantity 必须大于 0。
BOM item 的 lineNo 在同一个 bomId 下不能重复。
BOM 冻结前允许新增、修改、删除明细。
BOM 冻结后 PUT/POST item/PUT item/DELETE item 全部返回明确业务错误。
```

### 7.2 第二步：BOM 冻结

冻结接口：

```text
POST /api/v1/boms/{bomId}/freeze
```

关键规则：

```text
BOM 必须存在且未删除。
BOM status 必须为 draft。
BOM 至少有 1 条有效明细。
冻结后 plm_product_bom.status=frozen。
冻结后写 frozen_at、frozen_by。
成功动作写 plm_operation_log：BOM_FREEZE。
```

### 7.3 第三步：工艺路线查询和维护

用 Process 自关联表达路线：

```text
路线头：plm_process.process_type = routing
工序行：plm_process.process_type = operation
工序行.parent_process_id = 路线头.process_id
```

关键规则：

```text
创建路线时写入 route header，并批量写入 operations。
PUT 路线时，更新路线头和工序集合。
同一条路线下 operation.sequence_no 不重复。
每道工序必须有 process_name、sequence_no、quality_requirement。
process_param_json 如填写必须是合法 JSON。
```

### 7.4 第四步：工艺路线冻结

冻结接口：

```text
POST /api/v1/process-routes/{processId}/freeze
```

关键规则：

```text
processId 必须是 process_type=routing。
路线 status 必须为 draft。
至少有 1 道有效工序。
所有工序必须有质量要求。
冻结后 route 和 operations 状态都更新为 locked。
成功动作写 plm_operation_log：PROCESS_ROUTE_FREEZE。
```

### 7.5 第五步：时间轴节点文件上传

上传接口：

```text
POST /api/v1/projects/{projectId}/timeline/{nodeKey}/attachments
Content-Type: multipart/form-data
```

字段：

```text
file: 文件
fileCategory: sop/sip/testing/drawing/customer_confirm/other
versionNo: 文件版本号
remark: 备注，可选
```

关键规则：

```text
校验 Product 存在。
校验 nodeKey 是当前 productType 对应时间轴中的合法节点。
校验文件非空、大小不超过配置上限、扩展名在白名单。
保存真实文件到 app.storage.local-root 下。
写 plm_attachment 元数据。
owner_object_type=PRODUCT，owner_object_id=projectId。
timeline_node_key=nodeKey。
成功动作写 plm_operation_log：ATTACHMENT_UPLOAD。
```

### 7.6 第六步：文件中心归档查询和下载

文件中心查询：

```text
GET /api/v1/file-center/attachments?projectId=1&nodeKey=PRODUCT_LINE_SAMPLE_PROCESS&fileCategory=testing&page=1&size=20
```

下载：

```text
GET /api/v1/attachments/{attachmentId}/download
```

关键规则：

```text
附件元数据不存在，返回 40402 附件不存在。
元数据存在但本机文件丢失，返回明确错误，不能返回空流。
文件存在时返回 application/octet-stream 文件流。
下载成功写 plm_attachment_download_log。
下载成功写 plm_operation_log：ATTACHMENT_DOWNLOAD。
```

### 10.2 LocalStorageClient 核心逻辑

```java
@Component
@RequiredArgsConstructor
public class LocalStorageClient implements StorageClient {

    private final AppProperties appProperties;

    @Override
    public StoredObject store(String storageKey, InputStream inputStream) throws IOException {
        Path root = Paths.get(appProperties.getStorage().getLocalRoot()).toAbsolutePath().normalize();
        Path target = root.resolve(storageKey).normalize();
        if (!target.startsWith(root)) {
            throw new IOException("Invalid storage key");
        }
        Files.createDirectories(target.getParent());
        MessageDigest digest = MessageDigest.getInstance("SHA-256");
        long size;
        try (DigestInputStream digestInput = new DigestInputStream(inputStream, digest);
             OutputStream output = Files.newOutputStream(target)) {
            size = digestInput.transferTo(output);
        }
        return new StoredObject(storageKey, size, HexFormat.of().formatHex(digest.digest()));
    }

    @Override
    public Resource loadAsResource(String storageKey) {
        Path root = Paths.get(appProperties.getStorage().getLocalRoot()).toAbsolutePath().normalize();
```

### 10.3 BOM 冻结防修改

```java
private ProductBom requireEditableBom(Long bomId) {
    ProductBom bom = getBomOrThrow(bomId);
    if ("frozen".equals(bom.getStatus()) || "archived".equals(bom.getStatus())) {

@Override
@Transactional
public ProductBomVO freeze(Long bomId, HttpServletRequest request) {
    ProductBom bom = requireEditableBom(bomId);
    long itemCount = bomItemRepository.selectCount(Wrappers.<ProductBomItem>lambdaQuery()
        .eq(ProductBomItem::getProductBomId, bomId)
        .eq(ProductBomItem::getDeletedFlag, 0));
    if (itemCount <= 0) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "BOM 至少需要一条明细才能冻结");
    }
    CurrentUser currentUser = requireCurrentUser();
    bom.setStatus("frozen");
    bom.setFrozenAt(LocalDateTime.now());
    bom.setFrozenBy(currentUser.displayName());
    fillUpdateAudit(bom, currentUser);
    bomRepository.updateById(bom);
    writeLog("BOM_FREEZE", bom.getProductBomId(), bom.getBomCode(), bom.getBomName(), request);
    return getById(bomId);
}
```

### 10.4 工艺路线用 Process 自关联承载

```java
private void assertEditableRoute(ProcessEntity route) {
    if (!"routing".equals(route.getProcessType())) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "processId 不是工艺路线");
    }
    if ("locked".equals(route.getStatus())) {
        throw new BusinessException(ErrorCodeConstants.VERSION_FROZEN, "工艺路线已冻结，不能继续修改");
    }
}

private void validateOperations(List<ProcessOperationDTO> operations) {
    if (operations == null || operations.isEmpty()) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "工艺路线至少需要一道工序");
    }
    Set<Integer> sequenceNos = new HashSet<>();
    for (ProcessOperationDTO operation : operations) {
        if (!StringUtils.hasText(operation.getProcessName())) {
            throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "工序名称不能为空");
        }
        if (operation.getSequenceNo() == null || !sequenceNos.add(operation.getSequenceNo())) {
            throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "工序顺序不能为空且不能重复");
        }
        if (!StringUtils.hasText(operation.getQualityRequirement())) {
            throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "质量要求不能为空");
        }
        assertValidJsonIfPresent(operation.getProcessParamJson());
    }
}
```

```java
public AttachmentVO uploadTimelineAttachment(
    Long projectId,
    String nodeKey,
    MultipartFile file,
    String fileCategory,
    String versionNo,
    String remark,
    HttpServletRequest request
) {

    String ext = FilenameUtils.getExtension(originalName).toLowerCase(Locale.ROOT);
    String storageKey = "projects/" + projectId + "/timeline/" + nodeKey + "/"
        + UUID.randomUUID() + "." + ext;

    StoredObject storedObject;
    try {
        storedObject = storageClient.store(storageKey, file.getInputStream());
    } catch (IOException ex) {
        throw new BusinessException(ErrorCodeConstants.FILE_SERVICE_ERROR, "文件保存失败，请稍后重试");
    }

    Attachment attachment = new Attachment();
    attachment.setOwnerObjectType("PRODUCT");
    attachment.setOwnerObjectId(projectId);
    attachment.setTimelineNodeKey(nodeKey);
    attachment.setFileCategory(fileCategory);
    attachment.setFileName(originalName);
    attachment.setFileExt(ext);
    attachment.setStorageKey(storedObject.storageKey());
    attachment.setFileSize(storedObject.fileSize());
    attachment.setMimeType(file.getContentType());
    attachment.setChecksum(storedObject.checksum());
    attachment.setVersionNo(versionNo);
    attachment.setStatus("draft");
    attachment.setRemark(remark);
    fillCreateAudit(attachment);
    attachmentRepository.insert(attachment);
    writeLog("ATTACHMENT_UPLOAD", attachment.getAttachmentId(), null, originalName, request);
    return toVO(attachment);
}
```

## 12. 代码逻辑说明

### 12.1 BOM 逻辑

```text
ProductBomService.create：
  校验 Product 存在。
  生成 bom_code。
  status=draft。
  写 BOM_CREATE 日志。

ProductBomService.addItem：
  requireEditableBom。
  校验 quantity > 0。
  校验 line_no 不重复。
  插入 item。
  写 BOM_ITEM_CREATE 日志。

ProductBomService.updateItem/deleteItem：
  requireEditableBom。
  修改或逻辑删除 item。
  写 BOM_ITEM_UPDATE/BOM_ITEM_DELETE 日志。

ProductBomService.freeze：
  requireEditableBom。
  校验至少存在有效 item。
  status=frozen。
  写冻结人、冻结时间。
  写 BOM_FREEZE 日志。
```

### 12.2 工艺路线逻辑

```text
ProcessRouteService.create：
  校验 Product 存在。
  插入 process_type=routing 的路线头。
  批量插入 process_type=operation 且 parent_process_id=routeId 的工序。
  写 PROCESS_ROUTE_CREATE 日志。

ProcessRouteService.update：
  校验 route 未 locked。
  校验 operations sequence_no 不重复。
  采用“软删除旧工序 + 插入新工序”或差异更新，建议 M4 使用软删除重建，逻辑简单。
  写 PROCESS_ROUTE_UPDATE 日志。

ProcessRouteService.freeze：
  校验 route 未 locked。
  校验至少一道工序。
  校验每道工序有 qualityRequirement。
  route 和 operations 都更新 status=locked。
  写 PROCESS_ROUTE_FREEZE 日志。
```

### 12.3 附件逻辑

```text
AttachmentService.uploadTimelineAttachment：
  校验 Product。
  校验 nodeKey。
  校验文件大小和后缀。
  保存本机文件。
  写 plm_attachment 元数据。
  写 ATTACHMENT_UPLOAD 日志。

AttachmentService.listTimelineAttachments：
  owner_object_type=PRODUCT。
  owner_object_id=projectId。
  timeline_node_key=nodeKey。
  deleted_flag=0。

AttachmentService.pageFileCenter：
  支持 projectId、nodeKey、fileCategory、keyword、page、size。
  返回 PageVO<AttachmentVO>。

AttachmentService.download：
  查元数据。
  校验真实文件存在。
  存在则返回 Resource 文件流。
  不存在则返回 FILE_SERVICE_ERROR 明确错误。
  下载成功写下载日志和操作日志。

AttachmentService.delete：
  released/frozen 状态禁止删除。
  M4 逻辑删除元数据，本机文件保留。
  写 ATTACHMENT_DELETE 日志。
```

## 15. 后续维护建议

1. M4 先实现本机真实文件，后续接 MinIO 时只替换 `StorageClient` 实现，不改 Controller 和 Service 合同。
2. BOM 当前冻结为最小闭环，后续审批流成熟后可把 `freeze` 前置到审批完成后触发。
3. 工艺路线使用 Process 自关联，后续如果需要更复杂版本管理，可以增加 Process 扩展表，但仍不要新增 Routing 根对象。
4. 文件中心查询要区分“成功但无结果”和“查询失败”：无结果返回 `code=0` 且 `content=[]`，异常返回错误码。
5. 文件实体丢失必须作为错误返回，不能伪装成空文件或空结果。
6. 后续并发冻结和并发修改建议增加乐观锁字段或条件更新，避免冻结同时仍写入明细。
7. 下载日志失败不应影响文件下载，但操作日志失败是否回滚需统一团队口径；建议关键业务日志失败时回滚，下载日志可降级。
8. 时间轴节点文件数量应由 `plm_attachment` 实时统计，避免另存冗余计数字段。
9. 所有新增接口需要同步更新正式 API 文档和前端接口层。

## 16. 最终验收清单

| 验收项 | 通过标准 |
| --- | --- |
| 项目能创建 BOM | `POST /projects/{projectId}/boms` 返回 `code=0` |
| BOM 能添加 2-3 条明细 | `GET /boms/{bomId}` 返回明细数量 >= 3 |
| BOM 冻结后不能修改 | 冻结后 PUT/POST item/DELETE item 返回明确业务错误 |
| 项目能创建工艺路线 | `POST /projects/{projectId}/process-routes` 返回路线 ID |
| 工艺路线能维护工序顺序和质量要求 | `operations` 按 `sequenceNo` 返回且质量要求不为空 |
| 工艺路线冻结后不能修改 | 冻结后 PUT 返回明确业务错误 |
| 当前时间轴节点能上传文件 | 上传接口返回 `attachmentId` |
| 本机目录能看到真实文件 | `app.storage.local-root` 下存在对应 `storageKey` 文件 |
| `plm_attachment` 能看到元数据 | 数据库能查到 owner、node、category、storage_key |
| 文件中心能按项目、节点、分类查到文件 | 查询接口返回刚上传的 attachment |
| 下载文件存在时返回文件流 | HTTP 200 + `Content-Disposition` |
| 本机文件丢失时返回明确错误 | 返回错误码和可读错误消息 |
| 所有关键动作都有日志 | `plm_operation_log` 能查到对应 action |
