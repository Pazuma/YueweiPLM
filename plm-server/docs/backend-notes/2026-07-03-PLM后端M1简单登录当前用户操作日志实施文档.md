# PLM 后端 M1 简单登录、当前用户与操作日志实施文档

> 日期：2026-07-03  
> 文档类型：M1 实施步骤 / Apifox 验证步骤  
> 适用仓库：`D:\Yuewei\git\YUEWEI\plm-server`  
> 沉淀目录：`D:\Yuewei\资料\PLM\docs\后端-沉淀`  
> 目标：让后端知道“是谁在操作”，并让关键业务动作能落库留痕。

## 1. M1 目标

M1 要补齐后续业务闭环的第一批公共能力：

```text
1. 用户能用账号密码登录。
2. 登录成功后拿到 token。
3. 携带 token 能获取当前用户 profile。
4. 未携带 token 访问业务接口必须返回未登录。
5. 后端业务代码能稳定拿到 operator_user_id 和 operator_user_name。
6. 关键动作能写入 plm_operation_log。
7. Apifox 能验证登录、profile、未登录拦截、测试写日志、日志查询。
```

为什么 M1 要先做：

```text
后面所有动作都需要操作人：
推进节点是谁，上传文件是谁，冻结 BOM 是谁，发布项目是谁。
如果没有当前用户和操作日志，业务跑起来也不可追溯。
```

M1 不做完整 RBAC，不做复杂角色权限矩阵，不做菜单权限，不做审批权限。

M1 只解决：

```text
登录身份
当前用户
allPermissions 简单标记
操作日志
未登录拦截
```

### 3.3 allPermissions 规则

M1 先按简单规则处理：

```text
从 sys_user 表查询账号和用户信息。
工程部两位正式用户默认 allPermissions=true。
其他用户 allPermissions=false。
```

推荐落地方式：

```text
1. sys_user 表保留 all_permissions 字段。
2. 种子数据中把工程部两位正式用户 all_permissions=true。
3. AuthService 登录时读取该字段并写入 CurrentUser。
```

这样不是完整 RBAC，只是一个临时全权限开关，语义清晰，后续也容易迁移到角色权限系统。

两位正式用户账号如果尚未最终确认，开发环境建议先使用：

```text
engineer01
engineer02
```

正式实施前需要由业务确认真实账号、姓名、初始密码策略。

## 5. 数据库设计建议

### 5.1 sys_user

如果当前数据库已有 `sys_user`，优先适配现有字段，不重复建表。

如果尚未建表，M1 建议最小字段：

```sql
create table if not exists sys_user (
    user_id bigserial primary key,
    username varchar(64) not null unique,
    password_hash varchar(128) not null,
    display_name varchar(64) not null,
    department_name varchar(64) not null,
    formal_flag integer not null default 1,
    all_permissions boolean not null default false,
    status varchar(32) not null default 'active',
    created_at timestamp not null default now(),
    created_by varchar(64),
    updated_at timestamp not null default now(),
    updated_by varchar(64),
    deleted_flag integer not null default 0
);

create index if not exists idx_sys_user_username on sys_user(username);
create index if not exists idx_sys_user_status on sys_user(status);
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `user_id` | 用户 ID，写入操作日志的 `operator_user_id` |
| `username` | 登录账号 |
| `password_hash` | 密码 hash，不建议明文存储 |
| `display_name` | 用户姓名，写入操作日志的 `operator_user_name` |
| `department_name` | 部门名，工程部用户识别依据之一 |
| `formal_flag` | 是否正式用户，1 是，0 否 |
| `all_permissions` | M1 临时全权限标记 |
| `status` | `active` 才允许登录 |
| `deleted_flag` | 软删除标记 |

开发环境种子数据建议：

```sql
insert into sys_user (
    username,
    password_hash,
    display_name,
    department_name,
    formal_flag,
    all_permissions,
    status,
    created_by,
    updated_by
) values
('engineer01', '$2a$10$replace_with_real_bcrypt_hash', '工程部用户一', '工程部', 1, true, 'active', 'seed', 'seed'),
('engineer02', '$2a$10$replace_with_real_bcrypt_hash', '工程部用户二', '工程部', 1, true, 'active', 'seed', 'seed')
on conflict (username) do nothing;
```

密码处理建议：

```text
使用 Spring Security 的 BCryptPasswordEncoder。
不要为了“简单登录”把密码明文写入数据库。
M1 简单的是权限模型，不是密码安全。
```

### 5.2 plm_operation_log

建议建表：

```sql
create table if not exists plm_operation_log (
    log_id bigserial primary key,
    request_id varchar(64) not null,
    operator_user_id bigint,
    operator_user_name varchar(64),
    action varchar(64) not null,
    business_type varchar(64) not null,
    business_id varchar(64),
    business_code varchar(128),
    business_name varchar(256),
    result varchar(32) not null default 'success',
    request_method varchar(16),
    request_uri varchar(512),
    client_ip varchar(64),
    user_agent varchar(512),
    detail_json text,
    created_at timestamp not null default now(),
    created_by varchar(64),
    updated_at timestamp,
    updated_by varchar(64),
    deleted_flag integer not null default 0
);

create index if not exists idx_operation_log_request_id on plm_operation_log(request_id);
create index if not exists idx_operation_log_operator on plm_operation_log(operator_user_id);
create index if not exists idx_operation_log_action on plm_operation_log(action);
create index if not exists idx_operation_log_business on plm_operation_log(business_type, business_id);
create index if not exists idx_operation_log_created_at on plm_operation_log(created_at desc);
```

M1 必须保证这些信息能落库：

```text
业务对象：business_type、business_id、business_code、business_name
动作：action
操作人：operator_user_id、operator_user_name
requestId：request_id
时间：created_at
```

### 步骤 5：实现 TokenSessionService

M1 推荐先使用内存会话：

```text
ConcurrentHashMap<String, TokenSession>

token 过期时间默认 8 小时
logout 删除 token

```

接口建议：

```java

```

说明：

```text

```

### 步骤 6：实现 AuthService

登录流程：

```text
1. 根据 username 查询 sys_user。
2. 用户不存在，返回 code=40101，message=账号或密码错误。
3. deleted_flag=1 或 status != active，返回 code=40101，message=账号或密码错误。
4. 使用 BCryptPasswordEncoder 校验 password 和 password_hash。
5. 密码错误，返回 code=40101，message=账号或密码错误。
6. 组装 CurrentUser(userId, username, displayName, allPermissions)。
7. 调用 TokenSessionService.createSession 生成 token。
8. 返回 LoginVO。
9. 写入登录成功操作日志。
```

退出流程：

```text
1. 从 Authorization Header 解析 token。
2. 调用 TokenSessionService.invalidate。
3. 写入登出操作日志。
4. 返回 success。
```

profile 流程：

```text
1. 从 CurrentUserContext 获取当前用户。
2. 为空则返回未登录。
3. 转成 CurrentUserVO。
```

### 步骤 7：改造 SimpleTokenAuthenticationFilter

当前 filter 的问题：

```text
只校验固定 dev-token。
写入假的 CurrentUser(1L, "dev", "工程部用户", true)。
无法代表真实登录用户。
```

M1 改造目标：

```text
1. public path 继续放行。
2. app.security.enabled=false 时可放行，但 M1 验证必须开启 true。
3. app.security.enabled=true 时，从 Authorization 解析 Bearer token。
4. token 缺失、格式错误、已失效，返回未登录。
5. token 有效时，从 TokenSessionService 取 CurrentUser。
6. 写入 CurrentUserContext。
7. 写入 Spring SecurityContext。
8. finally 中清理 CurrentUserContext 和 SecurityContext。
```

public path 至少包含：

```text
/api/v1/health/**
/api/v1/auth/login
/swagger-ui.html
/swagger-ui/**
/v3/api-docs/**
```

注意：

```text
GET /api/v1/auth/profile 和 POST /api/v1/auth/logout 不应放行。
它们必须依赖 token。
```

## 11. 常见问题与处理

### 11.1 未登录接口返回 403，不是 401

可能原因：

```text
Spring Security 没有配置 AuthenticationEntryPoint。
filter 抛出的异常被 Security 默认处理。
```

处理：

```text
在 SecurityConfig 中配置 authenticationEntryPoint，统一写 ResponseVO。
```

### 11.2 不带 token 也能访问业务接口

可能原因：

```text
APP_SECURITY_ENABLED=false。
SecurityConfig 放行规则过宽。
SimpleTokenAuthenticationFilter 在安全关闭时直接放行。
```

处理：

```text
M1 验证时启动参数显式设置 APP_SECURITY_ENABLED=true。
检查 /api/v1/operation-logs 不在 permitAll 中。
```

### 11.3 profile 里 allPermissions=false

可能原因：

```text
sys_user 种子数据没有把 all_permissions 设置为 true。
AuthService 没有映射 allPermissions 字段。
登录账号不是工程部两位正式用户。
```

处理：

```text
检查 sys_user。
检查 SysUser entity 字段映射。
检查 AuthService 组装 CurrentUser 的逻辑。
```

### 11.4 操作日志 operator 为空

可能原因：

```text
OperationLogService 没有从 CurrentUserContext 取当前用户。
SimpleTokenAuthenticationFilter 没有 set CurrentUserContext。
OperationLogService 在异步线程执行，ThreadLocal 丢失。
测试接口没有带 Authorization。
```

处理：

```text
M1 不建议异步写日志。
先保证同步请求线程内 CurrentUserContext 可用。
```

### 11.5 日志 requestId 和 Apifox 不一致

可能原因：

```text
Apifox 没有传 X-Request-Id。
OperationLogService 自己重新生成了 requestId。
没有使用 RequestIdUtil.getRequestId(request)。
```

处理：

```text
写日志统一使用 RequestIdUtil.getRequestId(request)。
Apifox 测试写日志接口显式传 X-Request-Id。
```

### 11.6 Product freeze 仍然允许 query 参数 operator 伪造操作人

问题：

```text
这会破坏“是谁操作”的可信度。
```

处理：

```text
M1 改造后，operator 必须来自 CurrentUserContext。
query 参数 operator 应删除或忽略。
reason 可以继续来自 query 或 body。
```
