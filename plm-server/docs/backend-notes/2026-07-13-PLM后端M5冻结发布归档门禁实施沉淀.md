## 1. 任务理解

M5 的目标是把 Product 发布从“单纯修改 `status=released`”升级为“资料齐备、节点允许、门禁确认后才能发布”的受控动作。

核心原则：

```text
发布不是改状态。
发布前必须检查 BOM、工艺、必要文件、时间轴节点和门禁确认状态。
资料不足时必须失败，并返回可读的缺失项清单。
资料齐备后才允许 Product.status 进入 released。
归档后 Product.status 进入 archived，但文件中心仍可查看历史文件。
发布、归档、废弃等关键动作必须写 plm_operation_log。
```

本次仍然坚持 PLM 七个核心对象原则：

```text
projectId = productId
BOM 是 Product 下的版本化资料，不新增 BOM 根对象。
工艺路线是 Process 的 routing/operation 记录，不新增 Routing 根对象。
文件是 plm_attachment 元数据，不新增 FileVersion 根对象。
发布对象是 Product，不新增 Project 根对象。
```

## 3. 所属 PLM 业务链路

M5 属于新产品线和新型号线共用的发布门禁链路。

新产品线：

```text
Product 立项
  -> 设计确认
  -> 开模试模
  -> 样品与工艺
  -> 小批与 MX 验证
  -> 投产决策节点确认
  -> 发布门禁校验
  -> Product.status=released
  -> 历史追溯 / 归档
```

新型号线：

```text
Product 子版本扩展
  -> 差异设计
  -> 模具判断
  -> 差异验证
  -> 小批与 MX 验证
  -> 冻结发布节点确认
  -> 发布门禁校验
  -> Product.status=released
  -> 历史追溯 / 归档
```

## 5. 涉及数据对象、状态和 API

### 5.1 核心对象归属

| 能力 | 归属对象 | 说明 |
| --- | --- | --- |
| 项目冻结 | Product | `projectId` 即 `product_id`，冻结写 `lock_status=frozen` |
| 项目发布 | Product | 发布成功写 `status=released`、`released_at`、`released_by` |
| 项目归档 | Product | 归档成功写 `status=archived`，历史附件保留可查 |
| 项目废弃 | Product | M5 建议作为归档语义扩展，写 `status=archived` + `lock_status=abandoned` 或 `abandon_reason` |
| BOM 门禁 | Product 扩展资料 | 查询 `plm_product_bom` |
| 工艺门禁 | Process | 查询 `plm_process` 中 `process_type=routing` |
| 文件门禁 | plm_attachment | 查询 `owner_object_type=PRODUCT`、`owner_object_id=projectId` |
| 时间轴门禁 | Product 当前节点字段 | `current_step_no`、`timeline_current_confirmed`、`timeline_confirmed_node_key` |

### 5.3 状态口径

Product 标准状态机仍采用：

```text
draft -> developing -> reviewing -> released -> archived
```

M5 动作建议：

| 动作 | 前置状态 | 成功后 |
| --- | --- | --- |
| freeze | 非 `released/archived`，且非 abandoned | `lock_status=frozen`，`status` 不强制改变 |
| publish | `reviewing`，资料门禁通过 | `status=released` |
| archive | `released` 或业务确认可归档状态 | `status=archived` |
| abandon | 非 `released/archived` | `status=archived`，并记录废弃原因；如后续新增 `abandoned` 状态需先更新状态机文档 |

说明：用户提出“项目不能处于 archived 或 abandoned”。当前 `ProductStatusConstants` 未定义 `abandoned`，为了不擅自扩展 Product 状态机，M5 文档建议先用 `lock_status=abandoned` 或新增 `abandoned_flag/abandoned_reason` 表达废弃语义；若业务确认要新增 `Product.status=abandoned`，必须同步更新 `05-数据模型与编码规范.md`、`14-API接口定义文档.md` 和状态机测试。

## 6. 发布门禁规则

发布前校验必须一次性返回缺失项清单，不允许遇到第一个缺失项就中断。

最小门禁：

```text
1. Product 存在，且 deleted_flag=0。
2. Product.status 必须是 reviewing。
3. Product.status 不能是 archived。
4. Product.lock_status 不能是 abandoned。
5. 当前时间轴必须到允许发布节点：
   - product_line: PRODUCT_LINE_PRODUCTION_DECISION
   - model_variant: MODEL_VARIANT_FREEZE_RELEASE
6. 当前时间轴节点必须已确认：
   - timeline_current_confirmed=true
   - timeline_confirmed_node_key=当前节点 nodeCode
7. BOM 至少存在一个 status in ('frozen','released') 的版本。
8. 工艺路线至少存在一个 process_type='routing' 且 status in ('locked','frozen') 的版本。
9. 必要文件至少满足：
   - drawing 至少 1 个
   - sop 或 sip 至少 1 个
   - testing 至少 1 个
10. 发布成功写 plm_operation_log: PRODUCT_PUBLISH。
```

建议缺失项编码：

| code | message |
| --- | --- |
| `PRODUCT_STATUS_NOT_REVIEWING` | 产品当前状态不是 reviewing，不能发布 |
| `PRODUCT_ARCHIVED` | 产品已归档，不能发布 |
| `PRODUCT_ABANDONED` | 项目已废弃，不能发布 |
| `TIMELINE_NODE_NOT_ALLOWED` | 当前时间轴未到发布或投产决策节点 |
| `TIMELINE_NODE_NOT_CONFIRMED` | 当前门禁节点尚未确认 |
| `BOM_NOT_FROZEN` | 缺少已冻结或已发布 BOM |
| `PROCESS_ROUTE_NOT_LOCKED` | 缺少已锁定或已冻结工艺路线 |
| `DRAWING_FILE_MISSING` | 缺少图纸文件 |
| `SOP_OR_SIP_FILE_MISSING` | 缺少 SOP 或 SIP 文件 |
| `TESTING_FILE_MISSING` | 缺少测试资料 |

```sql

    add column if not exists abandoned_at timestamp,
    add column if not exists abandoned_by varchar(64),
    add column if not exists abandon_reason text,
    add column if not exists archived_at timestamp,
    add column if not exists archived_by varchar(64),
    add column if not exists archive_reason text;
```

```text

```

完整草稿：

```sql

    add column if not exists archived_at timestamp,
    add column if not exists archived_by varchar(64),
    add column if not exists archive_reason text,
    add column if not exists abandoned_at timestamp,
    add column if not exists abandoned_by varchar(64),
```

### 10.5 门禁校验实现

文件：`src/main/java/com/yuewei/plm/service/impl/ProductReleaseGateValidatorImpl.java`

```java
package com.yuewei.plm.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.yuewei.plm.common.constant.ProductStatusConstants;
import com.yuewei.plm.module.attachment.entity.Attachment;
import com.yuewei.plm.module.attachment.repository.AttachmentRepository;
import com.yuewei.plm.module.bom.entity.ProductBom;
import com.yuewei.plm.module.bom.repository.ProductBomRepository;
import com.yuewei.plm.module.process.entity.ProcessEntity;
import com.yuewei.plm.module.process.repository.ProcessRepository;
import com.yuewei.plm.module.project.constant.TimelineNodeConstants;
import com.yuewei.plm.module.project.constant.TimelineNodeConstants.TimelineNodeDefinition;
import com.yuewei.plm.module.project.service.TimelineDefinitionProvider;
import com.yuewei.plm.repository.entity.Product;
import com.yuewei.plm.service.ProductReleaseGateValidator;
import com.yuewei.plm.service.vo.ProductReleaseGateCheckVO;
import com.yuewei.plm.service.vo.ProductReleaseGateMissingItemVO;
import java.util.ArrayList;
import java.util.List;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;

@Component
@RequiredArgsConstructor
public class ProductReleaseGateValidatorImpl implements ProductReleaseGateValidator {

    private static final String OWNER_OBJECT_TYPE_PRODUCT = "PRODUCT";
    private static final String PROCESS_TYPE_ROUTING = "routing";

    private final ProductBomRepository productBomRepository;
    private final ProcessRepository processRepository;
    private final AttachmentRepository attachmentRepository;
    private final TimelineDefinitionProvider timelineDefinitionProvider;

    @Override
    public ProductReleaseGateCheckVO check(Product product) {
        List<ProductReleaseGateMissingItemVO> missingItems = new ArrayList<>();
        String currentNodeKey = resolveCurrentNodeKey(product);
        boolean currentNodeConfirmed = Boolean.TRUE.equals(product.getTimelineCurrentConfirmed())
            && currentNodeKey.equals(product.getTimelineConfirmedNodeKey());

        if (!ProductStatusConstants.REVIEWING.equals(product.getStatus())) {
            missingItems.add(missing("PRODUCT_STATUS_NOT_REVIEWING", "产品当前状态不是 reviewing，不能发布"));
        }
        if (ProductStatusConstants.ARCHIVED.equals(product.getStatus())) {
            missingItems.add(missing("PRODUCT_ARCHIVED", "产品已归档，不能发布"));
        }
        if ("abandoned".equals(product.getLockStatus())) {
            missingItems.add(missing("PRODUCT_ABANDONED", "项目已废弃，不能发布"));
        }
        if (!isAllowedPublishNode(product.getProductType(), currentNodeKey)) {
            missingItems.add(missing("TIMELINE_NODE_NOT_ALLOWED", "当前时间轴未到发布或投产决策节点"));
        }
        if (!currentNodeConfirmed) {
            missingItems.add(missing("TIMELINE_NODE_NOT_CONFIRMED", "当前门禁节点尚未确认"));
        }

        int frozenBomCount = countFrozenBom(product.getProductId());
        int lockedProcessRouteCount = countLockedProcessRoute(product.getProductId());
        int drawingFileCount = countAttachment(product.getProductId(), List.of("drawing"));
        int sopFileCount = countAttachment(product.getProductId(), List.of("sop"));
        int sipFileCount = countAttachment(product.getProductId(), List.of("sip"));
        int testingFileCount = countAttachment(product.getProductId(), List.of("testing"));

        if (frozenBomCount <= 0) {
            missingItems.add(missing("BOM_NOT_FROZEN", "缺少已冻结或已发布 BOM"));
        }
        if (lockedProcessRouteCount <= 0) {
            missingItems.add(missing("PROCESS_ROUTE_NOT_LOCKED", "缺少已锁定或已冻结工艺路线"));
        }
        if (drawingFileCount <= 0) {
            missingItems.add(missing("DRAWING_FILE_MISSING", "缺少图纸文件"));
        }
        if (sopFileCount + sipFileCount <= 0) {
            missingItems.add(missing("SOP_OR_SIP_FILE_MISSING", "缺少 SOP 或 SIP 文件"));
        }
        if (testingFileCount <= 0) {
            missingItems.add(missing("TESTING_FILE_MISSING", "缺少测试资料"));
        }

        return ProductReleaseGateCheckVO.builder()
            .projectId(product.getProductId())
            .productId(product.getProductId())
            .passed(missingItems.isEmpty())
            .currentStatus(product.getStatus())
            .currentNodeKey(currentNodeKey)
            .currentNodeConfirmed(currentNodeConfirmed)
            .frozenBomCount(frozenBomCount)
            .lockedProcessRouteCount(lockedProcessRouteCount)
            .drawingFileCount(drawingFileCount)
            .sopFileCount(sopFileCount)
            .sipFileCount(sipFileCount)
            .testingFileCount(testingFileCount)
            .missingItems(missingItems)
            .build();
    }

    private String resolveCurrentNodeKey(Product product) {
        List<TimelineNodeDefinition> definitions = timelineDefinitionProvider.getDefinitions(product.getProductType());
        int stepNo = product.getCurrentStepNo() == null ? 1 : product.getCurrentStepNo();
        int normalized = Math.min(Math.max(stepNo, 1), definitions.size());
        return definitions.get(normalized - 1).nodeCode();
    }

    private boolean isAllowedPublishNode(String productType, String currentNodeKey) {
        if (TimelineNodeConstants.PRODUCT_TYPE_PRODUCT_LINE.equals(productType)) {
            return "PRODUCT_LINE_PRODUCTION_DECISION".equals(currentNodeKey);
        }
        if (TimelineNodeConstants.PRODUCT_TYPE_MODEL_VARIANT.equals(productType)) {
            return "MODEL_VARIANT_FREEZE_RELEASE".equals(currentNodeKey);
        }
        return false;
    }

    private int countFrozenBom(Long productId) {
        Long count = productBomRepository.selectCount(new LambdaQueryWrapper<ProductBom>()
            .eq(ProductBom::getProductId, productId)
            .eq(ProductBom::getDeletedFlag, 0)
            .in(ProductBom::getStatus, List.of("frozen", "released")));
        return count.intValue();
    }

    private int countLockedProcessRoute(Long productId) {
        Long count = processRepository.selectCount(new LambdaQueryWrapper<ProcessEntity>()
            .eq(ProcessEntity::getProductId, productId)
            .eq(ProcessEntity::getProcessType, PROCESS_TYPE_ROUTING)
            .eq(ProcessEntity::getDeletedFlag, 0)
            .in(ProcessEntity::getStatus, List.of("locked", "frozen")));
        return count.intValue();
    }

    private int countAttachment(Long productId, List<String> categories) {
        Long count = attachmentRepository.selectCount(new LambdaQueryWrapper<Attachment>()
            .eq(Attachment::getOwnerObjectType, OWNER_OBJECT_TYPE_PRODUCT)
            .eq(Attachment::getOwnerObjectId, productId)
            .eq(Attachment::getDeletedFlag, 0)
            .in(Attachment::getFileCategory, categories));
        return count.intValue();
    }

    private ProductReleaseGateMissingItemVO missing(String code, String message) {
        return ProductReleaseGateMissingItemVO.builder()
            .code(code)
            .message(message)
            .build();
    }
}
```

## 11. 代码逻辑说明

### 11.1 freeze

```text
1. 校验 Product 存在。
2. 校验当前用户来自 CurrentUserContext，不能由前端传 operator。
3. archived/released 状态下不允许重复冻结。
4. 写 Product.frozen_at、frozen_by、freeze_reason。
5. 写 Product.lock_status=frozen、lock_reason、lock_operator_user_id、lock_operator_user_name。
6. 写 operation_log: PRODUCT_FREEZE。
7. 返回 ProductVO。
```

### 11.2 checkReleaseGate

```text
1. 查询 Product。
2. 根据 product_type 和 current_step_no 计算当前时间轴节点。
3. 校验状态是否 reviewing。
4. 校验当前节点是否允许发布。
5. 校验当前节点是否已确认。
6. 统计 frozen/released BOM 数量。
7. 统计 locked/frozen 工艺路线数量。
8. 统计 drawing、sop、sip、testing 附件数量。
9. 汇总 missingItems。
10. 返回 passed=true/false。
```

### 11.3 publish

```text
1. 查询 Product。
2. 执行 checkReleaseGate。
3. 若 missingItems 非空，抛出 RELEASE_GATE_NOT_PASSED，data 返回缺失项清单。
4. 门禁通过后更新 Product.status=released。
5. 写 released_at、released_by、updated_at、updated_by。
6. 写 operation_log: PRODUCT_PUBLISH。
7. 返回 ProductVO。
```

### 11.4 archive

```text
1. 查询 Product。
2. 校验状态机允许进入 archived。
3. 更新 Product.status=archived。
4. 写 archived_at、archived_by、archive_reason。
5. 不删除附件、不删除 BOM、不删除 Process。
6. 写 operation_log: PRODUCT_ARCHIVE。
7. 文件中心仍按 owner_object_id 查询历史文件。
```

### 11.5 abandon

```text
1. 查询 Product。
2. released 不允许 abandon，避免绕过已发布版本追溯。
3. archived 不允许重复 abandon。
4. 更新 Product.status=archived。
5. 写 lock_status=abandoned。
6. 写 abandoned_at、abandoned_by、abandon_reason。
7. 写 operation_log: PRODUCT_ABANDON。
8. 后续如业务确认新增 Product.status=abandoned，再同步升级状态机和接口文档。
```

## 15. 后续维护建议

1. 发布门禁规则集中放在 `ProductReleaseGateValidatorImpl`，不要散落在 Controller 或多个 Service 中。
2. 文件门禁的必需分类建议后续改为字典或配置，例如不同产品类型可配置不同必需文件。
3. 当前 SOP/SIP 规则采用“二选一”，若业务要求 SOP 和 SIP 都必需，只改 Validator 和测试即可。
4. `abandoned` 暂不进入 Product 标准状态机，避免破坏既有 `draft -> developing -> reviewing -> released -> archived` 口径。
5. 如业务确认必须有独立 abandoned 状态，先更新文档，再改 `ProductStatusConstants.TRANSITIONS` 和 API 文档。
6. 归档不删除附件、不删除本地文件、不物理删除 BOM/Process；归档只是 Product 生命周期状态变化。
7. 已发布版本不允许直接编辑，后续修改应走变更流程或创建新版本。
8. 门禁失败是业务失败，必须返回错误码和缺失项清单，不能吞成空对象或空数组。
9. 预检接口无缺失时 `passed=true`；有缺失时 `passed=false` 但 `code=0`，因为预检动作本身成功。
10. 发布接口有缺失时必须返回错误码，不能返回 `code=0`。
11. 当前 `ProductController.publish` 不能继续信任前端传入 `operator`，应统一从 `CurrentUserContext` 获取当前用户。
12. 所有关键动作必须写 `plm_operation_log`，尤其是 `PRODUCT_PUBLISH` 和 `PRODUCT_ARCHIVE`。

## 16. 最终验收清单

| 验收项 | 通过标准 |
| --- | --- |
| 资料不足发布失败 | 返回 `40307`，含 `missingItems` |
| BOM 门禁 | 至少 1 个 `frozen/released` BOM |
| 工艺门禁 | 至少 1 条 `locked/frozen` routing |
| 图纸门禁 | 至少 1 个 `file_category=drawing` 附件 |
| SOP/SIP 门禁 | 至少 1 个 `file_category=sop` 或 `sip` 附件 |
| 测试资料门禁 | 至少 1 个 `file_category=testing` 附件 |
| 时间轴门禁 | 当前节点为发布节点且已确认 |
| 发布成功 | `Product.status=released`，写 `released_at/released_by` |
| 归档成功 | `Product.status=archived` |
| 归档后文件可查 | 文件中心仍能查历史文件 |
| 归档后文件可下载 | 下载接口仍返回文件流 |
| 发布日志 | `plm_operation_log.action=PRODUCT_PUBLISH` |
| 归档日志 | `plm_operation_log.action=PRODUCT_ARCHIVE` |
| 废弃日志 | `plm_operation_log.action=PRODUCT_ABANDON` |
