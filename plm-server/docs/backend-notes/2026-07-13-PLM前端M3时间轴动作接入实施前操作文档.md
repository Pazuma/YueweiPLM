### 3.6 不确定点

正式开发前建议确认：

```text
1. M3 按钮放在“当前节点”区域，还是“项目流程”时间轴节点卡片上。
2. returnToPrevious 默认是否为 true；建议页面提供“退回当前节点修改 / 退回上一节点”二选一。
3. confirm 和 advance 是否允许连续操作；建议确认后仍让用户手动点推进，避免误推进。
4. 是否需要展示最近操作人、最近操作时间、最近退回原因；建议展示，便于工程人员判断状态。
5. 是否需要前端隐藏非当前节点动作按钮；建议隐藏或禁用，并显示原因。
```

### 3.7 实施方案

推荐方案：先接 API 层，再接详情页操作区。

```text
第一步：在 project.ts 中把 M3 三个占位函数改成真实 POST 请求。
第二步：补充 TimelineActionResultVO 前端类型。
第三步：在 ProjectCenterView.vue 中增加当前节点操作状态、按钮、确认弹窗、退回原因弹窗。
第四步：动作成功后重新调用 getProjectTimeline(projectId)，刷新当前节点和确认状态。
第五步：动作失败时直接展示后端业务错误，不吞掉错误。
第六步：完成前端手工测试和 type-check / build。
```

### 3.8 风险点

```text
M3 动作会真实修改数据库，不能拿正式项目随便测试。
advance 会改变 current_step_no 和 Product.status。
returnToPrevious=true 会把项目退回上一节点。
重复点击可能导致重复推进，前端必须加 loading 防重复提交。
后端已经校验只能操作 current 节点，但前端也要把非 current 节点按钮禁用。
return 必须填写 reason，不能传空字符串。
失败动作不能在前端伪装成成功。
```

### 5.1 前端 API 文件

文件：

```text
D:\Yuewei\git\YUEWEI\plm-web\src\api\modules\project.ts
```

当前状态：

```text
confirmTimelineNode()
advanceTimelineNode()
returnTimelineNode()
```

目前仍调用 `rejectUntestedM3Action()`，主动提示 M3 尚未完成前端接入。

正式开发时建议改为：

```ts
export interface TimelineActionResultVO {
  projectId: number
  productId: number
  action: 'confirm' | 'advance' | 'return'
  nodeKey: string
  beforeStepNo: number
  currentStepNo: number
  currentNodeKey: string
  currentNodeName: string
  currentConfirmed: boolean
  productStatus: string
  logId: number
}

export interface TimelineActionPayload {
  remark?: string
  reason?: string
  returnToPrevious?: boolean
}

export async function confirmTimelineNode(projectId: number, nodeKey: string, remark?: string): Promise<TimelineActionResultVO> {
  const response = await request.post(`/projects/${projectId}/timeline/${nodeKey}/confirm`, { remark })
  return unwrapResponse<TimelineActionResultVO>(response)
}

export async function advanceTimelineNode(projectId: number, nodeKey: string, remark?: string): Promise<TimelineActionResultVO> {
  const response = await request.post(`/projects/${projectId}/timeline/${nodeKey}/advance`, { remark })
  return unwrapResponse<TimelineActionResultVO>(response)
}

export async function returnTimelineNode(
  projectId: number,
  nodeKey: string,
  reason: string,
  returnToPrevious = true
): Promise<TimelineActionResultVO> {
  const response = await request.post(`/projects/${projectId}/timeline/${nodeKey}/return`, {
    reason,
    returnToPrevious
  })
  return unwrapResponse<TimelineActionResultVO>(response)
}
```

注意：上面是后续开发草稿，不是本次已落地代码。

## 6. 代码使用哪些技术以及理由

### 6.1 Vue 3 Composition API

理由：

```text
当前前端项目已经使用 Vue 3 Composition API。
ProjectCenterView.vue 已经大量使用 ref / computed / async function。
继续沿用现有写法，改动最小。
```

### 6.2 TypeScript

理由：

```text
M3 动作结果包含 currentStepNo、currentNodeKey、currentConfirmed、logId 等关键字段。
使用 TypeScript 明确定义 TimelineActionResultVO，可以减少字段拼错和响应误用。
```

### 6.3 Axios + 现有 request.ts

理由：

```text
M1/M2 已经通过 request.ts 统一处理 baseURL、Authorization token、错误拦截。
M3 必须复用同一入口，不能绕过 token 和统一错误处理。
```

### 6.4 Element Plus

理由：

```text
当前项目使用 Element Plus。
确认动作适合用 ElMessageBox.confirm。
退回动作适合用 ElMessageBox.prompt 或自定义 el-dialog 输入 reason。
结果提示适合用 ElMessage.success / ElMessage.error。
按钮 loading 可以直接使用 Element Plus 的 :loading。
```

### 6.5 后端 ResponseVO 解包

理由：

```text
后端统一返回 { code, message, data, requestId, timestamp }。
前端必须用 unwrapResponse<T>() 识别 code。
code 不为 0 时必须抛错或展示错误，不能返回空对象伪装成功。
```

## 7. 正式接入后的核心代码逻辑

### 7.1 页面打开详情

```text
用户打开项目详情
-> 调用 getProductPresentation(productId)
-> 调用 getProjectTimeline(productId)
-> 把 timeline.nodes 映射到 detailPresentation.timeline
-> 找到 status=current 的当前节点
-> 显示当前节点名称、确认状态、下一动作
```

### 7.2 确认当前节点

```text
用户点击“确认当前节点”
-> 前端确认弹窗
-> 调用 confirmTimelineNode(projectId, currentNode.nodeKey, remark)
-> 后端校验只能确认 current 节点
-> 成功后写 operation_log
-> 前端重新查询 timeline
-> 页面显示 currentConfirmed=true
```

合格表现：

```text
页面提示“节点已确认”
当前节点仍然不变
确认状态变为已确认
操作日志出现 TIMELINE_CONFIRM
```

### 7.3 推进下一节点

```text
用户点击“推进下一节点”
-> 前端确认弹窗提醒“会进入下一节点”
-> 调用 advanceTimelineNode(projectId, currentNode.nodeKey, remark)
-> 后端校验当前节点已确认
-> 后端 current_step_no + 1
-> 后端根据节点更新 Product.status
-> 成功后写 operation_log
-> 前端重新查询 timeline
-> 页面 current 节点变成下一节点，currentConfirmed=false
```

合格表现：

```text
页面提示“已推进到下一节点”
时间轴 current 高亮移动到下一节点
新当前节点显示未确认
操作日志出现 TIMELINE_ADVANCE
```

### 7.4 退回

```text
用户点击“退回”
-> 前端弹窗要求输入退回原因
-> 用户选择“退回当前节点修改”或“退回上一节点”
-> 调用 returnTimelineNode(projectId, currentNode.nodeKey, reason, returnToPrevious)
-> 后端校验 reason 必填
-> returnToPrevious=true 时退回上一节点
-> returnToPrevious=false 时只记录当前节点退回修改
-> 成功后写 operation_log
-> 前端重新查询 timeline
```

合格表现：

```text
没有原因时不能提交
成功后 currentConfirmed=false
页面能看到最近退回原因
操作日志出现 TIMELINE_RETURN
```

## 11. 维护注意事项

```text
1. 不要把 M3 与发布、冻结、归档混在一起接入；本次只接 confirm / advance / return。
2. 不要新增 Project 根对象；前端 projectId 继续等于后端 productId。
3. 不要在前端硬编码绕过后端状态机，所有动作以接口返回为准。
4. 不要在接口失败时返回空对象，必须展示错误。
5. return 必须保留 reason，后续排查项目为什么退回要依赖这个字段。
6. 动作成功后必须重新拉取 timeline，不能只靠前端本地改状态。
7. 按钮必须加 loading，避免重复点击导致重复推进。
8. 如果后续加多人并发操作，建议后端再补乐观锁或版本号校验。
9. 如果新环境 M2/M3 查询 500，优先检查 plm_product 是否包含 current_step_no 和 timeline_* 字段。
10. Product.status 的 released 仍应由正式发布接口处理，不应由 M3 advance 直接发布。
```
