# PLM 编码规则前端测试数据对齐与验收说明

> 日期：2026-07-23  
> 适用功能：钉钉新型号开模申请传入模具编码，PLM 自动解析、匹配或创建模具资料，并在新型号第一节点表单回显。

## 1. 本次新增文件

| 文件 | 用途 |
| --- | --- |
| `plm-server/src/test/resources/sql/dingtalk-mold-code-frontend-test-data.sql` | 前端联调数据脚本，补齐产品线、颜色、BOM、路线、投产颜色决策和一条已存在模具 |
| `plm-server/docs/backend-notes/2026-07-23-PLM编码规则前端测试数据对齐与验收说明.md` | 本说明文档 |

这份 SQL 不是 Flyway 迁移，不会随正式启动自动执行；只在本地联调、验收库或演示库按需执行。

## 2. 数据对齐内容

脚本会补齐下面这组固定测试口径：

| 数据 | 值 |
| --- | --- |
| 产品线编码 | `FA` |
| 产品线名称 | `幻影 Fantasia Case` |
| 产品状态 | `released` |
| 手机型号 | `Xiaomi Redmi A7 Pro` |
| 手机型号编码 | `1291` |
| 颜色 | `01 黑色`、`02 透明色` |
| 最终工序编码 | `4030` |
| 预置已存在模具 | `MFA101291`，写入 `plm_inventory.inventory_type = tooling` |
| 预期自动创建模具 | `MFA201291`，接口接入时如不存在会自动创建 `tooling/draft` |

脚本执行完成后会返回 `parent_product_id`。后续调用钉钉接入接口时，把这个 ID 填到 `parentProductId`。

## 4. 调用钉钉接入接口

后端接口：

```text
POST http://localhost:8080/api/v1/integrations/dingtalk/model-variant-approvals
```

请求体示例，把 `parentProductId` 的 `123` 替换为 SQL 返回的 ID。重复测试时建议改一个新的 `dingTalkApprovalNo`，否则会命中幂等记录，直接返回上一次项目。

```json
{
  "dingTalkApprovalNo": "DT-MOLD-20260723-001",
  "approvalStatus": "approved",
  "parentProductId": 123,
  "model": "Xiaomi Redmi A7 Pro",
  "tipo": "幻影 Fantasia Case",
  "priority": "general",
  "manufacturingLocation": "国内",
  "moldMarking": "Redmi A7 Pro",
  "productSpecificCode": "FA",
  "phoneModelCode": "1291",
  "materialCodes": ["10", "20"],
  "moldCodes": "MFA101291\nMFA201291",
  "createdBy": "frontend-test"
}
```

预期响应里有 `projectId` 和 `moldMatches`：

```text
MFA101291 -> linked_existing
MFA201291 -> created_draft
```

如果 `MFA201291` 之前已经被你测试创建过，再次请求时它也会变成 `linked_existing`。这是正常的，因为系统按 `plm_inventory.inventory_code` 去重。

## 5. 前端页面验收

1. 启动后端和前端。
2. 打开前端，默认是 `http://localhost:5173`。
3. 登录后进入项目中心。
4. 找到刚才接口返回的 `projectId` 对应的新型号项目。
5. 打开第一节点“新型号项目信息完善表”。

页面预期：

- 钉钉审批单号显示为请求里的 `DT-MOLD-20260723-001`。
- 产品特定编码显示 `FA`。
- 手机型号编码显示 `1291`。
- 材质编码显示 `10,20`。
- 模具编码显示 `MFA101291` 和 `MFA201291`。
- 模具匹配结果里能看到一条 `linked_existing`，一条 `created_draft`。
- 正式投产颜色默认带出 `01 黑色`、`02 透明色`，并默认选中。

## 6. 验收后可查数据库

```sql
select inventory_code, inventory_type, status, product_id, specification
from plm_inventory
where inventory_code in ('MFA101291', 'MFA201291')
  and deleted_flag = 0
order by inventory_code;
```

预期：

- `MFA101291` 是脚本预置的 `tooling/available`。
- `MFA201291` 是接口自动创建的 `tooling/draft`。

## 7. 后续维护建议

- 这份脚本只服务联调验收，不要把它改成正式 Flyway migration。
- 如果颜色编码中心已有正式颜色数据，脚本会复用 `code_type=color`、`code_value=01/02`，不会重复造颜色编码。
- 如果后续业务确认材质编码字典，需要把 `10=TPU`、`20=PC` 也沉淀到编码中心，再让前端/API 从字典选择。
- 如果要每次都验证 `created_draft`，请使用新的审批号和新的手机型号编码，或者人工清理上一轮接口自动创建的测试模具。
