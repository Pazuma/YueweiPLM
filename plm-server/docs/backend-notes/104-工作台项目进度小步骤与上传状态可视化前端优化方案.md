# 104-工作台项目进度小步骤与上传状态可视化前端优化方案

## 0. 本次范围声明

本次只生成方案沉淀文档，不修改任何实际业务代码。

本次只涉及前端展示层，不涉及后端 Controller、Service、数据库、接口、权限逻辑和状态机逻辑。方案中的代码均为后续实施草稿，用于评审和二次开发。

## 1. 任务理解

当前工作台“项目进度”弹窗中，用户能看到大节点状态，例如“已完成、进行中、待开始”，也能看到当前大节点包含的小节点和“需上传 / 审批”标签。

但从用户视角仍有三个问题：

1. 不清楚当前项目实际推进到了哪一个小节点。
2. 不清楚刚刚确认的是哪一步。
3. 不清楚哪个小节点已经上传了文件、哪个还需要上传。

目标是在不改后端的前提下，通过前端已有时间轴数据和附件数量，增强弹窗的信息表达：

- 当前小节点明确高亮。
- 已完成 / 已确认的小节点用绿色区分。
- 已上传文件的小节点也用绿色区分。
- 需要上传但未上传的小节点用橙色提示。
- 用户能在当前大节点内看清楚“走到哪一步、哪些资料已经有、下一步要干什么”。

## 2. 所属 PLM 业务链路

- 业务链路：新产品线 / 新型号线项目推进。
- 页面入口：工作台 → 进行中的产品 / 待办 → 项目进度弹窗。
- 业务对象：Product。
- 资料对象：Product 下的附件资料，仍通过后端 `plm_attachment` 绑定时间轴节点。
- 本次只优化前端状态展示，不新增根对象，不新增文件业务对象。

## 6. 不确定点

1. 当前 `DashboardChildStep` 模板中的小节点主要是前端模板，不一定每个小节点都有独立后端 `nodeKey`。
2. 如果一个大节点内包含多个小节点，而后端当前只返回一个代表节点的 `documentCount`，前端只能做到“当前大节点内资料已上传”的视觉提示；若要精确到每个小节点，需要后端后续返回小步骤级附件计数。
3. 用户截图中的“制作模具 / 测试模具”已有“需上传”标签，但是否已上传只能从当前可用 `documentCount` 粗略判断。
4. 本方案严格按“只涉及前端”处理，因此不设计后端字段扩展；后续如要求逐小节点精确展示附件数，需要另开后端方案。

## 7. 实施方案

### 7.1 总体思路

不改变后端数据结构，只在 `DashboardView.vue` 中增加前端派生展示模型：

```ts
interface DashboardChildStepView extends DashboardChildStep {
  nodeKey: string
  isCurrent: boolean
  isConfirmed: boolean
  hasUploaded: boolean
  uploadCount: number
  visualStatus: 'confirmed' | 'current' | 'uploaded' | 'missing-upload' | 'pending'
}
```

将原来的：

```vue
<article
  v-for="step in selectedProgressNode.childSteps"
  :key="step.stepNo"
  class="project-progress-child-step"
>
```

改为使用派生后的：

```vue
<article
  v-for="step in selectedProgressChildSteps"
  :key="step.stepNo"
  class="project-progress-child-step"
  :class="`is-${step.visualStatus}`"
>
```

### 7.2 当前小节点识别

建议新增计算属性：

```ts
const currentProgressStepNo = computed(() => {
  return activeProgressTimeline.value?.currentStepNo
    || activeProgressProject.value?.currentStepNo
    || 1
})
```

用于判断当前走到哪一步。

### 7.3 小节点附件状态识别

由于本次不改后端，小节点附件状态先基于当前大节点对应的 `documentCount` 做可视化归因：

```ts
function getStepUploadCount(step: DashboardChildStep, node: DashboardProgressNode) {
  if (!step.requireUpload) return 0
  if (step.stepNo !== currentProgressStepNo.value) return 0
  return Number(node.documentCount || 0)
}
```

如果后续后端返回小步骤级 `documentCount`，可替换为：

```ts
function getStepUploadCount(step: DashboardChildStep) {
  return step.documentCount || 0
}
```

### 7.4 小节点展示模型

建议新增：

```ts
type ChildStepVisualStatus = 'confirmed' | 'current' | 'uploaded' | 'missing-upload' | 'pending'

interface DashboardChildStepView extends DashboardChildStep {
  uploadCount: number
  isCurrent: boolean
  isConfirmed: boolean
  hasUploaded: boolean
  visualStatus: ChildStepVisualStatus
}

const selectedProgressChildSteps = computed<DashboardChildStepView[]>(() => {
  const node = selectedProgressNode.value
  if (!node) return []
  return node.childSteps.map((step) => {
    const uploadCount = getStepUploadCount(step, node)
    const isCurrent = step.stepNo === currentProgressStepNo.value
    const isConfirmed = step.stepNo < currentProgressStepNo.value || Boolean(node.confirmed && isCurrent)
    const hasUploaded = step.requireUpload ? uploadCount > 0 : false
    const visualStatus: ChildStepVisualStatus = isConfirmed
      ? 'confirmed'
      : isCurrent
        ? (step.requireUpload && !hasUploaded ? 'missing-upload' : 'current')
        : hasUploaded
          ? 'uploaded'
          : 'pending'

    return {
      ...step,
      uploadCount,
      isCurrent,
      isConfirmed,
      hasUploaded,
      visualStatus
    }
  })
})
```

### 7.5 标签展示规则

将原来的：

```vue
<el-tag v-if="step.requireUpload" size="small" type="warning" effect="light">需上传</el-tag>
<el-tag v-if="step.requireApproval" size="small" type="info" effect="light">审批</el-tag>
```

建议改为：

```vue
<el-tag v-if="step.isCurrent" size="small" type="primary" effect="light">当前步骤</el-tag>
<el-tag v-if="step.isConfirmed" size="small" type="success" effect="light">已确认</el-tag>
<el-tag v-if="step.requireUpload && step.hasUploaded" size="small" type="success" effect="light">
  已上传 {{ step.uploadCount }} 个
</el-tag>
<el-tag v-else-if="step.requireUpload" size="small" type="warning" effect="light">待上传</el-tag>
<el-tag v-if="step.requireApproval" size="small" type="info" effect="light">审批</el-tag>
```

### 7.6 右侧摘要增加“当前小节点”

建议在 `project-progress-info-grid` 增加或替换一项：

```vue
<div>
  <span class="subtle-text">当前小节点</span>
  <strong>
    第 {{ currentProgressStepNo }} 步：{{ activeProgressTimeline?.currentStepName || selectedProgressNode.title }}
  </strong>
</div>
```

目标：用户打开弹窗后，不需要猜当前选中大节点里具体走到第几步。

### 7.7 上传弹窗选项增强

上传资料弹窗中的“资料归属步骤”建议展示状态后缀：

```vue
<option

  :value="option.nodeKey"

  {{ option.title }}（{{ option.documentCount || 0 }} 个附件）

</option>
```

## 8. 视觉目标效果

### 8.1 左侧大节点

- 已完成大节点：浅绿色背景。

| 当前步骤 | `#eff6ff` | `#60a5fa` | 蓝色“当前步骤” |
| 当前待上传 | `#fff7ed` | `#fdba74` | 橙色“待上传” |
| 待开始 | `#f8fafc` | `#e5e7eb` | 灰色“待开始” |

### 8.3 用户能直接看到的信息

打开项目进度弹窗后，用户应立即看见：

1. 当前项目处于哪个大节点。
2. 当前大节点内当前小节点是第几步。
3. 哪些小节点已经确认。
4. 哪些小节点已经上传文件。
5. 哪些小节点还缺上传。
6. 点击上传资料时，能选择对应步骤，不再靠记忆判断。

## 11. 风险点

1. 只靠前端现有 `documentCount` 无法完全区分同一大节点内每一个小步骤各自上传了几个文件。
2. 如果用户要求“制作模具”和“测试模具”分别显示各自文件数量，后端需要返回小步骤级附件统计，本次前端-only 方案无法完全覆盖。
3. 色彩提示不能替代后端门禁校验，真正能否进入下一个大节点仍以后端校验为准。
4. 弹窗内标签增多后，需要控制列宽和换行，避免 1366 宽屏下按钮区被挤压。
