## 1. 实施目标

让编码规则在系统里真正可用：

- 统一生成 `M + 产品特定编码 + 材质编码 + 手机型号编码` 的模具编码。
- 统一生成 `N + 产品特定编码 + 工序编码 + 手机型号编码 + 颜色编码` 的成品/半成品/工序状态编码。
- 钉钉新型号开模申请传入模具编码时，系统自动解析、校验、匹配已有模具。
- 未匹配到已有模具时，自动创建 `tooling/draft` 的库存资料，作为“待开模模具”。
- 第一节点表单回显钉钉传入的编码字段和模具匹配结果。

## 3. 核心代码

### 3.1 统一编码生成

```java
public String generateMoldCode(String productSpecificCode, String materialCode, String phoneModelCode) {
    return "M" + product + material + phone;
}

public String generateProductStateCode(String productSpecificCode, String operationCode,
                                       String phoneModelCode, String colorCode) {
    return "N" + product + operation + phone + color;
}
```

示例：

```text
M + FA + 10 + 1291 = MFA101291
N + FA + 4030 + 1291 + 01 = NFA4030129101
```

### 3.2 钉钉模具编码解析

```java
MFA101291 = M / FA / 10 / 1291
```

解析时会优先使用钉钉传入的：

- `productSpecificCode`
- `materialCodes`
- `phoneModelCode`

如果这些字段存在，系统会用它们反向生成预期编码，并与钉钉传入的 `moldCodes` 对比。不一致时直接返回业务校验错误，避免错误模具进入正式资料。

### 3.3 模具编码匹配和创建

```java
select inventory_id
from plm_inventory
where inventory_code = ?
  and deleted_flag = 0
```

- 查到：返回 `linked_existing`，直接关联已有模具资料。
- 查不到：插入 `plm_inventory`，类型为 `tooling`，状态为 `draft`。

创建字段口径：

```text
inventory_code = 模具编码
inventory_type = tooling
product_id = 新型号项目 Product ID
status = draft
stock_uom = 套
remark = 来源钉钉审批单号
```

## 4. 业务逻辑

钉钉新型号开模申请进入 PLM 后，流程如下：

1. 钉钉提交新型号开模申请。
2. PLM 接收 `dingTalkApprovalNo`、来源产品、手机型号、产品特定编码、材质编码、模具编码。
3. 系统校验审批状态必须为 `approved`。
4. 系统校验来源产品必须是已发布的 `product_line`。
5. 系统创建新型号 `Product` 子项。
6. 系统解析钉钉传入的模具编码。
7. 系统按基础字段反向生成预期模具编码并比对。
8. 系统查询 `plm_inventory` 是否已有该模具编码。
9. 已存在则关联；不存在则创建 `tooling/draft` 待开模资料。
10. 系统把模具编码、匹配状态、匹配明细写入第一节点表单。
11. 项目详情第一节点可直接看到模具编码和匹配结果。

## 5. 好处

- 编码规则从文档变成了可复用的后端代码，不再靠人工拼接。
- 钉钉传入的模具编码不会被盲目信任，会先解析和反向校验。
- 已有模具不会重复创建，避免库存资料重复。
- 新开模具自动进入 `Inventory/tooling/draft`，符合 PLM 七大对象边界。
- 第一节点能看到钉钉带入的编码和系统匹配结果，方便项目人员复核。
- `N` 开头成品/半成品编码生成能力已沉淀在统一工具里，后续 SKU、BOM、工序模块可以复用。

## 7. 后续维护建议

1. 产品特定编码建议后续沉淀为 `Product` 的明确字段，例如 `product_specific_code`，不要长期依赖钉钉传入字段。
2. 手机型号编码建议作为 Product 型号层级或编码中心字典维护，后续解析时从字典匹配，不依赖 4 位兜底截取。
3. 材质编码建议进入编码中心，例如 `code_type=material`，支持 TPU、PC 以外的更多材质。
4. `4030` 最终工序编码建议进入工序库配置，由工序主数据标记最终工序，不长期硬编码。
5. 模具从 `draft` 到 `available` 应挂到开模/试模节点审批后流转，避免申请阶段直接成为可用库存。
6. 钉钉正式联调时，需要补签名验签、用户映射、失败重试和集成记录查询页面。
7. BOM 批量导入后可复用 `ProductBusinessCodeGenerator.generateProductStateCode` 自动生成成品/半成品编码，并与颜色编码、最终工序一起校验。
