# PLM 前端 M3 时间轴动作接入代码实现沉淀

日期：2026-07-13

## 1. 本次目标

把后端已经实现的 M3 时间轴动作接口接入前端项目详情页，在“当前节点”区域支持：

```text
确认当前节点：confirm
推进到下一节点：advance
退回当前节点修改：returnToPrevious=false
退回上一节点：returnToPrevious=true
```

接入后，用户可以在项目中心打开某个 Product 详情，直接对当前时间轴节点执行确认、推进和退回动作。项目流程/时间轴节点卡片仍只负责展示，不放操作按钮。

## 5. 代码逻辑

### 5.1 页面打开详情

```text
用户打开项目详情
-> getProductPresentation(productId)
-> getProjectTimeline(productId)
-> mapTimelineToPresentationNodes(timeline)
-> 找到 status=current 的当前节点
-> 展示当前节点名称、确认状态、最近动作和下一步动作
```

### 5.2 确认当前节点

```text
用户点击“确认当前节点”
-> ElMessageBox.prompt 允许填写备注
-> confirmTimelineNode(projectId, currentNode.nodeKey, remark)
-> 成功后 refreshProjectTimeline(projectId)
-> 再 loadData() 刷新项目列表当前阶段
-> 页面提示“节点已确认”
```

合格标准：

```text
Network 出现 POST /api/v1/projects/{projectId}/timeline/{nodeKey}/confirm。
响应 code=0 且 data.action=confirm。
页面重新请求 GET /api/v1/projects/{projectId}/timeline。
当前节点仍为原节点，确认状态变为“已确认”。
```

### 5.3 推进下一节点

```text
当前节点已确认时，显示“推进下一节点”
-> 用户确认推进
-> advanceTimelineNode(projectId, currentNode.nodeKey)
-> 成功后 refreshProjectTimeline(projectId)
-> 再 loadData() 刷新项目列表当前阶段
-> 页面提示“已推进到下一节点”
```

合格标准：

```text
未确认时不能推进。
最后节点不能继续推进。
Network 出现 POST /api/v1/projects/{projectId}/timeline/{nodeKey}/advance。
响应 code=0 且 data.action=advance。
页面重新请求 timeline。
当前节点移动到下一节点，新当前节点显示未确认。
```

### 5.4 退回

```text
用户点击“退回”
-> 下拉选择“退回当前节点修改”或“退回上一节点”
-> ElMessageBox.prompt 要求填写退回原因
-> returnTimelineNode(projectId, currentNode.nodeKey, reason, returnToPrevious)
-> 成功后 refreshProjectTimeline(projectId)
-> 再 loadData() 刷新项目列表当前阶段
-> 页面提示“已退回处理”
```

合格标准：

```text
空原因不能提交。
退回当前节点修改时，请求体 returnToPrevious=false。
退回上一节点时，请求体 returnToPrevious=true。
响应 code=0 且 data.action=return。
页面重新请求 timeline。
页面能看到最近退回原因。
```

## 6. 作用功能

```text
1. 工程人员可在项目详情“当前节点”区域确认当前节点。
2. 当前节点确认后，工程人员可手动推进到下一节点。
3. 当前节点可退回当前节点修改，也可退回上一节点。
4. 每次动作成功后，页面重新读取后端时间轴，避免前端伪造状态。
5. 每次动作失败时，页面展示错误，不伪装成功。
6. 动作按钮有 loading 防重复点击。
7. 非当前节点卡片不提供动作按钮。
```

## 8. 每一步合格标准

本次合格标准汇总：

```text
1. API 层不再调用 M3 占位 reject。
2. freeze / publish / archive / abandon 仍未被本次误接入。
3. 按钮只出现在“当前节点”区域。
4. 未确认节点只能确认或退回，不能推进。
5. 已确认节点可以推进或退回。
6. 退回必须填写 reason。
7. 所有成功动作后必须重新请求 timeline。
8. 所有失败动作必须显示错误，不显示成功。
9. 快速重复点击时，loading 阻止重复提交。
10. type-check、build、后端 M3 回归测试按实际环境验证并记录。
```
