# PLM 钉钉项目完成后回传方案沉淀

日期：2026-07-27

## 1. 文档目的

本文用于沉淀“钉钉审批接入 PLM，PLM 完成对应项目流程后再回到钉钉”的方案、已修改代码、目标效果和后续维护方式。

当前结论：

```text
钉钉负责发起审批，并在 PLM 完成对应项目流程后接收结果。
新型号线在 PLM 中只执行到 MODEL_VARIANT_MOLD_TRANSFER / 运模；运模完成即视为该新型号项目在 PLM 中完成。
新型号线 PLM 项目完成后，回到钉钉的动作是：由 PLM 调用钉钉 API 代审批人同意等待节点。
新产品线在 PLM 中跑完整个产品线项目流程；流程完成即视为该新产品线项目在 PLM 中完成。
新产品线 PLM 项目完成后，回到钉钉的动作是：抄送或通知对应人员。
```

重点边界：

```text
不要让钉钉连接器 HTTP 请求一直等待 PLM 流程完成。
创建 PLM 项目和 PLM 完成后回传钉钉，必须拆成两个阶段。
```

## 2. 背景与问题

钉钉新型号审批表会把新型号开模信息传入 PLM，PLM 根据 `processCode` 识别新型号流程，创建 `model_variant` 项目，并把来源产品、型号、Tipo、模具印字、期望交期、模具编码等信息落入项目基础信息。

调试过程中出现过几类问题：

- `processCode`、`approvalStatus` 没有映射到请求体根字段，导致 PLM 返回参数校验失败。
- 新型号流程码未配置，导致 PLM 返回“未支持的钉钉审批流程”。
- 钉钉表单字段名和 PLM 入参字段名不一致，导致缺少 `parentProductId`。
- 钉钉生成的模具编码是带中文说明、顿号、斜杠、换行或字符串 `\n` 的文本，旧逻辑按单个编码校验会报“模具编码格式错误”。
- 如果用同步 HTTP 等待 PLM 运模完成，钉钉连接器会超时。

新的业务规则是：

```text
新型号线在 PLM 中只走到 MODEL_VARIANT_MOLD_TRANSFER / 运模。
运模完成后，该新型号项目在 PLM 中即视为完成并归档。
随后 PLM 回到钉钉，代审批人同意等待节点，让钉钉运模后的审批步骤继续流转。
新产品线在 PLM 中跑完整个产品线项目流程。
产品线项目流程完成后，PLM 回到钉钉，抄送或通知对应人员。
```

## 3. 目标效果

### 3.1 表单提交目标效果

钉钉审批通过或流转到连接器节点后，调用 PLM：

```text
POST /api/v1/integrations/dingtalk/approval-callbacks
```

PLM 应完成：

- 根据 `processCode` 识别新型号流程。
- 校验 `approvalStatus=approved`。
- 根据 `parentProductId` 找到已发布的来源产品。
- 创建 PLM `model_variant` 项目。
- 复制来源产品已确认的生产颜色池。
- 保存新型号需求表单。
- 保存钉钉来源审批实例、审批编号、表单链接、原始 payload。
- 自动解析并拆分模具编码。
- 将模具编码写入新型号基本信息，并在库存资料中匹配或创建待开模模具资料。
- 初始化 PLM 项目时间轴。

该接口返回成功，只代表：

```text
PLM 已接收钉钉表单，并创建新型号项目。
```

不代表：

```text
PLM 运模已完成。
钉钉后续审批已经可以继续。
```

### 3.2 PLM 项目完成目标效果

新型号项目在 PLM 中的流程终点固定为：

```text
MODEL_VARIANT_MOLD_TRANSFER / 运模
```

当 PLM 用户确认运模节点完成后，该新型号项目在 PLM 中即完成：

- 当前节点标记为已确认。
- 项目状态置为 `archived`。
- 写入归档时间、归档人、归档原因。
- 后续 PLM 节点不再继续。
- 触发“回到钉钉并代同意等待节点”的出站动作。

归档原因固定为：

```text
PLM新型号线运模完成，后续流程移交钉钉
```

### 3.3 钉钉审批目标效果

本节描述新型号线。新型号线在 PLM 中到运模即完成，回到钉钉时需要通过“代审批人同意”等待节点，让钉钉后续审批继续走。

钉钉审批模板建议拆成：

```text
申请人填写新型号资料
  -> 前置审批
  -> 连接器：创建 PLM 新型号项目
  -> 审批节点：PLM自动校验/等待运模完成
  -> 钉钉后续审批节点
```

目标自动方案：

```text
PLM 运模完成
  -> PLM 获取或保存当前等待节点 taskId
  -> PLM 使用系统审批账号调用钉钉“同意审批任务”接口
  -> 钉钉等待节点自动通过
  -> 钉钉后续审批继续流转
```

这对应业务口径：

```text
业务系统自动校验通过后，由外部系统调用 API 代审批人一键同意，审批正常流转下一节点。
```

### 3.4 新产品线完成后抄送目标效果

新产品线和新型号线的共同点是：都在 PLM 完成自己对应的项目流程后回到钉钉。

区别是回到钉钉后的动作不同：

```text
新型号线：PLM 到运模即完成，回到钉钉后代审批人同意等待节点。
新产品线：PLM 跑完整个产品线流程即完成，回到钉钉后抄送或通知对应人员。
```

新产品线在 PLM 中完成最后节点后，回到钉钉的目标动作是：

- PLM 项目完成或归档。
- 记录产品线流程完成时间、完成人、完成节点。
- 根据配置找到需要抄送的人。
- 通过钉钉发送抄送、工作通知、群通知或待办提醒。
- 抄送结果写入出站集成记录，便于失败重试和审计。

建议通知内容：

```text
PLM 新产品线流程已完成
产品：xxx
项目：xxx
产品编码：xxx
完成时间：2026-07-27 18:00
PLM 链接：xxx
请相关人员查看后续生产、资料或业务安排
```

## 4. 推荐集成方案

### 4.1 阶段一：钉钉创建 PLM 对应项目

钉钉连接器调用 PLM 入站接口，PLM 快速返回。

```text
钉钉 -> PLM：创建对应 PLM 项目
PLM -> 钉钉：已接收、已创建、返回 projectId
```

这个阶段不能等待 PLM 项目流程完成，避免连接器超时。

### 4.2 阶段二 A：新型号线 PLM 运模完成后代同意

新型号线在 PLM 中只到运模。PLM 在运模节点确认时，该新型号项目在 PLM 中完成，并触发回到钉钉的出站动作。

推荐目标方案：

```text
PLM -> 钉钉：调用同意审批任务 API，自动通过“PLM自动校验/等待运模完成”节点
```

保底方案：

```text
PLM -> 钉钉：发送工作通知或群通知，由负责人手动在钉钉审批中点击通过
```

推荐先按“自动方案”的数据结构和幂等记录设计；如果钉钉权限或模板限制暂时不满足，再临时降级为人工确认。

### 4.3 阶段二 B：新产品线 PLM 流程完成后抄送

新产品线在 PLM 中跑完整个产品线项目流程。流程完成后也要回到钉钉，只是回到钉钉后的动作不是“代审批人同意”，而是“抄送或通知对应人员”。

推荐方案：

```text
PLM 产品线流程完成
  -> PLM 项目完成/归档
  -> PLM 创建出站通知记录
  -> PLM 回到钉钉，调用通知能力抄送对应人员
  -> 写入 success / failed 状态
```

抄送对象建议支持配置：

- 固定用户：例如产品负责人、业务负责人、工程负责人。
- 来源表单字段：例如钉钉表单里选择的抄送人。
- PLM 项目字段：例如项目负责人、创建人、当前节点处理人。
- 部门或群：例如产品群、工程群、生产准备群。

维护建议：

```text
新产品线完成通知不要硬编码人员。
优先做成配置项或表单字段映射，方便后续调整。
```

## 5. 钉钉模板配置要求

### 5.1 连接器节点

连接器节点只负责创建 PLM 项目。

连接器请求地址：

```text
https://{外网域名}/api/v1/integrations/dingtalk/approval-callbacks
```

请求方法：

```text
POST
```

请求头：

```json
{
  "Content-Type": "application/json"
}
```

如果后端启用 `callbackToken`，需要补：

```json
{
  "X-PLM-Callback-Token": "与后端配置一致的 token"
}
```

### 5.2 等待节点

连接器后面增加一个审批节点：

```text
PLM自动校验/等待运模完成
```

审批人建议配置为专用系统账号：

```text
PLM自动审批人
```

不建议配置成随机业务人员，原因：

- 后续 API 代同意时需要明确 `actionerUserId`。
- 使用专用账号便于审计。
- 避免误用真实审批人的权限和待办。

### 5.3 后续节点

等待节点之后继续配置原来的钉钉审批流程。

PLM 不主动新建新的钉钉审批实例，只推动原审批实例的等待节点继续流转，避免和审批中心自定义模板冲突。

## 6. 钉钉自动同意接口设计

目标接口：

```text
POST https://api.dingtalk.com/v1.0/workflow/processInstances/execute
```

用途：

```text
同意或拒绝指定审批实例下的指定审批任务。
```

自动同意时，PLM 需要准备：

```text
processInstanceId / approvalInstanceId：钉钉审批实例 ID
taskId：当前“PLM自动校验/等待运模完成”节点任务 ID
actionerUserId：系统审批账号 userId
result：agree
remark：PLM 运模完成说明
```

建议出站 payload：

```json
{
  "processInstanceId": "ding-instance-xxx",
  "taskId": "ding-task-xxx",
  "actionerUserId": "plm-auto-approver",
  "result": "agree",
  "remark": "PLM 运模已完成，项目已归档，自动代同意钉钉等待节点"
}
```

`taskId` 来源建议二选一：

- 监听钉钉审批任务变更事件，当前流程到达等待节点时保存 `taskId`。
- 运模完成时通过审批实例详情查询当前任务列表，找到系统审批账号对应的待办任务。

维护建议：

```text
能监听事件就优先监听事件。
事件丢失时，再用审批实例详情查询作为兜底。
```

参考文档：

- 钉钉“同意或拒绝审批任务”：`https://dingtalk.apifox.cn/api-141067774`
- 钉钉“同意或拒绝审批流程”说明：`https://dingtalk.apifox.cn/doc-3568375`

## 7. 入站 JSON 字段口径

新型号当前需要的核心字段：

```json
{
  "processCode": "PROC-BD65F530-F66F-46B9-8F72-0567DD68F60C",
  "approvalInstanceId": "ding-instance-smoke-001",
  "approvalNo": "DT-MODEL-SMOKE-001",
  "approvalStatus": "approved",
  "approvedAt": "2026-07-24T10:30:00+08:00",
  "formUrl": "https://aflow.dingtalk.com/mock",
  "applicant": {
    "userId": "ding-user-001",
    "userName": "测试人员"
  },
  "form": {
    "parentProductId": 1,
    "tipo": "Fantasia Case",
    "model": "Xiaomi Redmi A7 Pro",
    "generatedCode": "MFA101291\nMFA201291",
    "moldMarking": "Redmi A7 Pro",
    "expectedDeliveryDate": "2026-08-30",
    "remark": "钉钉连接器联调"
  },
  "attachments": []
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `processCode` | 钉钉审批流程码，用于区分产品线和新型号线 |
| `approvalInstanceId` | 钉钉审批实例 ID，后续回传钉钉必须保存 |
| `approvalNo` | 钉钉审批编号，用于业务展示和追踪 |
| `approvalStatus` | 当前审批状态，新型号创建要求为 `approved` |
| `approvedAt` | 钉钉审批通过时间 |
| `formUrl` | 钉钉审批表链接 |
| `applicant.userId` | 申请人钉钉 userId |
| `applicant.userName` | 申请人名称 |
| `form.parentProductId` | 来源产品 ID，必须是已发布产品线 |
| `form.tipo` | 产品类型 / Tipo |
| `form.model` | 新型号型号 |
| `form.generatedCode` | 钉钉生成的模具编码，可包含换行、顿号、斜杠、中文说明 |
| `form.moldMarking` | 模具印字 |
| `form.expectedDeliveryDate` | 期望交付日期 |
| `form.remark` | 备注 |
| `attachments` | 附件列表，当前可为空 |

当前兼容字段名：

| PLM 字段 | 兼容别名 |
| --- | --- |
| `parentProductId` | `parent_product_id`、`来源产品ID`、`父产品ID` |
| `model` | `modelos`、`Modelos 型号`、`型号` |
| `tipo` | `Tipo 类型`、`产品类型`、`类型` |
| `moldMarking` | `Selle en el molde 模具印字`、`模具印字` |
| `moldCodes` | `generatedCode`、`生成的编码`、`模具编码` |
| `expectedDeliveryDate` | `预计交付时间`、`预计交付日期` |
| `remark` | `备注` |

## 8. 已修改代码与文件

### 8.1 钉钉入站分发

文件：

```text
plm-server/src/main/java/com/yuewei/plm/module/integration/dingtalk/service/DingTalkApprovalDispatchService.java
```

作用：

- 统一接收钉钉审批回调。
- 根据 `processCode` 分发到产品线或新型号服务。
- 支持从根字段和 `form` 字段中合并取值。
- 对新型号字段做中文字段名、英文变量名兼容。

关键维护点：

```text
以后钉钉表单字段名变更，优先在这里补字段别名。
不要直接改业务服务里的字段解析。
```

### 8.2 钉钉新型号 DTO

文件：

```text
plm-server/src/main/java/com/yuewei/plm/module/integration/dingtalk/dto/DingTalkModelVariantReceiveDTO.java
```

作用：

- 定义新型号入站请求在 PLM 内部的标准结构。
- 必填字段包括审批编号、审批状态、来源产品 ID、型号、Tipo、创建人。
- 承载模具编码、产品特定编码、手机型号编码、材质编码、附件、原始 payload 等扩展字段。

维护点：

```text
新增表单字段时，DTO 先补字段，再在 DingTalkApprovalDispatchService 中做映射。
```

### 8.3 新型号项目创建

文件：

```text
plm-server/src/main/java/com/yuewei/plm/module/integration/dingtalk/service/DingTalkModelVariantService.java
```

作用：

- 幂等处理同一个钉钉审批实例。
- 校验 `approvalStatus=approved`。
- 校验来源产品必须是已发布产品线。
- 创建 `model_variant` 项目。
- 绑定当前启用的新型号流程模板。
- 复制来源产品已确认颜色池。
- 创建新型号需求表单。
- 调用模具编码接入服务。
- 保存入站集成记录 `IntegrationRecord`。
- 写入创建操作日志。

关键维护点：

```text
同一个 approvalInstanceId 不应重复创建项目。
新型号创建失败时，优先查这里的校验逻辑和 integration record。
```

### 8.4 模具编码解析与校验

文件：

```text
plm-server/src/main/java/com/yuewei/plm/common/util/ProductBusinessCodeGenerator.java
```

已改能力：

- `splitCodes` 支持从钉钉文本中提取多个模具编码。
- 支持真实换行和字符串形式的 `\n`。
- 支持中文说明、顿号、斜杠、空格等混合文本。
- 自动大写并去重。

示例：

```text
生成的编码：MFA101291、MFA201291 / MFA301291
```

会被解析为：

```text
MFA101291
MFA201291
MFA301291
```

维护点：

```text
以后只要钉钉生成的编码仍然符合 M + 产品特定编码 + 材质编码 + 手机型号编码 的规则，就不需要表单侧强制逐行填写。
如果编码规则变化，先改 ProductBusinessCodeGenerator，再补测试。
```

### 8.5 模具编码写入与库存匹配

文件：

```text
plm-server/src/main/java/com/yuewei/plm/module/integration/dingtalk/service/MoldCodeIntakeService.java
```

作用：

- 解析 `dto.moldCodes`。
- 如果钉钉没传具体模具编码，但传了产品特定编码、手机型号编码、材质编码，则自动生成模具编码。
- 校验多个模具编码的产品特定编码和手机型号编码必须一致。
- 将 `dto.moldCodes` 回填为干净的换行分隔格式。
- 将产品特定编码、手机型号编码、材质编码回填到 DTO，最终落到新型号基本信息。
- 在 `plm_inventory` 中匹配已有模具资料；不存在则创建 `tooling` 类型草稿库存资料。

维护点：

```text
“模具编码格式错误”优先看这里和 ProductBusinessCodeGenerator。
如果要调整模具资料创建字段，改 createToolingInventory。
```

### 8.6 新型号流程截断到运模

文件：

```text
plm-server/src/main/java/com/yuewei/plm/module/project/service/TimelineDefinitionProvider.java
```

作用：

- 获取项目时间轴定义。
- 对 `model_variant` 类型项目，将流程定义截断到 `MODEL_VARIANT_MOLD_TRANSFER`。
- 无论来自动态流程模板还是 fallback 常量，都确保新型号 PLM 流程不进入运模之后的节点。

维护点：

```text
如果以后新型号 PLM 流程终点变化，只改这里的终点节点判断和对应测试。
```

### 8.7 运模完成后项目归档

文件：

```text
plm-server/src/main/java/com/yuewei/plm/module/project/service/impl/TimelineActionServiceImpl.java
```

作用：

- 确认当前时间轴节点。
- 当当前项目是 `model_variant` 且当前节点是 `MODEL_VARIANT_MOLD_TRANSFER`，确认后将项目置为 `archived`。
- 写入归档人、归档时间、归档原因。

当前已实现：

```text
PLM 运模完成后项目归档。
```

当前未实现：


## 10. 后续代码实施建议

建议新增独立服务：

```text
DingTalkWorkflowTaskExecuteService
DingTalkProductLineCompletionNotifyService
```

DingTalkWorkflowTaskExecuteService 职责：

- 获取钉钉 access token。
- 查询或接收当前审批任务 `taskId`。
- 调用 `processInstances/execute`。
- 写入出站集成记录。
- 处理幂等和重试。

DingTalkProductLineCompletionNotifyService 职责：

- 判断产品线流程完成事件。
- 解析抄送人。
- 发送钉钉抄送或工作通知。
- 写入出站集成记录。
- 处理幂等和重试。

建议新增或复用出站记录：

```text
source_system = dingtalk
integration_type = model_variant_mold_transfer_completed
direction = outbound
project_id = PLM 项目 ID
external_instance_id = 钉钉审批实例 ID
external_task_id = 钉钉等待节点 taskId
process_code = 新型号流程码
processing_status = pending / success / failed
error_message = 失败原因
last_triggered_at = 最近触发时间
```

产品线完成抄送建议记录：

```text
source_system = dingtalk
integration_type = product_line_completed_cc
direction = outbound
project_id = PLM 产品线项目 ID
process_code = 新产品线流程码
receiver_user_ids = 抄送人 userId 列表
processing_status = pending / success / failed
error_message = 失败原因
last_triggered_at = 最近触发时间
```

幂等键建议：

```text
新型号自动同意：project_id + node_key + task_id + action=agree
新产品线完成抄送：project_id + final_node_key + receiver_hash + action=cc
```

触发位置建议：

```text
TimelineActionServiceImpl.completeModelVariantAtMoldTransfer(...)
```

但不要把钉钉 HTTP 调用硬写进时间轴主事务里。建议：

```text
1. 时间轴事务内只完成 PLM 状态和 pending 出站记录。
2. 事务提交后异步调用钉钉。
3. 调用成功更新 success。
4. 调用失败更新 failed，允许后台或人工重试。
```

### 11.2 常见错误排查

| 错误 | 含义 | 处理 |
| --- | --- | --- |
| `processCode must not be blank` | 钉钉没有把流程码映射到请求体根字段 | 连接器请求体补 `processCode` |
| `approvalStatus must not be blank` | 钉钉没有传审批状态 | 连接器请求体补 `approvalStatus=approved` |
| `未支持的钉钉审批流程` | 后端配置的流程码和钉钉模板不一致 | 修改 `modelVariantProcessCode` 或钉钉流程码 |
| `缺少字段 parentProductId` | 表单字段没映射来源产品 ID | 钉钉表单增加字段或映射别名 |
| `模具编码格式错误` | 传入文本无法提取符合规则的 M 开头模具编码 | 检查 `generatedCode` 内容和编码规则 |
| `HTTP 请求超时` | 连接器同步等待太久 | 使用两阶段方案，不在创建项目接口等待运模 |
| `404 cpolar domain doesn't exist` | 外网穿透域名失效或填错 | 更新钉钉连接器 URL |
| `500 服务器内部错误` | 后端内部异常 | 用 `requestId` 查服务日志 |

### 11.3 配置变更维护

钉钉审批模板变化时，按顺序检查：

```text
1. processCode 是否变化。
2. 表单字段名是否变化。
3. 连接器 URL 是否仍然可访问。
4. 等待节点审批人是否仍是 PLM 自动审批账号。
5. PLM 是否还能拿到 approvalInstanceId 和 taskId。
```

PLM 编码规则变化时，按顺序检查：

```text
1. ProductBusinessCodeGenerator。
2. MoldCodeIntakeService。
3. ProductBusinessCodeGeneratorTest。
4. MoldCodeIntakeServiceTest。
```

PLM 流程终点变化时，按顺序检查：

```text
1. TimelineDefinitionProvider。
2. TimelineActionServiceImpl.completeModelVariantAtMoldTransfer。
3. TimelineDefinitionProviderTest。
4. TimelineActionServiceImplTest。
```

新产品线完成抄送人员变化时，按顺序检查：

```text
1. 钉钉表单是否有抄送人字段。
2. PLM 配置中是否有默认抄送人。
3. 项目负责人、产品负责人等 PLM 字段是否完整。
4. 出站记录中 receiver_user_ids 是否正确。
5. 钉钉通知是否 success。
```

## 12. 验收清单

### 12.1 创建项目验收

- 钉钉连接器返回 200。
- 返回数据中有 `projectId`。
- `plm_integration_record` 有入站 success 记录。
- `plm_product` 创建 `model_variant` 项目。
- 新型号基本信息中能看到模具编码。
- 多个模具编码换行展示。
- `plm_inventory` 中已有或新建对应模具资料。

### 12.2 PLM 运模验收

- 新型号项目时间轴最后一个节点是运模。
- 运模节点确认后，项目状态变为 `archived`。
- 项目归档原因正确。
- 时间轴不再推进到 PLM 运模后的节点。

### 12.3 新型号钉钉代同意验收

自动方案完成后，需要验收：

- 钉钉流程停在“PLM自动校验/等待运模完成”节点。
- PLM 运模完成后能拿到正确 `taskId`。
- PLM 调用钉钉同意接口成功。
- 钉钉等待节点自动通过。
- 钉钉后续审批节点继续流转。
- 重复点击 PLM 运模确认不会重复调用钉钉同意。
- 钉钉接口失败时有 failed 记录并可重试。

### 12.4 新产品线完成抄送验收

- 新产品线 PLM 最后节点确认完成。
- 项目状态正确进入完成或归档态。
- 系统创建 `product_line_completed_cc` 出站记录。
- 抄送人列表正确。
- 钉钉对应人员收到通知或抄送。
- 重复确认或重试不会重复发送成功通知。
- 发送失败时有 failed 记录并可重试。

## 13. 推荐最终口径

对业务和钉钉配置侧统一说明：

```text
新型号线进入 PLM 后，PLM 负责执行到运模。
PLM 运模确认完成时，该新型号项目在 PLM 中即完成并归档。
随后 PLM 回到钉钉，使用钉钉系统审批账号自动同意“PLM自动校验/等待运模完成”节点。
钉钉审批继续进入后续节点。
新产品线进入 PLM 后，PLM 负责跑完整个产品线流程。
PLM 产品线流程完成时，该新产品线项目在 PLM 中即完成。
随后 PLM 回到钉钉，系统抄送或通知对应人员。
连接器不使用 HTTP 长等待，避免超时。
PLM 不新建新的钉钉审批实例，避免和审批中心自定义模板冲突。
```
