### 1.2 业务问题

前端工作台、项目中心和附件上传在展示同一项目进度时存在口径不一致：

1. 工作台不知道当前推进到哪个小节点。
2. 项目中心和工作台显示的当前节点可能不一致。
3. 上传资料选择小节点后，已上传文件没有稳定显示在对应小节点上。
4. 用户无法通过颜色快速区分“当前步骤”“已上传资料步骤”“待上传资料步骤”。

### 1.3 本次范围

本次只修改前端代码，不修改后端接口、数据库表和后端业务逻辑。

后端仍作为唯一数据源，前端通过 `getProjectTimeline(projectId)` 获取项目时间轴，再统一转换为工作台和项目中心可使用的视图模型。

## 2. 总体方案

采用方案 A：新增前端统一时间轴适配器。

核心原则：

1. 工作台和项目中心都使用后端时间轴数据，不再各自推导当前步骤。
2. 大节点用于分组，小节点用于确认、上传归属和状态展示。
3. 附件数量以小节点 `documentCount` 为准，上传后刷新时间轴。
4. 当前小节点优先显示“当前态”，即使已有附件，也继续展示为当前节点，同时显示“已上传 N 个”。
5. 非当前但已上传资料的小节点显示为已确认或已上传状态，便于用户识别资料归属。

```ts
export function mapTimelineSteps(timeline: TimelineDetailVO | null | undefined): TimelineStepView[] {
  if (!timeline?.nodes?.length) return []
  const currentStepNo = Number(timeline.currentStepNo || 1)

  return timeline.nodes.map((node) => {
    const documentCount = Number(node.documentCount || 0)
    const isCurrent = node.stepNo === currentStepNo || node.status === 'current'
    const isConfirmed = Boolean(node.confirmed) || node.stepNo < currentStepNo || node.status === 'completed'

    return {
      nodeKey: node.nodeKey,
      stepNo: node.stepNo,
      stepName: node.nodeName,
      stageCode: node.stageCode,
      stageName: node.stageName,
      phaseName: node.phaseName,
      status: node.status,
      confirmed: Boolean(node.confirmed),
      documentCount,
      requiredFileCategory: node.requiredFileCategory,
      isCurrent,
      isConfirmed,
      hasUploaded: documentCount > 0,
      visualStatus: resolveStepVisualStatus(node, currentStepNo),
      source: node
    }
  })
}
```

```ts
export function mapTimelineStages(timeline: TimelineDetailVO | null | undefined): TimelineStageView[] {
  const steps = mapTimelineSteps(timeline)
  const groups = new Map<string, TimelineStepView[]>()

  steps.forEach((step) => {
    const key = step.stageCode || step.nodeKey
    groups.set(key, [...(groups.get(key) || []), step])
  })

  return Array.from(groups.entries()).map(([stageCode, groupSteps]) => {
    const current = groupSteps.find((step) => step.isCurrent)
    const rejected = groupSteps.some((step) => step.status === 'rejected')
    const allConfirmed = groupSteps.every((step) => step.isConfirmed)

    return {
      stageCode,
      stageName: current?.stageName || groupSteps[0]?.stageName || groupSteps[0]?.stepName || stageCode,
      phaseName: current?.phaseName || groupSteps[0]?.phaseName || '',
      status: rejected ? 'rejected' : current ? 'current' : allConfirmed ? 'completed' : 'pending',
      currentStepNo: Number(timeline?.currentStepNo || current?.stepNo || groupSteps[0]?.stepNo || 1),
      documentCount: groupSteps.reduce((sum, step) => sum + step.documentCount, 0),
      steps: groupSteps
    }
  })
}
```

## 4. 业务逻辑说明

### 4.1 后端调用数据逻辑

前端打开工作台项目进度：

1. 调用 `getWorkbenchInProgressProjects()` 获取进行中项目列表。
2. 用户点击项目后，调用 `getProjectTimeline(projectId)` 获取该项目完整时间轴。
3. 前端通过 `mapTimelineStages()` 按大节点分组。
4. 前端通过 `findCurrentTimelineStep()` 找到当前小节点。
5. 用户点击确认时，调用 `confirmTimelineNode(projectId, currentStep.nodeKey, remark)`。
6. 确认成功后重新调用 `getProjectTimeline(projectId)` 和 `getWorkbenchInProgressProjects()` 刷新页面。

前端打开项目中心详情：

1. 调用 `getProductPresentation(productId)` 读取基础展示数据；如果该接口不可用，则使用当前列表行生成基础兜底对象。
2. 调用 `getProjectTimeline(productId)` 获取真实流程数据。
3. 使用 `mapTimelineStages()` 生成项目中心流程大节点和小节点。
4. 使用 `findCurrentTimelineStep()` 设置当前激活的大节点。
5. 页面展示当前小节点、附件数量和状态。

前端上传节点资料：

1. 上传弹窗里的“资料归属步骤”来自当前大节点下的小节点列表。
2. 用户选择小节点后，前端调用 `uploadTimelineAttachment(projectId, selectedStep.nodeKey, file, category)`。
3. 上传成功后重新调用 `getProjectTimeline(projectId)`。
4. 后端返回的小节点 `documentCount` 更新后，页面对应小节点展示“已上传 N 个”。

### 4.2 状态规则

| 后端状态/数据 | 前端状态 | 用户看到的效果 |
| --- | --- | --- |
| `status=current` 且当前小节点无附件 | `missing-upload` | 当前步骤 + 待上传 |
| `status=current` 且当前小节点有附件 | `current` | 当前步骤 + 已上传 N 个 |
| `stepNo < currentStepNo` 或 `status=completed` | `confirmed` | 已确认 |
| 非当前小节点且 `documentCount > 0` | `uploaded` | 已上传资料 |
| `status=rejected` | `rejected` | 已退回 |
| 其他 | `pending` | 待处理 |

说明：当前小节点优先表达“正在处理哪一步”，所以即使已经上传附件，也不改成纯绿色已上传态，而是在当前态上显示附件数量。
