## 4. 关键代码逻辑

### 4.1 模板查询接口

```java
@GetMapping("/process-route-templates")
public ResponseVO<List<ProcessRouteTemplateVO>> listTemplates(
    @RequestParam(required = false) String productCode,
    @RequestParam(required = false) Boolean onlyDefault,
    HttpServletRequest request
) {
    return ResponseVO.success(
        processRouteTemplateService.listTemplates(productCode, onlyDefault),
        RequestIdUtil.getRequestId(request),
        OffsetDateTime.now()
    );
}
```

作用：前端按产品编码查询可用标准路线组合。当前 MVP 使用内置模板，后续可切换为配置表或清洗后的 seed 导入。

### 4.2 后端编码生成

```java
private String buildProcessCode(Product product, ProcessRouteSaveDTO dto) {
    String routeTemplateCode = StringUtils.hasText(dto.getRouteTemplateCode())
        ? dto.getRouteTemplateCode()
        : "CUSTOM";
    return sanitizeCode(product.getProductCode()) + "-"
        + sanitizeCode(routeTemplateCode) + "-"
        + sanitizeCode(dto.getVersionNo());
}
```

作用：废弃原 `PROC-{projectId}-{timestamp}`，改为业务可读、可追溯的产品编码版本化编码。

### 4.3 模板复制为 Process 工序

```java
private List<ProcessOperationDTO> resolveOperations(ProcessRouteSaveDTO dto, ProcessRouteTemplateVO template) {
    if (dto.getOperations() != null && !dto.getOperations().isEmpty()) {
        return dto.getOperations();
    }
    if (template == null || !Boolean.TRUE.equals(dto.getCopyTemplateOperations())) {
        return dto.getOperations();
    }
    return template.getOperations().stream().map(operation -> {
        ProcessOperationDTO target = new ProcessOperationDTO();
        target.setOperationCode(operation.getOperationCode());
        target.setSequenceNo(operation.getSequenceNo());
        target.setProcessName(operation.getProcessName());
        target.setProcessParamJson(operation.getProcessParamJson());
        target.setQualityRequirement(operation.getQualityRequirement());
        return target;
    }).toList();
}
```

作用：模板不是业务根对象，保存时仍复制为当前 Product 下的 `Process(operation)`。

## 5. 目标效果

1. 工作台到达“加工艺”“敲定工序”“差异组件/工艺确认”等小步骤时，不再把工艺路线当作普通附件上传。
2. 点击“新建工艺路线”后进入项目中心工艺路线页。
3. 新建弹窗默认选择标准工艺路线模板，并带出工序明细。
4. 编码预览显示 `产品编码-路线模板编码-版本号`。
5. 保存后后端返回真实 `Process` 数据，节点配置核对表显示“已落库”。
6. locked 路线不能编辑，只能查看。
7. 同一产品可保留多条路线版本，并通过适用型号、适用颜色、BOM 版本、最终确认标记区分。

## 6. 前端直接测试步骤与合格标准

### 6.1 工作台入口

步骤：
1. 启动本地数据库、后端、前端。
2. 登录系统。
3. 进入工作台。
4. 选择一个流程已到“加工艺”或“敲定工序”的项目。
5. 打开项目进度弹窗。
6. 查看当前小步骤底部按钮。
7. 点击“新建工艺路线”。

合格标准：
1. 当前小步骤显示“新建工艺路线”。
2. 不显示普通“上传节点资料”按钮。
3. 页面跳转到项目中心。
4. 自动打开该项目详情，并定位到“工艺路线/工序明细”分区。
5. 自动弹出“新建工艺路线”弹窗。

### 6.2 模板新建路线

步骤：
1. 在新建弹窗中选择“标准注塑组装路线”。
2. 查看工序明细。
3. 查看编码预览。
4. 保存。

合格标准：
1. 工序明细自动出现注塑、修边、组装、包装等模板工序。
2. 编码预览类似 `PRD-xxx-ROUTE-STD-INJECTION-V1`。
3. 保存请求发送到 `POST /api/v1/projects/{projectId}/process-routes`。
4. 保存后列表能看到刚创建的工艺路线。
5. 控制台无 400/500 错误。

### 6.3 节点配置核对表

步骤：
1. 新建或编辑工艺路线。
2. 调整工序顺序。
3. 查看“节点配置核对表”。
4. 保存后刷新页面重新进入该路线。

合格标准：
1. 核对表展示顺序、工序编码、工序名称、前置节点、后置节点。
2. 保存前显示“草稿”。
3. 保存后重新读取后端数据，显示“已落库”。
4. 前后置关系和工序顺序一致。

### 6.4 锁定路线

步骤：
1. 选择一条 draft 工艺路线。
2. 点击“锁定”。
3. 确认后查看按钮状态。

合格标准：
1. 路线状态变为“已锁定”。
2. “编辑路线”按钮不可用。
3. 后端返回 `status=locked`。
