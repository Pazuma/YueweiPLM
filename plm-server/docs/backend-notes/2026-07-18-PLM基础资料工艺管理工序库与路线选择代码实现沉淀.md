## 4. 核心代码逻辑

### 4.1 工序库建模

工序库不创建新根对象，落在 `plm_process`：

```java
public static final String TYPE_OPERATION_MASTER = "operation_master";
entity.setProductId(null);
entity.setProcessType(TYPE_OPERATION_MASTER);
entity.setStatus("draft");
```

工序分类、工序类型、默认参数、工位要求存入 `process_param_json`；默认工时使用 `standard_time_mins`；默认质量要求使用 `quality_requirement`。

### 4.2 项目路线保存

项目路线内每道工序可以传 `operationMasterProcessId`。后端保存时：

```java
ProcessEntity master = resolveOperationMaster(dto.getOperationMasterProcessId());
operation.setOperationMasterProcessId(master.getProcessId());
operation.setProcessName(master.getProcessName());
operation.setStandardTimeMins(dto.getStandardTimeMins() != null ? dto.getStandardTimeMins() : master.getStandardTimeMins());
operation.setQualityRequirement(StringUtils.hasText(dto.getQualityRequirement()) ? dto.getQualityRequirement() : master.getQualityRequirement());
```

校验规则：

1. 工序主数据必须存在。
2. `process_type` 必须是 `operation_master`。
3. 状态必须是 `confirmed` 或 `locked`。
4. 前端传入的 `processName` 不作为最终可信来源，后端以工序库主数据快照为准。

### 4.3 参数快照

项目路线工序参数由“工序库默认参数 + 项目局部参数”合并：

```java
params.putAll(defaultParamsFromMaster);
params.putAll(projectOperationParams);
params.put("operationCode", operationCode);
params.put("operationMasterProcessId", master.getProcessId());
params.put("operationMasterCode", master.getProcessCode());
params.put("operationMasterName", master.getProcessName());
```

这样后续工序库改名或改默认参数，不会自动污染已经保存或锁定的历史项目路线。

### 4.4 前端选择工序

项目路线编辑弹窗中，工序列改为选择器：

```vue
<el-select
  v-model="operation.operationMasterProcessId"
  filterable
  placeholder="选择工序"
  @change="(processId) => applyOperationMaster(operation, processId)"
>
  <el-option
    v-for="item in operationMasterOptions"
    :key="item.processId"
    :label="`${item.processName} / ${item.processCode}`"
    :value="item.processId"
  />
</el-select>
```

选择后带出：

```ts
operation.operationMasterProcessId = master.processId
operation.operationCode = master.processCode
operation.processName = master.processName
operation.standardTimeMins = master.defaultStandardTimeMins ?? 0
operation.qualityRequirement = master.defaultQualityRequirement || ''
operation.processParamJson = master.defaultProcessParamJson || '{}'
```

## 5. 作用功能

1. 工序名称不再靠项目人员临时手写，减少同义词、错别字、编码不一致。
2. 基础资料可集中维护常用工序，工作台和项目中心统一选择。
3. 标准工艺路线从数据库读取，后续不用改 Java 静态代码即可维护路线模板。
4. 项目路线保存工序主数据引用和快照，满足版本追溯。
5. 基础工序新增、更新、确认、归档有操作日志动作常量和日志写入。

步骤：
1. 进入“工序库”标签。
2. 查看初始化数据。

步骤：
1. 在“工序库”点击“新增工序”。
2. 输入 `PROC_TEST_PRESS`、`测试压合`、分类 `组装`、类型 `加工`、默认参数 `{"pressure":30}`。

合格标准：
1. 新增接口成功，无 400/500。
2. 新增工序出现在工序库列表。
3. 状态为 `confirmed` 或页面显示已确认。
4. 后续项目路线编辑弹窗中能选择该工序。

### 6.4 标准工艺路线

步骤：
1. 切换到“标准工艺路线”。
2. 查看初始化路线。

合格标准：
1. 能看到 `ROUTE-STD-INJECTION`、`ROUTE-STD-TPU-PUNCH`、`ROUTE-STD-COATING`。
2. 每条路线显示路线编码、路线名称、版本、默认标识、工序数、工序组合、状态。
3. 工序组合名称来自工序库，不是空字符串。

### 6.5 工作台编写工艺路线

步骤：
1. 进入工作台。
2. 选择处于工艺路线节点的项目。
3. 点击“编写工艺路线”。
4. 在弹窗中选择标准路线模板。
5. 新增一行工序，点击“选择工序”下拉框。
6. 选择一个工序后保存路线。

合格标准：
1. 工序名称位置是下拉框，不是自由输入框。
2. 选择工序后自动带出工序编码、默认工时、默认质量要求、默认参数。
3. 未选择工序库记录时保存被前端拦截，提示“请选择工序库中的工序”。
4. 保存成功后项目路线列表能回显工序编码和工序名称。
5. 控制台没有 400/404/500。

### 6.6 快照追溯

步骤：
1. 保存一条项目工艺路线。
2. 进入项目中心查看该路线。
3. 修改基础工序库中同名工序的默认参数或名称，再查看已保存路线。

合格标准：
1. 已保存路线保留当时的工序编码、名称、参数和质量要求。
2. 已锁定路线不被工序库后续变更自动污染。

### 7.4 404 与后端启动补充验证

问题现象：

```text
GET http://localhost:5173/api/v1/process-route-templates?productCode=PRD-M2测试产品-0002
HTTP 404 Not Found
```

根因判断：

1. `http://localhost:5173/api/...` 是 Vite 代理路径，URL 显示 5173 属于正常现象。
2. 直接访问 `http://localhost:8080/api/v1/process-route-templates` 曾返回 404，说明当时运行的后端不是包含新接口的版本，或新版本启动失败。
3. 后端启动失败点在 Flyway 迁移 `V20260718_1000__process_operation_master_and_templates.sql`。
4. 修复了三类迁移问题：
   - `ck_plm_process_type` 未包含 `operation_master`、`route_template`、`route_template_operation`。
   - `process_param_json` 为 `jsonb`，种子 JSON 需要 `::jsonb`。
   - 全局工序库/标准模板不能使用 `product_id = 0`，因为当前库存在 `plm_process_product_id_fkey` 外键；改为 `product_id = NULL`。

本次补充验证：

```text
Flyway: version=20260718.1000, success=t
GET http://localhost:8080/api/v1/health -> HTTP 200
GET http://localhost:8080/api/v1/process-route-templates -> 未登录时 HTTP 40101，说明接口已注册
POST http://localhost:8080/api/v1/auth/login engineer01/plm123456 -> code=0
GET http://localhost:8080/api/v1/process-route-templates?productCode=PRD-M2测试产品-0002 -> HTTP 200
GET http://localhost:5173/api/v1/process-route-templates?productCode=PRD-M2测试产品-0002 -> HTTP 200
```

数据库结果：

```text
operation_master         10
route_template            3
route_template_operation 13
```

结论：该 404 不是前端接口路径错误，而是后端新版本此前未成功启动；迁移修复并重启后，5173 代理和 8080 后端直连均能返回模板数据。

## 8. 后续维护建议

1. 工序库编码一旦被项目路线引用，不建议物理删除，只做归档。
2. 标准工艺路线模板后续应补齐新增、编辑、确认、归档页面和接口，目前本次落地为数据库化读取和种子初始化。
3. 工序库默认参数只作为新路线创建时的默认值，不应自动改写历史项目路线。
4. 项目流程最终确认时，应结合产品版本统一确认可用工艺路线版本；当前仍不引入 SKU 根对象。
5. 前端测试环境需修复 Node PATH，再执行 Vitest 和前端构建。
6. 完整后端测试中的项目时间轴/发布门禁失败应作为单独问题处理，避免和本次工艺管理验收混在一起。
