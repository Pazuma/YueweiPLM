## 4. 核心代码逻辑

### 4.1 后端默认编码

```java
businessOperationCode =
    PROCESS_STAGE_PREFIX + productShortCode + operationCraftCode + materialStatusCode;
```

示例：

```text
产品短码 BA
工序阶段前缀 N
工艺编码 注塑=10
材料/状态 TPU=10
生成 NBA1010
```

如果 `businessOperationCodeManualFlag=true` 且用户填写了 `businessOperationCode`，后端保存人工编码并转大写，例如 `nba10a1` 保存为 `NBA10A1`。

### 4.2 成品独立标识

```java
operation.setFinishedProductFlag(Boolean.TRUE.equals(dto.getFinishedProductFlag()));
operation.setMaterialStatusCode(materialStatusCode);
```

`finishedProductFlag` 不会改写 `materialStatusCode`。如果前端或历史接口传入 `materialStatusCode=40` 或 `成品`，后端返回校验错误，要求使用成品勾选。

### 4.3 前端联动

```ts
function refreshBusinessOperationCode(operation: ProcessOperationSavePayload) {
  operation.operationCraftCode = findOperationCraftCode(operation)
  if (operation.businessOperationCodeManualFlag && operation.businessOperationCode?.trim()) return
  operation.businessOperationCode = previewBusinessOperationCode(operation)
  operation.businessOperationCodeManualFlag = false
}
```

用户选择工序或材料/状态时，系统刷新默认编码；用户手工修改产品工序编码后，`businessOperationCodeManualFlag=true`，后续不再自动覆盖。

## 5. 作用功能

1. 现场和资料可使用 `NBA1010` 这类产品工序业务编码。
2. 系统仍保留 `PROC_INJECTION` 这类工序库编码，不破坏工序主数据引用。
3. 成品状态清晰独立，不再混入材料/状态码。
4. 工序库维护工艺编码，项目路线选择工序时可带出默认编码片段。
5. 后端最终校验和保存，避免只靠前端生成导致数据不一致。

## 6. 前端直接测试步骤与合格标准

### 6.1 工序库工艺编码

步骤：
1. 启动前端和后端。
2. 登录系统。
3. 进入“基础资料 / 工艺管理 / 工序库”。
4. 点击“新增工序”。
5. 填写工序编码、工序名称、工序分类、工序类型、工艺编码，例如 `10`。
6. 保存后查看工序库列表。

合格标准：
1. 新增弹窗可看到“工艺编码”字段。
2. 工序库列表可看到“工艺编码”列。
3. 保存后工艺编码能回显。
4. 控制台无 400、404、500。

### 6.2 默认产品工序编码

步骤：
1. 进入项目中心，选择产品编码为 `BA` 或用于测试的产品。
2. 打开工艺路线面板，点击“新建工艺路线”。
3. 选择或复制包含“注塑”工序的路线。
4. 材料/状态选择 `TPU / 10`。

合格标准：
1. 产品工序编码自动显示 `NBA1010`。
2. 系统工序编码仍显示 `PROC_INJECTION`。
3. 材料/状态下拉只包含 `TPU / 10`、`PC / 20`、`半成品 / 30`。
4. 下拉中不出现 `成品 / 40`。

### 6.3 成品勾选

步骤：
1. 在同一工序行材料/状态保持 `TPU / 10`。
2. 勾选“成品”。
3. 再取消勾选。

合格标准：
1. 勾选成品后，材料/状态仍保持 `TPU / 10`。
2. 产品工序编码仍保持 `NBA1010`，除非用户人工修改。
3. 取消成品后，材料/状态不被清空。

### 6.4 人工修改编码

步骤：
1. 在产品工序编码输入框中把 `NBA1010` 改为 `NBA10A1`。
2. 保存完整路线。
3. 刷新页面后重新打开该路线。

合格标准：
1. 前端允许人工修改编码。
2. 保存请求 payload 中包含 `businessOperationCode=NBA10A1` 和 `businessOperationCodeManualFlag=true`。
3. 重新打开后仍回显 `NBA10A1`。
4. 后端不把人工编码重新覆盖为默认编码。

## 8. 后续维护建议

1. 产品短码建议后续沉淀为 Product 明确字段，例如 `product_short_code`，不要长期依赖 `productCode` 推导。
2. 工艺编码和材料/状态编码建议进入“系统管理 - 编码管理”或“基础资料 - 工艺管理”统一维护。
3. 当前默认映射内置了常用工序：注塑 `10`、打印 `20`、喷涂 `30`、组装/包装 `40`、CNC `51`、贴磁铁 `52`；后续应改成字典表驱动。
4. 历史 `PET=40` 或 `成品=40` 数据需要单独数据清洗，把成品迁移到 `finished_product_flag=true`。
5. 文件中心后续如按工序归档资料，应优先绑定 `process_id`，展示 `business_operation_code`，避免只靠文本编码匹配。
6. 发布/锁定门禁后续可增加“最终路线至少存在一个成品工序”的校验，但本次不扩大门禁范围。
