## 3. 核心代码逻辑

### 3.1 发布门禁

新增 `ProductReleaseGateValidatorImpl`，集中做发布前资料完整性校验。

校验项：

```text
Product.status 必须是 reviewing
Product.status 不能是 archived
Product.lock_status 不能是 abandoned
当前时间轴必须到允许发布节点：
  product_line -> PRODUCT_LINE_PRODUCTION_DECISION
  model_variant -> MODEL_VARIANT_FREEZE_RELEASE
当前节点必须已确认：
  timeline_current_confirmed=true
  timeline_confirmed_node_key=当前节点 nodeCode
BOM 至少有一个 frozen/released 版本
工艺路线至少有一个 locked/frozen routing
附件至少有 drawing
附件至少有 sop 或 sip
附件至少有 testing
```

门禁预检返回：

```text
passed=true/false
missingItems=[{code,message}]
frozenBomCount
lockedProcessRouteCount
drawingFileCount
sopFileCount
sipFileCount
testingFileCount
```

### 3.2 发布动作

`ProductServiceImpl.publish(Long, ProductLifecycleActionDTO, HttpServletRequest)`：

```text
1. 查询 Product。
2. 从 CurrentUserContext 获取当前用户。
3. 调用 ProductReleaseGateValidator.check。
4. 门禁失败时抛出 BusinessException(40307, "发布门禁未通过", gate)。
5. 门禁通过后校验状态流转 reviewing -> released。
6. 写 status=released、released_at、released_by。
7. 写 operation_log: PRODUCT_PUBLISH。
8. 返回 ProductVO。
```

旧接口 `publish(Long, String)` 保留给历史调用方：

```text
1. 不强制 CurrentUserContext。
2. 仍执行 ProductReleaseGateValidator.check。
3. 门禁通过后使用传入 operator 写 released_by/updated_by。
4. 写 operation_log: PRODUCT_PUBLISH。
```

### 3.3 冻结动作

保留旧接口 `freeze(Long, String, HttpServletRequest)`，内部转成新 DTO 入口。

新逻辑：

```text
1. 当前用户必须来自 CurrentUserContext。
2. released 不能重复冻结。
3. archived 不能冻结。
4. 写 frozen_at、frozen_by、freeze_reason。
5. 写 lock_status=frozen、lock_reason、lock_operator_user_id、lock_operator_user_name。
6. 写 operation_log: PRODUCT_FREEZE。
7. 返回 ProductVO。
```

### 3.4 归档动作

```text
1. 校验状态机允许进入 archived。
2. 写 Product.status=archived。
3. 写 archived_at、archived_by、archive_reason。
4. 不删除附件、BOM、Process。
5. 写 operation_log: PRODUCT_ARCHIVE。
```

### 3.5 废弃动作

```text
1. released 不允许 abandon。
2. archived 不允许重复 abandon。
3. 未发布 Product 废弃后进入 archived。
4. 写 lock_status=abandoned。
5. 写 abandoned_at、abandoned_by、abandon_reason。
6. 写 operation_log: PRODUCT_ABANDON。
```

说明：未新增 `Product.status=abandoned`，避免破坏既有状态机；废弃语义通过 `lock_status=abandoned` 表达。

## 7. 数据库直查验证

Product 生命周期：

```sql
select product_id, product_code, status, lock_status,
       released_at, released_by,
       archived_at, archived_by, archive_reason,
       abandoned_at, abandoned_by, abandon_reason
from plm_product
where product_id = :projectId;
```

操作日志：

```sql
select action, business_type, business_id, business_code, business_name,
       operator_user_name, detail_json, created_at
from plm_operation_log
where business_type = 'PRODUCT'
  and business_id = cast(:projectId as varchar)
  and action in ('PRODUCT_FREEZE', 'PRODUCT_PUBLISH', 'PRODUCT_ARCHIVE', 'PRODUCT_ABANDON')
order by created_at desc;
```

## 8. 后续维护注意事项

1. `ProductReleaseGateValidatorImpl` 是发布门禁唯一集中入口，后续新增门禁项优先改这里和对应测试。
2. `abandoned` 暂时不作为 `Product.status`，避免破坏全局状态机；当前使用 `lock_status=abandoned`。
3. 发布失败必须返回 `40307` 和结构化 `data.missingItems`，不要只返回字符串。
4. `ProductController.publish` 已不再信任前端 `operator`，发布人统一来自 `CurrentUserContext`。
5. 归档和废弃不删除附件、BOM、Process，保证文件中心和历史追溯可用。
6. 若后续把 required file category 改为配置化，需要同步更新 Apifox 用例和自动化测试。
7. 生产库执行 M5 Flyway 前建议先备份数据库。
