## 5. 业务理解

基础资料里的“工艺管理”是工艺主数据入口；工作台和项目中心是业务执行入口。

推荐业务流：

1. 管理员或工程人员在“基础资料 > 工艺管理”维护工序库，例如注塑成型、修边去披锋、喷涂、组装、包装、成品检验。
2. 在同一个入口维护标准工艺路线模板，例如标准注塑组装路线、TPU 打孔组装路线、表面处理喷涂路线。
3. 每条路线模板由工序库中的工序组合而成，路线中可维护顺序、标准工时、参数 JSON、质量要求、是否关键工序等。
4. 工作台到“加工艺 / 敲定工序”等节点时，点击“编写工艺路线 / 新建工艺路线”。
5. 系统跳转到项目中心或弹窗，用户选择标准路线模板，必要时从工序库增删工序。
6. 保存后生成当前 Product 维度的项目工艺路线，编码按“产品编码 + 路线编码 + 版本号”生成。
7. 进入最终发布前，可锁定一个或多个产品级工艺路线版本，供后续 BOM、文件、质量资料、生产资料追溯使用。

注意：当前讨论范围是 Product 产品级，不包括 SKU 根对象。型号、颜色差异后续仍作为 Product 的型号/颜色/版本维度或工艺路线适用范围表达。

## 7. 数据设计方案

### 7.1 企业级推荐方案

不新增 `Operation`、`Routing` 根对象，仍复用 `plm_process`。

| 数据类型 | 表达方式 | 说明 |
| --- | --- | --- |
| 工序主数据 | `plm_process.process_type = 'operation_master'` | 不绑定具体 Product；作为可选择工序库 |
| 标准路线模板 | `plm_process.process_type = 'route_template'` | 不绑定具体 Product 或绑定产品分类；自身是路线模板头 |
| 模板内工序 | `plm_process.process_type = 'route_template_operation'`，`parent_process_id` 指向模板 | 子项引用 `operation_master_process_id` |
| 项目产品路线 | `plm_process.process_type = 'routing'`，`product_id = 项目产品ID` | 当前已存在方向 |
| 项目路线工序 | `plm_process.process_type = 'operation'`，`parent_process_id` 指向项目路线 | 保存时从工序库复制当时名称和参数快照 |

### 7.2 为什么项目路线工序要保存快照

工序库是主数据，后续可能改名、调整默认参数。已创建的项目路线必须可追溯当时使用的工序口径，所以项目路线保存时需要：

1. 保存 `operationMasterProcessId`，用于追溯来源。
2. 同步保存 `processName`、`operationCode`、`qualityRequirement`、`processParamJson` 快照。
3. 后续工序库变化不自动改已锁定或已保存路线，必须通过变更流程处理。

private ProcessEntity getOperationMasterOrThrow(Long operationMasterProcessId) {
    ProcessEntity master = processRepository.selectById(operationMasterProcessId);
    if (master == null || Integer.valueOf(1).equals(master.getDeletedFlag())) {
        throw new BusinessException(ErrorCodeConstants.RESOURCE_NOT_FOUND, "operation master not found");
    }
    if (!"operation_master".equals(master.getProcessType())) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "selected process is not operation master");
    }
    if (!List.of("confirmed", "locked").contains(master.getStatus())) {
        throw new BusinessException(ErrorCodeConstants.VALIDATION_ERROR, "operation master is not available");
    }
    return master;
}

注意：迁移必须幂等，不可重复插入同一 `process_code`。

## 12. 目标效果

实施后应达到：

1. 用户进入“基础资料 > 工艺管理”能看到工序库和标准工艺路线。
2. 工序名称由基础资料维护，工作台和项目中心只能选择，不再随手输入。
3. 标准路线模板由工序库组合，后续新增路线不需要改 Java 静态代码。
4. 项目产品工艺路线保留当时工序快照，支持版本追溯。
5. 工艺路线与 Product 编码、版本号、适用型号/颜色、BOM 版本关联。
6. 工艺数据可被文件中心、项目中心、发布门禁继续读取，形成同一套后端数据的不同视角。

## 15. 风险与待确认

1. 用户提到“像图二一样”，当前会话没有可读取截图，本文按“基础资料表格管理页 + Tab 分类”的企业后台口径设计；最终 UI 细节需结合截图确认。
2. 当前代码 `ProcessRouteTemplateServiceImpl` 使用 Java 静态模板，后续必须数据库化，否则无法在页面维护标准路线。
3. 当前前端有部分编码显示异常，需要后续实施时顺带确认文件编码，但不建议在本次业务改造中做大范围无关重构。
4. 工序库字段是否需要“默认损耗率、是否领料、是否参与排产、设备类型”等，需要业务再确认；本文先按工艺路线和工作台选择必需字段设计。
5. 如果后续只允许前端改造，不改后端，则只能做到“从前端常量选工序”，不满足企业级主数据维护。

## 16. 后续维护建议

1. 工序库由工程或管理员维护，普通项目用户只能选择，不应新增临时工序。
2. 工序库编码一旦被项目路线引用，不建议物理删除，只能归档。
3. 标准路线模板发布后应进入 `locked`，修改时创建新版本。
4. 项目路线保存后保留工序快照；基础工序库更新不自动污染历史项目。
5. 发布门禁应校验当前项目至少存在已锁定工艺路线。
6. 工艺路线与 BOM 的关系后续应由 Product 版本统一确认，避免 SKU 化扩散。
7. 每次新增工序分类、工序类型、路线模板状态，都要同步更新文档和测试用例。

## 17. 本次沉淀结论

本次方案建议把“工艺管理”作为基础资料下的主数据页面，包含工序库和标准工艺路线模板；工作台和项目中心只负责选择并生成产品项目级工艺路线。该方案符合七个核心对象约束，符合企业级主数据治理和可追溯要求，可作为后续代码实施依据。
