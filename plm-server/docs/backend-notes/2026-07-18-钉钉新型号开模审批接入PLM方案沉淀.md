# 钉钉新型号开模审批接入 PLM 方案沉淀

> 日期：2026-07-18  
> 状态：方案已确认；2026-07-20 完成第一节点单表字段范围调整；仅文档沉淀，未修改业务代码，未进行钉钉联调。  
> 适用范围：钉钉审批通过后创建 PLM 新型号线项目；本期暂不处理新产品线。

## 1. 任务理解

公司通过钉钉发起手机型号开模审批。钉钉审批通过后，由连接器把审批数据传入 PLM。PLM 根据已选产品线、手机型号和该产品正式确认批量生产的颜色，创建一个新型号主项目；该项目继承产品已发布工艺路线快照，第一步展示一张“新型号项目信息完善表”，由用户核对和修改钉钉带入信息，并补充订单类型和客户要求，后续沿用现有新型号线流程。

本次只生成实施方案文档，不落地 Java、Vue、数据库或钉钉配置代码。

## 3. 业务边界

### 3.1 本期包含

- 钉钉审批通过后的同步接入接口；
- 表单类型识别，首期只接受 `new_model`；
- PLM 第一节点补充订单类型（客户订单/市场需求）和客户要求；
- 钉钉字段在第一节点可修改并记录字段级修改日志；
- 已有产品线、手机型号和该产品全部正式确认批量生产颜色；
- 一个审批实例创建一个 Order 和一个新型号主项目；
- 颜色范围和已发布工艺路线的审批时快照；
- 首节点资料完善；
- 幂等、审计、错误返回和人工重试设计。

### 3.2 本期不包含

- 钉钉开放平台正式联调、应用创建、回调配置和线上密钥；
- 新产品线审批接入；
- ERP、MES、WMS、CRM 正式集成；
- 将钉钉附件全量搬运到 MinIO；
- 钉钉字段“是否为新型号”、销售渠道、价格和图片中两个打码字段；
- 修改现有业务代码、迁移脚本或前端页面。

## 4. 方案选择

采用“钉钉连接器直接调用 PLM 专用接入接口”。审批通过后同步调用，PLM 在事务内完成校验、订单创建、颜色快照、路线快照和项目初始化。以钉钉审批实例 ID 作为唯一幂等键，并保留集成记录用于失败重试和审计。

不采用 PLM 定时拉取，避免游标、漏单和延迟；不采用完整异步暂存闭环，避免首期增加调度和补偿页面。接入记录仍保留处理状态，为后续异步化预留边界。

## 5. 业务流程

```text
钉钉新型号审批通过
  -> 连接器签名调用 PLM
  -> 校验审批状态、表单类型和必填字段
  -> approval_instance_id 幂等判断
  -> 定位已有 Product 产品线
  -> 查询并快照该产品全部正式确认批量生产颜色，默认全部选中
  -> 快照当前已发布工艺路线及工序
  -> 创建 Order(order_type=model_variant)
  -> 创建 Product(product_type=model_variant) 主项目
  -> 初始化新型号线 16 节点，当前第 1 节点
  -> PLM 用户在一张表中核对钉钉字段并补充订单类型、客户要求
  -> 保存草稿或确认并进入下一步
  -> 沿用现有开模、差异、测试、冻结、发布流程
```

审批驳回、撤回、终止只记录接收结果，不创建 PLM 业务项目。重复回调返回首次成功结果，不重复创建数据。

## 6. 数据设计

### 6.1 Order 扩展字段

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `order_code` | varchar(64) | PLM 订单号，完成第一节点并创建需求订单时由后端生成，例如 `ORD-20260720-0001` |
| `order_type` | varchar(32) | `model_variant` |
| `requirement_type` | varchar(32) | 第一节点人工选择 `customer_order` 或 `market_requirement` |
| `customer_requirement` | text | 第一节点人工填写客户要求；市场需求场景可填写市场目标和约束 |
| `source_system` | varchar(32) | `dingtalk` |
| `source_reference` | varchar(128) | 审批实例 ID |
| `project_id` | bigint | 关联工作台项目，当前实现可与承载项目的 `product_id` 对齐 |
| `phone_model` | varchar(128) | 新型号订单显示手机型号；新产品订单为空，前端统一显示 `--` |
| `close_reason` | varchar(500) | 项目停止或放弃时同步写入关闭原因 |
| `closed_at` | timestamp | 订单关闭时间 |
| `closed_by` | varchar(64) | 订单关闭操作人 |
| `source_action` | varchar(64) | 关闭来源，例如 `project_abandoned` |

`requirement_type` 和 `customer_requirement` 属于 Order，不放到 Product；它们描述需求来源和业务要求，而不是产品主数据属性。

### 6.2 集成记录表 `plm_integration_record`

建议字段：`integration_record_id`、`source_system`、`integration_type`、`external_instance_id`、`external_status`、`request_hash`、`source_payload_json`、`processing_status`、`order_id`、`project_id`、`error_code`、`error_message`、`retry_count`、`last_retry_at`、`created_at`、`created_by`、`updated_at`、`updated_by`、`deleted_flag`。

唯一索引：`(source_system, integration_type, external_instance_id)`。状态建议为 `received`、`processing`、`success`、`rejected`、`error`、`retrying`。

### 6.3 颜色快照表 `plm_product_variant_color`

建议字段：`variant_color_id`、`project_product_id`、`source_product_id`、`source_decision_id`、`code_item_id`、`color_code`、`color_name`、`source_decision_batch_no`、`source_confirmed_at`、`default_selected_flag`、`selected_flag`、`deselected_at`、`deselected_by`、`snapshot_status`、`created_at`、`created_by`、`updated_at`、`updated_by`、`deleted_flag`。

审批通过时从 `plm_product_production_color_decision` 读取来源产品正式确认批量生产的颜色，并冻结为项目颜色池快照。查询条件固定为 `product_id=来源产品ID`、`selected_flag=1`、`status=confirmed`、`deleted_flag=0`。快照创建时所有颜色均设置 `default_selected_flag=1`、`selected_flag=1`。第一节点允许用户取消部分颜色，但禁止增加来源颜色池之外的颜色；保存草稿时允许暂时全部取消，确认进入下一步时必须至少保留一个颜色。不得从 `plm_product.color` 单值字段、`plm_product_bom_route_color.status=active` 的路线候选颜色或颜色子 Product 列表推导生产颜色范围。来源产品后续重新确认、增加、取消或归档投产颜色，不自动改变已经创建项目的颜色池快照。第一节点完成后，只按 `selected_flag=1` 的最终颜色生成可追溯的型号颜色 Product 子版本。

查询规则建议复用 `ProductProductionColorDecisionRepository`，由独立方法表达，例如 `listConfirmedProductionColors(productId)`，返回 `product_production_color_decision_id`、`code_item_id`、`color_code`、`color_name`、`product_bom_id`、`product_bom_route_id`、`decision_batch_no` 和确认信息。同一正式确认批次内按 `code_item_id` 去重；存在重复确认记录时以当前未删除的 `confirmed` 记录为准，并记录基础资料告警。更新选择结果时，后端必须校验提交的 `variant_color_id` 全部属于当前项目颜色池，不允许前端伪造额外颜色。

### 6.4 工艺路线快照

沿用 Process 对象及现有路线结构，保存来源 `process_id`、路线编码、路线版本、工序顺序、工序编码、工序名称、物料、工位、质量要求和来源版本。快照必须来自已发布/有效路线，不得引用草稿模板。来源路线后续变更不影响本项目快照。

### 6.5 项目与需求订单状态联动

项目在工作台时间轴推进，需求订单和其他项目引用页面不得维护独立、滞后的业务状态。项目推进服务作为状态事实来源，并在同一事务内同步 Order。

| 工作台项目动作 | Product/项目结果 | Order 状态 | 其他页面表现 |
| --- | --- | --- | --- |
| 第一节点确认并创建订单 | 项目继续推进 | `confirmed` | 需求订单出现记录，显示钉钉审批编号、订单号和手机型号 |
| 进入实际开发/生产阶段 | 项目推进中 | `in_production` | 工作台、项目中心、需求订单同步显示进行中 |
| 项目正常完成/发布 | 项目完成或发布 | `completed` | 所有引用位置同步显示已完成 |
| 项目中途停止或放弃 | `lock_status=abandoned` | `closed` | 工作台停止推进，项目中心和需求订单同步关闭 |
| 超级管理员恢复项目 | 恢复放弃前节点和锁定状态 | 恢复放弃前订单状态 | 所有引用页面同步恢复 |

项目停止或放弃时不新增 Order 非标准状态，统一使用标准状态 `closed`，同时写入 `close_reason`、`closed_at`、`closed_by`、`project_id` 和 `source_action=project_abandoned`。恢复前必须保存订单关闭前状态，例如操作日志或专用 `previous_status` 快照，避免一律错误恢复为 `in_production`。

项目状态更新、订单状态更新和操作日志必须位于同一数据库事务。任一写入失败则整体回滚，禁止出现项目已放弃但订单仍进行中，或订单已关闭但项目仍可推进的状态分叉。

## 7. 第一节点单表设计与钉钉字段映射

### 7.1 页面交互

第一节点只展示一张“新型号项目信息完善表”。页面不按 Order、Product、Attachment 分区，用户无需理解后端对象拆分。后端保存时仍按字段业务归属分别写入 Order、Product、Attachment 和集成记录。

- 钉钉审批单号自动带入且只读，作为来源追溯和幂等标识；
- 其他钉钉带入字段允许修改；
- PLM 用户补充订单类型和客户要求；
- 关键图片和附件展示同步结果，并允许继续补充上传；
- 正式投产颜色以多选列表展示，默认全部选中；用户只能取消部分颜色，不能新增来源产品未正式确认投产的颜色；
- “保存草稿”不推进时间轴；
- “保存草稿”允许颜色暂时全部取消；
- “确认并进入下一步”要求至少保留一个生产颜色，并执行必填、权限、来源项目和版本校验，通过后推进现有新型号线流程；
- 每次修改记录字段名、修改前值、修改后值、操作人、操作时间和所属项目。

### 7.2 正式进入 PLM 的字段

| 钉钉字段 | PLM 字段 | 校验 |
| --- | --- | --- |
| 钉钉审批单号/审批实例 ID | `external_instance_id`、`source_reference` | 必填、幂等唯一、页面只读 |
| 审批状态 | `external_status` | 仅 `approved` 创建项目 |
| 表单类型 | `form_type` | 首期仅 `new_model` |
| 产品编码/产品 ID | `parent_product_id` | 必须是有效产品线 |
| Modelos 型号 | `model` | 必填，允许修改并留痕 |
| 4G/5G | `network_type` | 字典值校验，允许修改并留痕 |
| 大孔或精孔 | `hole_type` | 字典值校验，允许修改并留痕 |
| 手机功能 | `mobile_function` | 文本长度校验，允许修改并留痕 |
| Tipo 类型 | `tipo` | 必填、字典值校验，允许修改并留痕 |
| Prioridad 紧急度 | `priority` | 字典值校验，允许修改并留痕 |
| Lugar de fabricación 制造地 | `manufacturing_location` | 字典或文本校验，允许修改并留痕 |
| Sello en el molde 模具印字 | `mold_marking` | 长度和字符规则校验，允许修改并留痕 |
| 网站链接 | `reference_url` | URL 格式校验，允许修改并留痕 |
| 其他备注 | `remark` | 长度校验，允许修改并留痕 |
| Expectante Fecha 期望交付时间 | `expected_delivery_date` | 日期格式校验，允许修改并留痕 |
| 关键图片 | Attachment：`reference_image` | 展示同步结果，允许补充上传 |
| 附件 | Attachment：`customer_requirement` | 展示同步结果，允许补充上传 |
| 表单快照 | `source_payload_json` | 脱敏后审计留存 |

### 7.3 仅在 PLM 第一节点补充的字段

| PLM 字段 | 页面名称 | 规则 |
| --- | --- | --- |
| `requirement_type` | 订单类型 | 必填，客户订单或市场需求 |
| `customer_requirement` | 客户要求 | 客户订单时必填；市场需求时填写市场目标和产品约束 |

### 7.4 明确排除的钉钉字段

“是否为新型号”、销售渠道、价格以及图片中两个打码字段不映射为 PLM 正式业务字段，也不出现在第一节点完善表中。为满足接入审计，原始钉钉报文可在脱敏后整体保存在 `source_payload_json`，但这些排除字段不得参与项目创建、查询、校验、报表和后续状态流转。

### 7.5 字段修改审计

建议复用操作日志体系并新增字段变更明细，至少保存 `project_id`、`order_id`、`field_name`、`old_value`、`new_value`、`operator_user_id`、`operator_user_name`、`operated_at` 和 `source_system`。敏感值和附件不保存完整正文，只保存脱敏摘要、附件 ID 或哈希。

- 首节点组件只展示一张“新型号项目信息完善表”，包含只读钉钉审批单号、可修改的钉钉字段、订单类型、客户要求、正式投产颜色多选列表、关键图片和附件；
- 正式投产颜色默认全部勾选，允许取消但不提供新增颜色入口；每个颜色显示颜色编码、颜色名称和来源确认时间；
- 首节点提供“保存草稿”和“确认并进入下一步”两个动作；
- 钉钉字段发生修改时展示留痕提示，并可在操作记录中查看修改前后值和操作人；
- 移除真实创建流程对前端静态审批模板的依赖。

## 10. 错误与补偿

| 场景 | 处理 |
| --- | --- |
| 签名失败 | 返回 `status=error`，不写业务数据 |
| 表单类型不支持 | 记录 `rejected`，返回不支持原因 |
| 审批未通过 | 记录忽略结果，不创建项目 |
| 产品不存在/不是产品线 | 事务失败，返回明确错误 |
| 产品无正式确认批量生产颜色 | `plm_product_production_color_decision` 中不存在 `selected_flag=1`、`status=confirmed`、`deleted_flag=0` 的记录时事务失败，返回“来源产品尚未确认批量生产颜色”，不创建空项目 |
| 没有已发布路线 | 事务失败，不伪造路线 |
| 用户映射失败 | 事务失败，要求补充映射 |
| 重复回调 | 返回原 `order_id`、`project_id` |
| 项目创建后快照失败 | 全事务回滚，记录错误 |
| 连接器重试 | 依赖唯一索引和处理状态，不重复建单 |
| 用户修改钉钉字段 | 允许保存，逐字段记录修改前值、修改后值和操作人 |
| 修改钉钉审批单号 | 后端拒绝，审批单号只读且不可变 |
| 客户订单未填写客户要求 | 阻止确认进入下一步，保存草稿不受影响 |
| 保存草稿时未选择颜色 | 允许保存，不推进时间轴 |
| 确认时未选择颜色 | 阻止进入下一步，提示“至少保留一个生产颜色” |
| 提交来源颜色池之外的颜色 | 后端拒绝，返回字段校验错误并记录异常操作日志 |
| 项目放弃但订单同步失败 | 同一事务整体回滚，项目保持放弃前状态并返回结构化错误 |
| 订单关闭但项目放弃失败 | 同一事务整体回滚，订单保持原状态 |
| 恢复项目时找不到订单原状态 | 拒绝自动恢复，返回错误并要求管理员核对操作日志，不猜测状态 |

业务成功但无颜色不属于合法空结果，而是配置/数据错误，必须返回错误状态。

## 11. 目标效果

- 钉钉审批通过后自动进入 PLM，人工不再重复录入项目基础信息；
- 一个审批实例只生成一个新型号主项目；
- 产品全部正式确认批量生产颜色被结构化快照并可追溯；
- 新型号默认生产来源产品全部正式投产颜色，但允许在第一节点取消不生产的颜色；
- 来源颜色池、取消颜色和最终生产颜色均可追溯；
- 已发布工艺路线在项目创建时固定，避免后续路线变更造成历史项目漂移；
- 第一节点完成“表格完善”，后续开模流程与现有 PLM 时间轴一致；
- 用户在一张表内完成核对和补充，不需要理解后端 Order、Product、Attachment 拆分；
- 钉钉字段允许修正且修改前后值、操作人和时间可追溯；
- 钉钉来源、审批实例、同步结果、错误和重试全过程可审计；
- 第一节点完成后需求订单自动生成唯一订单号，列表最左侧显示钉钉审批编号；
- 需求订单以手机型号替代原系统编号展示，新产品订单显示 `--`；
- 项目停止、放弃、完成或恢复时，需求订单及其他引用页面同步更新；
- 新产品线表单类型保留扩展位，但不在本期创建。

## 12. 验收标准

1. 同一审批实例最多生成一个 Order 和一个新型号主项目。
2. 新型号项目只关联一个来源产品线。
3. 审批通过时只快照 `plm_product_production_color_decision` 中 `selected_flag=1`、`status=confirmed`、`deleted_flag=0` 的正式投产颜色。
4. 项目颜色范围不从 `plm_product.color`、BOM 路线候选颜色或颜色子 Product 推导。
5. 来源产品正式投产颜色进入新型号第一节点时默认全部选中。
6. 用户可以取消来源颜色，但不能新增来源颜色池之外的颜色。
7. 保存草稿允许零个颜色，确认进入下一步至少保留一个颜色。
8. 只为最终选中的颜色生成新型号颜色 Product 子版本。
9. 审批通过时准确快照已发布工艺路线和工序版本。
10. 首节点以一张表展示钉钉带入资料和 PLM 待完善字段。
11. 钉钉审批单号只读；其他钉钉字段可修改并逐字段留痕。
12. 订单类型必填；客户订单场景下客户要求必填。
13. 保存草稿不推进节点，确认提交成功后才进入下一步。
14. 明确排除的五类字段不进入 PLM 正式业务字段和页面。
15. 后续新型号线 16 个节点顺序、权限、门禁和日志规则不被改变。
16. 失败均返回结构化错误，不用空数组掩盖异常。
17. 集成记录、字段修改日志和项目详情均可按审批实例追溯。
18. 第一节点完成后生成唯一订单号，需求订单列表最左侧为钉钉审批编号。
19. 原系统编号列改为手机型号；新型号显示实际型号，新产品显示 `--`。
20. 项目放弃时订单同步为 `closed` 并记录原因、时间、操作人和来源动作。
21. 项目恢复时订单恢复到放弃前状态，不使用固定状态猜测恢复。
22. 项目和订单状态更新在同一事务完成，任一失败时均不得产生状态分叉。

## 13. 待实施前确认

- 钉钉连接器的签名算法、回调重试策略和字段实际编码；
- 钉钉用户与 PLM 用户映射表及未映射用户的处理人；
- 来源产品存在多批正式投产颜色确认记录时，是否仅以当前未删除的 `confirmed` 批次为准；
- 已发布工艺路线的唯一选择规则；
- 第一节点完成后生成颜色 Product 子版本的编码规则；
- 是否需要同步钉钉附件到 PLM 文件中心。

以上事项不影响本方案文档沉淀，但在正式开发前必须冻结。

## 14. 方案调整记录

### 2026-07-20 第一节点字段和交互收敛

- 取消将需求类型作为钉钉带入字段，改为 PLM 第一节点人工选择订单类型；

- 钉钉带入字段允许修改，但必须记录修改前值、修改后值和操作人；

### 2026-07-20 产品正式确认批量生产颜色口径修正

- 统一使用“产品正式确认批量生产颜色”名称，删除上一版较宽泛的颜色筛选口径；
- 项目颜色范围改为读取 `plm_product_production_color_decision`；
- 查询条件固定为 `product_id=来源产品ID`、`selected_flag=1`、`status=confirmed`、`deleted_flag=0`；

### 2026-07-20 新型号生产颜色选择规则

- 新产品流程最后一步负责正式确认批量生产颜色；
- 新型号开模选择来源产品后，读取该产品正式确认批量生产颜色并默认全部选中；
- 第一节点允许取消部分颜色，但禁止新增来源颜色池之外的颜色；
- 保存草稿允许暂时不选颜色，确认进入下一步必须至少保留一个颜色；
- 同时保留完整来源颜色池快照、取消记录和最终选择结果；
- 只为最终选中的颜色生成新型号颜色 Product 子版本。

### 2026-07-20 需求订单字段与项目状态联动

- 第一节点完成后在需求订单生成唯一 PLM 订单号；

- 原“系统编号”列改为“手机型号”；新型号显示实际型号，新产品显示 `--`；
- 列顺序固定为“钉钉审批编号、订单号、手机型号、类型、关联产品、状态、时间、操作”；

- 项目状态、订单状态和操作日志在同一事务中更新，避免跨页面状态不一致。
