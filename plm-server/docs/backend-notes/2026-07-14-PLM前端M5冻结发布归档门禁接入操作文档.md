## 1. 任务理解

M5 的目标是把“发布 Product”从一个简单按钮，变成一个有门禁、有缺失项提示、有生命周期动作记录的前端流程。

前端接入后，用户在项目详情中应该能看到：

```text
1. 当前项目是否具备发布条件。
2. 缺少哪些资料，例如 BOM、工艺路线、图纸、SOP/SIP、测试资料。
3. 可以执行冻结、发布、归档、放弃动作。
4. 发布失败时能看到后端返回的缺失项清单。
5. 发布、归档后页面能刷新项目状态。
```

重要原则：

```text
前端只做展示、提醒、确认和触发动作。
发布门禁最终以后端校验为准。
前端不能伪造 passed=true，也不能吞掉 missingItems。
```

## 3. 所属 PLM 业务链路

M5 属于 Product 生命周期门禁链路。

新产品线：

```text
Product 建档
-> 设计确认
-> 开模试模
-> 样品与工艺
-> 小批与 MX 验证
-> 投产决策节点确认
-> 发布门禁预检
-> Product.status=released
-> 归档和历史追溯
```

新型号线：

```text
Product 子版本建立
-> 差异设计
-> 模具判断
-> 差异验证
-> 小批与 MX 验证
-> 冻结发布节点确认
-> 发布门禁预检
-> Product.status=released
-> 归档和历史追溯
```

对象口径：

```text
projectId = productId
BOM 是 Product 下的版本化资料
工艺路线是 Process 下的 routing 记录
文件是 Product 附件
发布对象是 Product
不新增 Project、BOM、Routing、FileVersion 等根对象
```

把当前占位函数：

替换为真实接口：

```ts
export async function checkProjectReleaseGate(projectId: number): Promise<ProductReleaseGateCheckVO> {
  const response = await request.get(`/projects/${projectId}/release-gate`)
  return unwrapResponse<ProductReleaseGateCheckVO>(response)
}

export async function freezeProject(
  projectId: number,
  payload: ProductLifecycleActionPayload = {}
): Promise<ProductLifecycleResultVO> {
  const response = await request.post(`/projects/${projectId}/freeze`, payload)
  return unwrapResponse<ProductLifecycleResultVO>(response)
}

export async function publishProject(
  projectId: number,
  payload: ProductLifecycleActionPayload = {}
): Promise<ProductLifecycleResultVO> {
  const response = await request.post(`/projects/${projectId}/publish`, payload)
  return unwrapResponse<ProductLifecycleResultVO>(response)
}

export async function archiveProject(
  projectId: number,
  payload: ProductLifecycleActionPayload = {}
): Promise<ProductLifecycleResultVO> {
  const response = await request.post(`/projects/${projectId}/archive`, payload)
  return unwrapResponse<ProductLifecycleResultVO>(response)
}

export async function abandonProject(
  projectId: number,
  payload: ProductLifecycleActionPayload
): Promise<ProductLifecycleResultVO> {
  const reason = payload.reason?.trim()
  if (!reason) throw new Error('请填写放弃原因')
  const response = await request.post(`/projects/${projectId}/abandon`, { reason })
  return unwrapResponse<ProductLifecycleResultVO>(response)
}
```

注意：

```text
1. publishProject 不要在前端判断 passed=true 后才允许调用。
2. 前端可以先预检并提示，但真正 publish 仍然要调用后端。
3. abandonProject 必须有 reason，避免以后追溯时不知道为什么废弃。
```

## 8. 错误响应处理建议

当前 `request.ts` 的响应拦截器会直接 `Promise.reject(error)`，而 `unwrapResponse` 只处理 HTTP 200 且 body code 非 0 的情况。

如果后端发布失败时 HTTP status 不是 200，而是 400，同时 body 中有：

```json
{
  "code": 40307,
  "message": "发布门禁未通过",
  "data": {
    "missingItems": []
  }
}
```

那么页面需要从 `error.response.data.data.missingItems` 读取缺失项。

建议在页面里增加一个小工具函数：

```ts
function getReleaseGateFromError(error: unknown): ProductReleaseGateCheckVO | null {
  const responseData = (error as { response?: { data?: { code?: number; data?: ProductReleaseGateCheckVO } } })
    .response?.data
  if (responseData?.code === 40307 && responseData.data) return responseData.data
  return null
}
```

这样可以先少改 `request.ts`，降低影响范围。

如果后期要统一优化错误处理，再考虑改 `request.ts`，让业务错误对象保持完整。

```ts
async function loadReleaseGate() {
  loading.value = true
  try {
    gate.value = await checkProjectReleaseGate(props.projectId)
  } catch (error) {
    ElMessage.error(error instanceof Error ? error.message : '发布门禁预检失败')
  } finally {
    loading.value = false
  }
```

发布逻辑草稿：

```ts
async function handlePublish() {
  try {
    await ElMessageBox.confirm('发布后 Product 将进入 released 状态，已发布版本不允许直接编辑。', '确认发布', {
      confirmButtonText: '发布',
      cancelButtonText: '取消',
      type: 'warning'
    })

    actionLoading.value = 'publish'
    const result = await publishProject(props.projectId, { reason: '前端项目中心发布' })
    ElMessage.success(`发布成功，当前状态：${result.status}`)
    emit('changed')
    await loadReleaseGate()
  } catch (error) {
    const gateFromError = getReleaseGateFromError(error)
    if (gateFromError) {
      gate.value = gateFromError
      ElMessage.error('发布门禁未通过，请先补齐缺失项')
      return
    }
    if (error !== 'cancel') {
      ElMessage.error(error instanceof Error ? error.message : '发布失败')
    }
  } finally {
    actionLoading.value = false
  }
}
```

放弃逻辑草稿：

```ts
async function handleAbandon() {
  try {
    const { value } = await ElMessageBox.prompt('请输入放弃原因，便于后续追溯。', '放弃项目', {
      confirmButtonText: '确认放弃',
      cancelButtonText: '取消',
      inputPlaceholder: '例如：客户取消需求，项目停止推进',
      inputValidator: (value) => Boolean(value?.trim()) || '请填写放弃原因'

    actionLoading.value = 'abandon'
    await abandonProject(props.projectId, { reason: value.trim() })
    ElMessage.success('项目已放弃并归档')
    emit('changed')
  } catch (error) {
    if (error !== 'cancel') {
      ElMessage.error(error instanceof Error ? error.message : '放弃失败')
    }
  } finally {
    actionLoading.value = false
  }
}
```

## 11. 页面交互建议

建议在“当前节点”区域里放两个层次：

```text
第一层：M3 时间轴动作
- 确认当前节点
- 推进下一节点
- 退回

第二层：M5 生命周期门禁
- 发布门禁预检
- 冻结
- 发布
- 归档
- 放弃
```

不要把 M5 按钮放在每个时间轴节点卡片上，避免用户误以为任何节点都能发布。

按钮展示建议：

| 当前状态 | 建议展示 |
| --- | --- |
| draft/developing | 可预检、可放弃，发布按钮可显示但后端会拦截 |
| reviewing | 可预检、可冻结、可发布、可放弃 |
| released | 可归档，不可放弃 |
| archived | 只读，不显示动作按钮或全部禁用 |

说明：

```text
前端禁用按钮只是用户体验优化，不是安全边界。
后端仍必须校验状态和权限。
```

## 12. 注意事项

1. `release-gate` 返回 `code=0` 且 `passed=false` 时，不是接口失败，而是预检成功但业务未通过。
2. `publish` 返回 `code=40307` 时，必须展示 `data.missingItems`。
3. 不要在前端写死“资料齐备就一定发布成功”，因为用户可能同时在其他页面修改资料。
4. 不要让前端传 `operator`，发布人以后端登录态为准。
5. `abandoned` 当前不是 `Product.status` 标准状态，后端用 `lockStatus=abandoned` 表达废弃。
6. 归档不删除附件，文件中心仍要能查历史文件。
7. 页面刷新必须重新请求后端，不能只靠本地改状态。
8. 若后端 HTTP status 为 400，但 body code 为 40307，前端要读取 `error.response.data.data`。
9. 上传文件时不要手动设置 multipart `Content-Type`，让浏览器自动带 boundary。
10. 不要把 M5 发布当成 M3 推进节点。M3 是时间轴动作，M5 是生命周期门禁。

## 13. 后期维护注意事项

1. 必需文件类别如果后续变成可配置，前端不要写死固定文案，应使用后端返回的 `missingItems.message`。
2. 如果后续新增缺失项编码，只要后端返回 message，前端可以不改枚举也能显示。
3. 如果未来新增权限控制，前端只负责隐藏或禁用按钮，后端仍必须拦截无权限请求。
4. 如果 `ProjectCenterView.vue` 继续变大，应优先把 M5 面板、M3 时间轴动作、M4 附件面板拆成独立组件。
5. 如果统一改 `request.ts` 错误处理，要回归所有 API 模块，避免影响登录、上传、下载。
6. 发布、归档、放弃都是真实修改数据库的动作，测试必须使用测试项目，不能拿正式项目随便点。
7. 归档后仍要验证文件中心可查可下载，不能只看 Product.status。
8. 每次后端新增生命周期字段，前端 `ProductLifecycleResultVO` 和状态展示都要同步。

## 15. Apifox 联合测试步骤

### 15.1 配置环境变量

在 Apifox 环境中配置：

| 变量 | 示例 | 说明 |
| --- | --- | --- |
| `baseUrl` | `http://localhost:8080` | 后端地址 |
| `projectId` | `10` | 测试项目 ID |
| `nodeKey` | `PRODUCT_LINE_PRODUCTION_DECISION` | 当前发布节点 |
| `bomId` | 空 | 创建 BOM 后保存 |
| `processId` | 空 | 创建工艺路线后保存 |
| `attachmentId` | 空 | 上传附件后保存 |

公共 Header：

```text
Content-Type: application/json
X-Request-Id: m5-web-apifox
```

如果开启登录鉴权，再加：

```text
Authorization: Bearer {{token}}
```

### 15.2 查询项目详情

```http
GET {{baseUrl}}/api/v1/projects/{{projectId}}
```

通过标准：

```text
code=0
data.productId={{projectId}}
```

### 15.3 查询时间轴

```http
GET {{baseUrl}}/api/v1/projects/{{projectId}}/timeline
```

通过标准：

```text
code=0
data.nodes 中存在 nodeStatus=current 的节点
```

### 15.4 确认发布节点

新产品线：

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/timeline/PRODUCT_LINE_PRODUCTION_DECISION/confirm
```

新型号线：

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/timeline/MODEL_VARIANT_FREEZE_RELEASE/confirm
```

Body：

```json
{
  "remark": "M5 前端发布门禁测试，确认当前节点"
}
```

通过标准：

```text
code=0
data.currentConfirmed=true
```

### 15.5 资料不足预检

```http
GET {{baseUrl}}/api/v1/projects/{{projectId}}/release-gate
```

通过标准：

```text
code=0
data.passed=false
data.missingItems 有缺失项
```

### 15.6 资料不足发布失败

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/publish
```

```text
code=40307
message=发布门禁未通过
data.missingItems 有缺失项
```

### 15.7 创建并冻结 BOM

创建 BOM：

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/boms
```

Body：

```json
{
  "bomName": "M5 前端接入测试 BOM",
  "bomType": "ebom",
  "versionNo": "A",
  "remark": "M5 前端接入测试"
}
```

添加 BOM 明细：

```http
POST {{baseUrl}}/api/v1/boms/{{bomId}}/items
```

Body：

```json
{
  "lineNo": 10,

  "quantity": 1,
  "unit": "kg",
  "lossRate": 0.02,
  "substituteFlag": 0,
  "remark": "M5 前端测试"
}
```

冻结 BOM：

```http
POST {{baseUrl}}/api/v1/boms/{{bomId}}/freeze
```

通过标准：

```text
code=0
data.status=frozen
```

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/process-routes
```

Body：

```json

  "processName": "M5 前端接入测试工艺路线",

  "remark": "M5 前端接入测试",
```


通过标准：


### 15.9 上传必要文件

图纸：

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/timeline/{{nodeKey}}/attachments
```

Body 选择 `form-data`：

```text
file=<选择本地测试文件>
fileCategory=drawing
versionNo=V1
remark=M5 前端测试图纸
```

SOP：

```text
file=<选择本地测试文件>
fileCategory=sop
versionNo=V1
remark=M5 前端测试 SOP
```

测试资料：

```text
file=<选择本地测试文件>
fileCategory=testing
versionNo=V1
remark=M5 前端测试资料
```

通过标准：

```text
每次上传都返回 code=0
data.attachmentId 有值
data.fileCategory 与上传类别一致
```

### 15.10 门禁预检通过

```http
GET {{baseUrl}}/api/v1/projects/{{projectId}}/release-gate
```

通过标准：

```text
code=0
data.passed=true
data.missingItems=[]
data.frozenBomCount >= 1
data.lockedProcessRouteCount >= 1
data.drawingFileCount >= 1
data.sopFileCount + data.sipFileCount >= 1
data.testingFileCount >= 1
```

### 15.11 发布成功

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/publish
```

Body：

```json
{
  "reason": "M5 前端接入测试，资料齐备发布"
}
```

通过标准：

```text
code=0
data.status=released
data.releasedAt 有值
data.releasedBy 有值
```

### 15.12 归档后文件仍可查

归档：

```http
POST {{baseUrl}}/api/v1/projects/{{projectId}}/archive
```

Body：


查询文件中心：


通过标准：

```text
归档接口返回 code=0
data.status=archived
文件中心仍能查到历史附件
```
