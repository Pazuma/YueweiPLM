# PLM 工作台驱动项目与模块数据联动业务逻辑沉淀

日期：2026-07-15

## 1. 背景

本次沉淀只记录业务逻辑理解和后续接入方向，不修改前端或后端实际业务代码。

当前测试时发现：首页总览/工作台弹窗里的“推动项目进程”按钮仍是占位逻辑，只会提示“后续接入流程推进接口”，不会真实推进项目。真实的时间轴确认、推进、退回接口已经在项目中心里接入。

用户期望的系统业务逻辑是：

- 工作台承载项目推进动作，包括当前节点确认、推动到下一节点、驳回、暂不推进、强制推进、上传当前节点资料。
- 各业务模块承载项目数据沉淀和查看，包括 BOM、工艺路线、文件中心、测试、成本、质量、库存等。
- 工作台发生的推动和上传动作，最终都写入后端项目数据；对应模块只从后端读取同一份项目数据，不再依赖前端假数据或本地临时状态。

## 2. 总体业务原则

### 2.1 工作台是操作入口

工作台不是单纯展示首页，而是项目日常推进的第一入口。

工作台需要聚焦“当前要做什么”：

- 当前项目处于哪个时间轴节点。
- 当前节点是否已确认。
- 当前节点缺哪些资料。
- 当前节点是否允许推进。
- 当前项目是否有风险、逾期、待审批、待上传资料。
- 当前责任人是谁。

工作台上允许做的动作：

- 查看项目进度弹窗。
- 确认当前节点。
- 推动项目到下一节点。
- 驳回当前节点或退回上一节点。
- 暂不推进并记录原因。
- 强制推进并记录权限、原因和风险说明。
- 上传当前节点资料。
- 跳转项目详情或对应业务模块查看沉淀数据。

### 2.2 模块是数据沉淀入口

各模块不是重新造一套项目状态，而是围绕项目读取后端沉淀数据。

模块侧主要负责：

- BOM 模块查看项目对应 BOM、BOM 明细、冻结状态、版本信息。
- 工艺路线模块查看项目对应工艺路线、工序、锁定/冻结状态。
- 文件中心查看项目各时间轴节点上传的附件。
- 测试/质量模块查看项目对应测试记录、问题记录、验证结论。
- 成本模块查看项目对应成本、报价、版本差异。
- 库存/物料模块查看项目相关物料、模具、治具、库存状态。

模块可以提供维护能力，但维护后的数据也必须回写后端，并被工作台和项目时间轴读取到。

### 2.3 后端是唯一数据源

前端不能用静态数组、mockResolve、本地临时状态伪造核心业务结论。

关键业务状态必须以后端为准：

- 项目当前节点。
- 节点是否确认。
- 节点推进结果。
- 附件上传结果。
- BOM 是否冻结。
- 工艺路线是否锁定。
- 发布门禁是否通过。
- 废弃、归档、发布等生命周期状态。

前端可以缓存和刷新，但不能自己判定真实业务状态。

## 3. 推荐业务流

### 3.1 工作台查看项目

1. 用户登录后进入工作台。
2. 前端调用后端工作台项目接口，加载正在推进的项目。
3. 每个项目展示当前节点、完成率、责任人、风险和下一步动作。
4. 用户点击项目进度，打开项目进度弹窗。

涉及接口：

- `GET /api/v1/workbench/projects/in-progress`
- `GET /api/v1/projects/{projectId}/timeline`
- `GET /api/v1/projects/{projectId}/release-gate`

### 3.2 工作台推动项目

工作台推动项目不能再使用占位 alert，需要接入后端时间轴动作接口。

推荐规则：

1. 如果当前节点未确认，先提示用户确认当前节点。
2. 用户确认当前节点后，调用确认接口。
3. 当前节点已确认后，允许推进下一节点。
4. 推进成功后刷新工作台项目列表、项目时间轴、发布门禁。
5. 如果最后一个节点不能推进，前端只提示，不调用接口。
6. 如果后端返回业务错误，前端展示后端错误信息，不伪装成功。

涉及接口：

- `POST /api/v1/projects/{projectId}/timeline/{nodeKey}/confirm`
- `POST /api/v1/projects/{projectId}/timeline/{nodeKey}/advance`
- `POST /api/v1/projects/{projectId}/timeline/{nodeKey}/return`

当前代码现状：

- `plm-web/src/views/dashboard/DashboardView.vue` 的 `handleProgressAction` 仍是占位 alert。
- `plm-web/src/views/project/ProjectCenterView.vue` 已经接入 `confirmTimelineNode` 和 `advanceTimelineNode`。
- `plm-server/src/main/java/com/yuewei/plm/module/project/controller/TimelineController.java` 已提供 confirm、advance、return 后端接口。

### 3.3 工作台上传资料

工作台上传资料应围绕“当前项目 + 当前节点 + 资料类别”进行。

推荐规则：

1. 工作台识别当前项目和当前时间轴节点。
2. 用户选择资料类别，例如 drawing、sop、sip、testing、other。
3. 用户上传文件。
4. 前端用 FormData 调用后端上传接口。
5. 上传成功后刷新当前节点附件列表、文件中心、发布门禁。
6. 上传失败时展示后端错误，例如文件大小、扩展名、项目不存在。

涉及接口：

- `POST /api/v1/projects/{projectId}/timeline/{nodeKey}/attachments`
- `GET /api/v1/projects/{projectId}/timeline/{nodeKey}/attachments`
- `GET /api/v1/file-center/attachments`
- `GET /api/v1/projects/{projectId}/release-gate`

当前代码现状：

- 项目中心已有 `TimelineAttachmentPanel.vue`，可按项目和节点上传资料。
- 工作台项目进度弹窗目前只展示小节点和“需上传”标签，没有接入真实上传控件。

### 3.4 模块查看项目沉淀数据

用户从工作台进入对应模块时，应带上项目上下文。

推荐规则：

1. 工作台或项目详情提供模块入口。
2. 跳转时带 `projectId` 或 `productId`。
3. 模块根据项目 ID 调后端接口查询数据。
4. 模块展示的数据必须和项目中心一致。
5. 模块内变更数据后，回到工作台/项目中心应能看到刷新后的状态。

模块和接口对应关系：

| 模块 | 读取内容 | 推荐接口 |
| --- | --- | --- |
| 项目中心 | 项目详情、时间轴、门禁 | `/api/v1/projects/{projectId}`、`/api/v1/projects/{projectId}/timeline`、`/api/v1/projects/{projectId}/release-gate` |
| BOM | 项目 BOM、BOM 明细、冻结状态 | `/api/v1/projects/{projectId}/boms` |
| 工艺路线 | 项目工艺路线、工序、锁定状态 | `/api/v1/projects/{projectId}/process-routes` |
| 文件中心 | 项目附件、节点附件、下载日志 | `/api/v1/file-center/attachments`、`/api/v1/projects/{projectId}/timeline/{nodeKey}/attachments` |
| 测试/质量 | 测试资料、验证结论、问题记录 | 后续补接口 |
| 成本报价 | 成本结构、报价版本 | 后续补接口 |
| 库存物料 | 物料、库存、模具治具 | 后续补接口 |

## 4. 工作台和模块的数据关系

### 4.1 数据写入方向

工作台动作写入后端：

```text
工作台按钮/上传
  -> 前端 API 层
  -> 后端 Controller
  -> Service 业务校验
  -> 数据库 / 文件存储 / 操作日志
```

典型写入：

- 确认节点：写入当前节点确认状态和操作日志。
- 推进节点：写入当前步骤号、当前节点、确认状态重置、操作日志。
- 退回节点：写入目标节点和退回原因。
- 上传资料：写入附件元数据、文件存储、上传操作日志。
- 强制推进：后续必须写入强制原因、操作者、权限校验、风险说明。

### 4.2 数据读取方向

模块从后端读取同一份数据：

```text
模块页面
  -> 前端 API 层
  -> 后端查询接口
  -> 数据库 / 文件存储
  -> 展示项目沉淀数据
```

同一项目的数据在不同入口看到的结果应一致：

- 工作台看到当前节点是“设计确认”，项目中心也必须是“设计确认”。
- 工作台上传 drawing 文件后，文件中心和发布门禁都能看到 drawing 文件。
- BOM 模块冻结 BOM 后，工作台发布门禁应能看到 BOM 已满足。
- 工艺路线模块锁定路线后，工作台发布门禁应能看到工艺路线已满足。

## 5. 当前代码差距

| 差距 | 位置 | 影响 | 后续解决方向 |
| --- | --- | --- | --- |
| 工作台推动项目仍是占位 | `plm-web/src/views/dashboard/DashboardView.vue` | 用户在首页弹窗点击推动不会真实推进 | 接入 `confirmTimelineNode`、`advanceTimelineNode`、`returnTimelineNode` |
| 工作台上传资料未接入 | `DashboardView.vue` | 工作台只能看“需上传”，不能直接补资料 | 复用或拆分 `TimelineAttachmentPanel.vue` 能力 |
| 工作台和项目中心状态刷新未统一 | Dashboard 与 ProjectCenter | 模块变更后可能需要手动刷新 | 统一刷新工作台列表、时间轴、门禁 |
| 模块数据仍有部分静态/占位 | 多个模块页面 | 模块看到的数据可能不是后端真实沉淀 | 逐模块替换为后端接口读取 |
| 强制推进缺权限闭环 | 前后端权限模块 | 高风险操作不能企业级验收 | 后端 RBAC、数据权限、强制原因、审计日志必须补齐 |
| 暂不推进/驳回语义未完全落库 | Dashboard 占位动作 | 推进过程不可追溯 | 后端新增暂停/驳回/退回记录模型或复用 timeline action |

## 6. 后续接入建议

### 6.1 第一阶段：工作台接真实时间轴

目标：让工作台“推动项目进程”不再是占位。

范围：

- 工作台弹窗加载真实项目时间轴。
- 当前节点未确认时，按钮引导先确认。
- 当前节点已确认时，按钮调用推进接口。
- 推进后刷新工作台列表和弹窗状态。
- 后端错误原样提示。

不做：

- 不做强制推进。
- 不做复杂审批。
- 不新增新的业务状态。

### 6.2 第二阶段：工作台接资料上传

目标：让工作台能直接补齐当前节点资料。

范围：

- 当前节点显示资料缺口。
- 点击“需上传”打开上传控件。
- 上传成功后刷新附件、门禁、工作台。
- 文件仍以后端校验为准。

不做：

- 不绕过后端文件规则。
- 不在前端伪造附件状态。

### 6.3 第三阶段：模块按项目查看沉淀数据

目标：工作台动作写入的数据，在对应模块可查看。

范围：

- BOM 模块按项目展示 BOM。
- 工艺路线模块按项目展示路线。
- 文件中心按项目/节点过滤附件。
- 测试、质量、成本、库存模块逐步接后端接口。

不做：

- 不让模块维护独立于项目的第二套状态。
- 不再使用静态假数据表达项目真实业务结果。

## 7. 验收口径

后续实现后，应按以下路径验收：

1. 登录系统。
2. 进入工作台。
3. 打开某个进行中项目的项目进度弹窗。
4. 在工作台确认当前节点。
5. 在工作台推动到下一节点。
6. 刷新工作台，确认项目当前节点变化。
7. 进入项目中心，确认时间轴节点一致。
8. 在工作台上传当前节点资料。
9. 进入文件中心，确认能看到该附件。
10. 如果上传的是发布门禁资料，进入发布门禁，确认缺失项减少。
11. 在 BOM/工艺模块修改或冻结数据后，回到工作台和项目中心，确认门禁状态同步。

通过标准：

- 同一个项目在工作台、项目中心、模块页面看到的状态一致。
- 所有核心状态来自后端接口。
- 上传、推进、退回、冻结、锁定等关键动作有操作日志。
- 前端失败提示能区分业务失败、权限失败、网络失败、后端异常。

## 8. 结论

推荐把 PLM 的交互主线定义为：

```text
工作台负责推动项目和补资料，
项目中心负责查看项目全貌和时间轴，
业务模块负责查看/维护项目沉淀数据，
后端负责保存唯一真实状态。
```

这样做的好处是：

- 用户日常只需要从工作台知道当前要做什么。
- 项目资料不会散落在多个前端页面状态里。
- BOM、工艺、文件、测试等模块天然能围绕项目沉淀数据。
- 发布门禁可以基于后端真实数据判断，不靠前端拼状态。

当前下一步最应该处理的是：把工作台项目进度弹窗里的推动、确认、退回、上传资料接入已有后端接口，并确保动作完成后刷新工作台、项目中心和相关模块数据。
