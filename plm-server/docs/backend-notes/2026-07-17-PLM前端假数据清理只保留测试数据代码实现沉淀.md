## 4. 核心代码逻辑

### 4.1 统一未接入错误

新增 `src/api/notConnected.ts`：

```ts
export class FrontendFeatureNotConnectedError extends Error {
  constructor(featureName: string) {
    super(`${featureName}接口未接入，整体测试阶段不展示前端假数据`)
    this.name = 'FrontendFeatureNotConnectedError'
  }
}

export function notConnected<T>(featureName: string): Promise<T> {
  return Promise.reject(new FrontendFeatureNotConnectedError(featureName))
}
```

作用：

- 统一表达“后端未接入，不返回前端假数据”。
- 让页面可以 catch 后进入空态。
- 让自动化测试能稳定判断运行态 mock 是否被清理。

## 6. 前端整体测试建议

1. 启动后端、本地数据库和前端。
2. 登录系统。
3. 进入工作台：
   - “进行中项目”应来自后端数据库。
   - “我的待办 / 逾期预警 / 待冻结资料”不应出现前端写死数据。
4. 进入项目中心、文件中心：
   - 已接入后端的列表应显示数据库真实数据。
5. 进入 BOM、工艺、库存、测试、报表、供应商、审批、系统管理：
   - 如果后端未接入，应为空态或未接入状态。
   - 不应出现前端伪造的业务记录。

## 7. 后续维护建议

1. 后端每补齐一个模块接口，再把对应 `notConnected` 替换为真实 `request.get/post` 调用。
2. 不要再在运行态页面直接 import `@/mock/*`。
3. 建议后续新增 ESLint 规则：非测试文件禁止导入 `@/mock/*`。
4. `src/mock/*` 后续可以迁移到 `src/test-fixtures/*`，只给测试使用。
5. 工作台待办、风险、冻结资料、新建项目选项需要后端补接口后再启用，不建议前端继续写死。
