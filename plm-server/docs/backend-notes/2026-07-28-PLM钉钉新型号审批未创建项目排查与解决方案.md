# PLM 钉钉新型号审批未创建项目排查与解决方案

日期：2026-07-28

## 1. 问题现象

钉钉侧提交了一张新型号审批表，但 PLM 系统里没有看到新的新型号项目。

用户此前钉钉调试返回中过：

```json
{
  "code": 0,
  "data": {
    "dingTalkApprovalNo": "111",
    "integrationRecordId": 19,
    "projectId": 42,
    "status": "success",
    "idempotentHit": true
  },
  "message": "success"
}
```

这个返回里最关键的是：

```text
idempotentHit = true
projectId = 42
dingTalkApprovalNo / approvalInstanceId = 111
```

含义：后端认为这次是“同一张钉钉审批的重复回调”，所以直接返回历史项目 42，没有新建项目。

## 2. 排查证据

### 2.1 后端服务可用

本机探测：

```powershell
Invoke-WebRequest -Uri 'http://localhost:8080/api/v1/health' -UseBasicParsing -TimeoutSec 5
```

结果：

```text
HTTP 200
profile = prod
```

说明后端服务是活的。

### 2.2 当前新型号流程码已被运行中后端识别

探测请求：

```powershell
POST http://localhost:8080/api/v1/integrations/dingtalk/approval-callbacks
{
  "processCode": "PROC-BD65F530-F66F-46B9-8F72-0567DD68F60C",
  "approvalStatus": "approved",
  "approvalInstanceId": "diag-process-bd65"
}
```

返回：

```json
{
  "code": 40001,
  "message": "钉钉审批表缺少字段: parentProductId/parent_product_id/来源产品ID/父产品ID"
}
```

结论：`PROC-BD65F530-F66F-46B9-8F72-0567DD68F60C` 已经被识别为新型号流程。否则会返回“未支持的钉钉审批流程”。

### 2.3 旧流程码不被当前后端识别

探测旧流程码：

```text
PROC-89949932-19DE-48EB-A20B-2595CB0F804D
```

返回：

```json
{
  "code": 40001,
  "message": "未支持的钉钉审批流程: PROC-89949932-19DE-48EB-A20B-2595CB0F804D"
}
```

结论：当前运行环境的新型号流程码是 `PROC-BD65...`，不是旧的 `PROC-899...`。

### 2.4 老接口地址不可用

探测老地址：

```text
POST /api/v1/integrations/ding
```

返回：

```text
HTTP 401
```

结论：钉钉连接器必须调用新地址：

```text
POST /api/v1/integrations/dingtalk/approval-callbacks
```

### 2.5 `approvalInstanceId=111` 会命中历史项目

探测请求：

```json
{
  "processCode": "PROC-BD65F530-F66F-46B9-8F72-0567DD68F60C",
  "approvalStatus": "approved",
  "approvalInstanceId": "111",
  "approvalNo": "diag-idempotent-111",
  "form": {
    "parentProductId": -999,
    "tipo": "Diag",
    "model": "Diag Model",
    "generatedCode": ""
  }
}
```

返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "integrationRecordId": 19,
    "projectId": 42,
    "dingTalkApprovalNo": "111",
    "status": "success",
    "idempotentHit": true,
    "attachmentArchiveStatus": "already_recorded",
    "moldMatches": []
  }
}
```

结论：`111` 已经是历史钉钉审批实例 ID，后端按幂等规则返回项目 42，不会创建新项目。

## 3. 根因结论

本次“钉钉提交了但 PLM 没有新型号项目”的最高概率根因是：

```text
钉钉连接器把 approvalInstanceId 或 approvalNo 配成了固定值 111，或者一直传同一个审批实例 ID。
```

后端新型号创建的幂等逻辑在：

```java
IntegrationRecord existing = first(integrationRepository.selectList(new LambdaQueryWrapper<IntegrationRecord>()
    .eq(IntegrationRecord::getSourceSystem, "dingtalk")
    .eq(IntegrationRecord::getIntegrationType, "model_variant")
    .eq(IntegrationRecord::getExternalInstanceId, externalInstanceId(dto))
    .eq(IntegrationRecord::getDeletedFlag, 0)));
if (existing != null) return result(existing, true);
```

这里的 `externalInstanceId(dto)` 优先取：

```text
approvalInstanceId
```

如果为空，才取：

```text
dingTalkApprovalNo / approvalNo
```

所以每一张真实的新审批都必须传唯一的钉钉审批实例 ID。不能写固定值、测试值、审批模板编号、流程编号。

## 4. 解决方案

### 4.1 钉钉连接器 URL

配置为：

```text
POST https://你的公网域名/api/v1/integrations/dingtalk/approval-callbacks
```

不要再使用：

```text
/api/v1/integrations/ding
```

### 4.2 请求头

如果后端没有配置 `DINGTALK_CALLBACK_TOKEN`，可以不传 Authorization。

如果配置了 `DINGTALK_CALLBACK_TOKEN`，请求头必须是：

```json
{
  "Content-Type": "application/json",
  "Authorization": "Bearer 后端配置的DINGTALK_CALLBACK_TOKEN"
}
```

### 4.3 请求体字段映射

新型号审批必须这样映射：

```json
{
  "processCode": "PROC-BD65F530-F66F-46B9-8F72-0567DD68F60C",
  "approvalInstanceId": "钉钉审批实例ID，必须是动态变量，不能固定写111",
  "approvalNo": "钉钉审批编号，必须是动态变量",
  "approvalStatus": "approved",
  "approvedAt": "审批通过时间",
  "taskId": "钉钉当前等待节点任务ID，如拿不到可先空，但运模后代同意会失败",
  "formUrl": "审批单链接",
  "applicant": {
    "userId": "申请人UserID",
    "userName": "申请人姓名"
  },
  "form": {
    "parentProductId": "来源产品ID",
    "tipo": "Tipo 类型",
    "model": "手机型号",
    "generatedCode": "模具编码，多行也可以",
    "moldMarking": "模具印字",
    "expectedDeliveryDate": "预计交付日期",
    "remark": "备注"
  },
  "attachments": []
}
```

最重要的三项：

```text
approvalInstanceId = 钉钉审批实例ID，动态值
approvalNo = 钉钉审批编号，动态值
processCode = PROC-BD65F530-F66F-46B9-8F72-0567DD68F60C
```

不能这样配：

```json
{
  "approvalInstanceId": "111",
  "approvalNo": "111"
}
```

### 4.4 钉钉调试成功后的判断标准

真正创建新项目时，返回应类似：

```json
{
  "code": 0,
  "data": {
    "projectId": 43,
    "integrationRecordId": 20,
    "idempotentHit": false,
    "status": "success"
  }
}
```

如果返回：

```json
{
  "idempotentHit": true,
  "projectId": 42
}
```

说明这次没有创建新项目，而是命中了历史审批实例。

## 5. 后续检查命令

查询某个审批实例是否已经被用过：

```powershell
docker compose exec -T postgres psql -U plm -d plm -c "select integration_record_id, external_instance_id, project_id, processing_status, created_at from plm_integration_record where source_system='dingtalk' and integration_type='model_variant' and external_instance_id='111' and deleted_flag=0;"
```

查询最新钉钉新型号入站记录：

```powershell
docker compose exec -T postgres psql -U plm -d plm -c "select integration_record_id, external_instance_id, project_id, processing_status, error_code, error_message, created_at from plm_integration_record where source_system='dingtalk' and integration_type='model_variant' order by integration_record_id desc limit 20;"
```

查询最新新型号项目：

```powershell
docker compose exec -T postgres psql -U plm -d plm -c "select product_id, product_code, product_name, product_type, model, source_instance_id, created_at from plm_product where product_type='model_variant' order by product_id desc limit 20;"
```

看后端实时日志：

```powershell
docker compose logs -f server
```

## 6. 维护建议

1. 钉钉连接器里 `approvalInstanceId` 一律选择“审批实例ID/流程实例ID”动态变量，不要手写常量。
2. `approvalNo` 也用动态审批编号，方便业务人员对账。
3. 如果调试时看到 `idempotentHit=true`，先检查是不是复用了审批实例 ID。
4. 每次换钉钉审批模板，都先用最小请求探测 `processCode` 是否被当前后端识别。
5. 建议后续在 PLM 后台增加“钉钉集成记录查询页”，直接展示 `approvalInstanceId、projectId、idempotentHit、errorMessage`，减少查库成本。
