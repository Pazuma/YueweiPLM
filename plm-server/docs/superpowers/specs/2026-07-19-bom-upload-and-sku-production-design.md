# BOM 上传、投产确认与 SKU 创建业务设计

## 1. 文档信息

- 日期：2026-07-19
- 状态：主体已实施；全局颜色编码库校验待颜色主数据模型落地
- 范围：历史 BOM 导入、新产品 BOM 建立、新型号投产颜色确认及 SKU 创建
- 本文档不包含业务代码修改

## 2. 设计目标

建立两条职责清晰的 BOM 进入路径：

1. 历史已有产品通过 BOM 管理中心批量导入正式 BOM。
2. 新产品通过工作台项目流程上传、校验、定版和发布 BOM。

同时明确产品、新型号项目与 SKU 的关系：产品开发阶段建立颜色、路线、BOM、工序和成本基线；新型号项目继承该基线，在最终投产决策时选择批量投产颜色，并仅为所选颜色创建正式 SKU。

## 3. 核心业务对象

### 3.1 产品基线

产品开发完成后形成以下正式关系：

```text
产品
└─ 正式产品版本
   ├─ 正式颜色集合
   ├─ 颜色对应的工艺路线
   ├─ 路线对应的 BOM
   ├─ 路线中的正式工序
   └─ 成本快照
```

同一条工艺路线可以适用于多个颜色；不同路线可以对应不同 BOM。例如：

```text
亮甲
└─ BOM V1
   ├─ 染色路线 R1 → 黑色、蓝色、绿色 → BOM-A
   └─ 透明路线 R2 → 透明色 → BOM-B
```

### 3.2 新型号项目

收到“产品 + 手机型号”的开模申请后创建新型号项目，例如“亮甲 + iPhone 18”。项目自动载入产品全部正式颜色及其路线、BOM、工序和成本基线，但此时不创建 SKU。

### 3.3 SKU

SKU 是“产品 + 手机型号 + 最终投产颜色”的正式结果。SKU 只在新型号项目最后完成批量投产确认后创建，不在收到开模申请时提前创建。

## 4. 双 BOM 上传入口

| 场景 | 上传入口 | 数据归属 | 上传后状态 | 正式确认位置 |
| --- | --- | --- | --- | --- |
| 历史已有产品 | BOM 管理中心 | 已有产品 | 待预览确认 | BOM 管理中心确认后成为正式历史 BOM |
| 新产品开发 | 工作台第 9 步“加工艺” | 当前新产品项目 | 项目 BOM 草稿 | 经项目流程定版，第 22 步投产决策后正式发布 |

两个入口使用相同的 xlsx 基础结构和校验组件，但不共用生效流程。

## 5. 历史 BOM 批量导入

### 5.1 处理流程

```text
BOM 管理中心上传 xlsx
→ 文件与模板校验
→ 按产品编码匹配已有产品
→ 按 BOM 业务组合拆分
→ 主数据与业务规则校验
→ 导入预览
→ 人工确认
→ 形成正式历史 BOM
```

### 5.2 匹配规则

历史导入以产品编码为主匹配键。

- 找不到产品：对应整组 BOM 不导入并报错。
- 匹配到多个有效产品：阻止导入并报错，不能默认选择最新记录。
- 唯一匹配：继续校验 BOM、路线、颜色和物料。

不同 BOM 按以下业务组合识别：

```text
产品编码 + BOM版本 + 工艺路线编码 + 适用颜色
```

历史文件中的颜色使用颜色编码，系统匹配颜色库。匹配不到时不得自动创建颜色，整组 BOM 进入错误报告。

### 5.3 生效规则

历史 BOM 预校验通过并由用户人工确认后，直接成为正式 BOM，来源标记为“历史数据导入”。系统保留原始文件、导入批次、上传人、确认人和时间。

历史导入不创建项目，不进入工作台流程，也不创建手机型号 SKU。

## 6. 新产品 BOM 工作台流程

### 6.1 第 9 步“加工艺”

工作台提供：

- 继承已有 BOM
- 上传 BOM
- 下载模板
- 查看校验结果
- 编辑 BOM
- 关联工艺路线
- 确认 BOM 与路线

上传文件自动归属当前项目。文件中的产品编码必须与当前项目产品编码一致，不通过产品编码跨项目查找。

上传后形成 BOM 草稿，不直接覆盖现有版本。同一版本再次上传时先生成差异预览，用户确认后形成新的草稿修订。

第 9 步确认内容：

- BOM 版本和物料明细
- BOM 与工艺路线的关系
- 路线适用的候选颜色关系
- 成本试算

第 9 步完成后，BOM 与路线进入“已定版、未正式发布”状态。

### 6.2 第 10 步“敲定工序”

第 10 步只负责从第 9 步已定版的每条路线中确认正式工序，不选择最终批量投产颜色。

确认规则：

- 每条待投产路线至少确认一道正式工序。
- 工序必须属于当前路线。
- 确认结果与路线版本绑定。
- 路线结构或版本变化后，原工序确认自动失效并要求重新确认。
- 第 10 步不能临时新增 BOM 或路线。

### 6.3 测试节点

样品、红样、黄样、小批量测试等节点记录候选颜色的测试情况。颜色从颜色库选择，并记录对应路线、BOM、测试结果和不合格原因。

只有验证通过的候选颜色可以进入第 22 步正式投产选择。

### 6.4 第 22 步“投产决策”

第 22 步选择产品正式投产颜色并发布产品基线。系统自动带出每个颜色对应的路线、BOM、正式工序和成本快照。

第 22 步不能直接修改 BOM、路线或工序；存在问题时必须退回对应节点调整并重新验证。

## 7. 新型号项目与 SKU 创建流程

### 7.1 创建项目

收到开模申请并确认产品和手机型号后，创建新型号项目：

```text
收到开模申请
→ 创建“亮甲 + iPhone 18”项目
→ 读取亮甲的正式产品基线
→ 载入全部正式颜色及其路线、BOM、工序和成本
```

此阶段的数据是项目候选方案，不是正式 SKU。

### 7.2 继承和差异修改

默认不要求人工重复填写颜色、工艺路线或 BOM。

- 没有型号差异：继续引用产品正式基线。
- 存在孔位、尺寸、材料或工艺差异：在当前型号项目内创建差异版本。
- 未修改部分继续继承产品基线。
- 差异版本只影响当前手机型号，不覆盖产品基线，也不影响其他型号。
- 人工可以修改颜色对应的 BOM、路线、工序和成本，但修改后必须重新验证。

### 7.3 最终批量投产颜色

新型号项目最后一步展示产品全部正式颜色，并默认全选。

用户可以取消本次不批量投产的颜色，但只能选择验证通过且数据完整的颜色。每个颜色只读展示：

```text
颜色 → 最终工艺路线 → 最终 BOM → 正式工序 → 成本快照 → 测试结论
```

### 7.4 创建 SKU

点击“确认批量投产并创建 SKU”后：

- 只为最终勾选的颜色创建正式 SKU。
- 未勾选颜色保留项目测试记录，但不创建 SKU。
- SKU 固化关联最终路线、BOM 版本、工序和成本快照。
- 操作必须幂等，重复提交不能重复创建 SKU。
- 已完成 SKU 创建后，如需新增颜色，必须进入新的变更流程，不能重新执行原投产确认。

示例：

```text
亮甲 + iPhone 18 项目
├─ 黑色：已选 → 创建黑色 SKU → R1 → BOM-A
├─ 蓝色：已选 → 创建蓝色 SKU → R1 → BOM-A
├─ 绿色：取消 → 保留测试记录，不创建 SKU
└─ 透明色：已选 → 创建透明色 SKU → R2 → BOM-B
```

## 8. xlsx 模板与校验

建议基础字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 产品编码 | 是 | 历史导入用于匹配；工作台上传用于校验当前项目 |
| BOM版本 | 是 | 例如 V1 |
| 工艺路线编码 | 是 | 必须关联有效路线 |
| 适用颜色编码 | 历史导入必填 | 匹配颜色库；工作台可在预览中从颜色库选择 |
| 物料编码 | 是 | 必须存在于物料主数据 |
| 物料名称 | 是 | 与物料主数据不一致时提示 |
| 用量 | 是 | 必须大于 0 |
| 单位 | 是 | 必须是有效单位 |
| 损耗率 | 否 | 缺省为 0 |
| 工序编码 | 否 | 按工序领料时填写 |
| 备注 | 否 | 业务说明 |

校验分三层：

1. 文件校验：格式、大小、表头和行数。
2. 主数据校验：产品、物料、单位、颜色和工艺路线。
3. 业务校验：版本、用量、重复物料、路线与 BOM 冲突。

失败隔离单位为整组 BOM，不允许只导入一组 BOM 中的部分物料行。其他完全正确的 BOM 组可以继续导入。

错误报告至少包含 Excel 行号、产品编码、BOM 版本、路线编码、颜色编码、物料编码、错误字段、错误原因和处理建议。

## 9. 状态与版本

新产品 BOM 建议状态链：

```text
draft → validated → determined → process_confirmed → released
```

发生退回或差异修改时：

```text
determined / process_confirmed → revision_required → 新草稿修订
```

已发布版本不能覆盖修改。修改必须复制产生新版本或差异版本，旧版本只读保留。

历史 BOM 在 BOM 管理中心确认后直接进入 `released`，同时记录来源为历史数据导入。

## 10. 发布门禁

### 10.1 新产品第 9 步

- 至少一个校验通过的 BOM。
- 产品编码与当前项目一致。
- BOM 物料、单位、用量和损耗率合法。
- 每个 BOM 已关联有效工艺路线。

### 10.2 新产品第 10 步

- 每条路线至少确认一道正式工序。
- 工序属于当前路线。
- 路线版本与第 9 步一致。
- 不存在失效确认。

### 10.3 新产品第 22 步

每个投产颜色必须满足：

```text
验证通过 + 唯一路线 + 有效 BOM + 已确认正式工序 + 有效成本快照
```

### 10.4 新型号最终发布

- 至少选择一个投产颜色。
- 所选颜色验证通过。
- 每个颜色有唯一有效路线和 BOM。
- 正式工序和成本快照完整。
- 差异修改均已重新确认。
- SKU 创建请求满足幂等约束。

## 11. 页面职责

### 11.1 BOM 管理中心

- 批量导入历史 BOM
- 下载模板
- 校验预览
- 下载错误报告
- 确认历史数据导入
- 查看导入批次
- 查询正式 BOM 台账

正式列表只展示产品和型号基本信息，详情中查看版本、BOM 和关联路线；关联 SKU 页面按颜色展示唯一路线、BOM、工序和成本。

### 11.2 工作台

- 新产品第 9 步：上传、编辑并定版 BOM 和路线。
- 新产品第 10 步：敲定路线中的正式工序。
- 测试节点：记录候选颜色及测试结论。
- 新产品第 22 步：发布产品正式颜色基线。
- 新型号最后一步：默认全选产品正式颜色，确认本型号批量投产颜色并创建 SKU。

## 12. 异常与审计

- 成功但无数据：返回成功状态和空结果，并明确业务提示。
- 模板错误、权限错误、版本冲突或系统异常：返回失败状态和真实原因，不能用空数组掩盖。
- 导入、定版、工序确认、投产决策和 SKU 创建均记录操作日志。
- 日志至少包含项目、产品、型号、BOM 版本、路线、颜色、工序、操作人、时间和变更前后摘要。

## 13. 前端验收要点

1. 历史 BOM 可在 BOM 管理中心批量预校验、下载错误报告并确认正式导入。
2. 同一产品编码匹配多个产品时阻止导入并准确报错。
3. 新产品 BOM 只能在工作台第 9 步进入项目草稿。
4. 第 10 步未敲定全部路线工序时不能推进。
5. 新型号项目创建时自动载入产品全部正式颜色，但不提前创建 SKU。
6. 新型号无差异时不要求重复填写路线和 BOM。
7. 差异修改只影响当前型号项目，并产生可追溯差异版本。
8. 新型号最后一步默认全选颜色，允许取消未投产颜色。
9. 只有验证通过且数据完整的颜色可以创建 SKU。
10. 重复点击或重复请求不能生成重复 SKU。
11. SKU 创建后按颜色只能查看其最终唯一路线、BOM、工序和成本。

## 14. 决策调整记录

1. BOM 管理中心批量上传仅用于历史已有产品；新产品 BOM 改为工作台上传。
2. 历史 BOM 经预校验和人工确认后直接成为正式历史 BOM。
3. 新产品 BOM 在第 9 步定版路线和 BOM，第 10 步敲定工序，第 22 步发布正式投产颜色。
4. 颜色统一来源于颜色库，不允许自由创建非标准颜色。
5. 曾讨论在收到开模申请时立即创建全部颜色 SKU，最终否决。
6. 最终规则为：收到开模申请时只创建新型号项目并载入候选颜色；项目最后一步默认全选颜色，用户确认批量投产颜色后才创建对应 SKU。
